# chewy — Storybook

Мастерская дизайна основного приложения. Цель и порядок завершения —
[MVP_PLAN](../docs/MVP_PLAN.md), очередь — [TODO](../docs/TODO.md),
экраны/готовность — [SCREEN_STUDIES](../docs/SCREEN_STUDIES.md).
Онбординг и пейвол не входят в текущую приёмку.

## Запуск

```bash
cd prototype
npm ci
npm run dev             # http://localhost:6006
npm test
npm run build           # storybook-static/
```

storybook / build-storybook — алиасы dev / build. В аудите 28 октября тесты и
сборка прошли; среда предупреждала о несовместимой паре npm 12 / Node 20.
Версия окружения пока не закреплена в проекте. Реальные Gemini и камера для работы
над дизайном не нужны. Файлы public раздаются по /assets/.

## Основной вход

Начинать с [Core/Sandbox — Все экраны · с контентом](http://localhost:6006/?path=/story/core-sandbox--all-screens).
Переходы работают внутри телефона. В инспекторе — прямой выбор состояния,
три размера телефона и демонстрационные настройки мира/питания.

Сейчас активны 51 история в трёх разделах. Sandbox — актуальная проба с контентом;
Canvas использует общие компоненты с блоками; Skeleton — прежняя модель кора.
Уборка повторных входов и разделение на «Прототип / Состояния / Мастерская»
запланированы, но ещё не выполнены. Архивы в archive/ не участвуют в сборке.

## Что действительно моделируется

- Затвор добавляет фото в несохранённый набор. **Только «Разобрать» создаёт
  сохранённую демозадачу** и возвращает в лагерь. Несколько фото — одна запись.
- Очередь сохраняется локально; после перезагрузки готовность определяется временем
  завершения. Настоящего фонового запроса нет. Ключ — chewy.capture-study.v1.
- Уточнение меняет ту же запись, прежние данные и снимки сохраняются до ответа.
  Во время повтора открытие записи ведёт к обработке; доступ к полному прежнему
  разбору ещё не доведён. Неотправленные правки/черновики не переживают перезагрузку.
- Камера и галерея используют три подготовленных фотографии; AI, сеть и системные
  разрешения не вызываются. Проблемные исходы преимущественно отдельные макеты,
  а не связанные ветви сохранённой задачи.
- Инвентарь, баланс, положение на пути и стадия лагеря живут до перезагрузки.
  Еда не начисляет монеты/рост и не меняет героя. Цены/слоты — условия примерки.
- Прямые истории результата используют fixtures, камера — общую очередь браузера.
  «Пустой день» скрывает данные и не является полным сбросом сессии. Для чистого
  теста используйте отдельный профиль/origin; не считайте все stories изолированными.

## Как убрать лишние страницы и экраны

«Экраны → Удалить эту страницу» в верхней панели скрывает выбранную историю;
«Удалённые страницы → Вернуть» восстанавливает её. В инспекторе «Удалить экран
из списка» отдельно скрывает пункт селектора; его также можно вернуть.

Это два независимых списка. Они не удаляют исходники, медиа, переходы или еду.
Выбор хранится в этом браузере под chewy.review-archive.v1 и синхронизируется
между вкладками одного адреса. У другого проверяющего набор будет исходным;
поэтому скрытие не заменяет упорядочивание самого каталога историй.

## Где менять

| Область | Файлы в src/core |
|---|---|
| Общий shell, переходы, рюкзак, состояния | ScreenStudy.jsx, screen-study-data.js |
| Камера, набор, обработка, уточнение | AddFoodCanvas.jsx, capture-session.js, CapturePhotoSet.jsx, CaptureProcessing.jsx |
| Записи и разбор | FoodJournal.jsx, FoodAssessment.jsx, food-assessment.js |
| Лагерь, слои и композиция | CampSandbox.jsx, camp-growth.js, sandbox-assets.js, sandbox-scene-layout.js; редактор CampCompositionCanvas.jsx |
| Путь и свет | ForestPath.jsx, journey-world.js, WorldLighting.jsx |
| Короткие переходы | CapturePhotoFlight.jsx, CaptureNotice.jsx, CampSupplyMoment.jsx |
| Арт и его происхождение | study-content.js, StudyMedia.jsx, *-generation.json, *-bounds*; реестр в ASSETS |
| Stories и локальное скрытие | Core*.stories.jsx, ReviewScreenPicker.jsx, review-archive.js; .storybook/manager.jsx |

Старый src/data/game.js и CoreSkeleton используют прежний скоринг. Они не являются
утверждённой спецификацией будущего GameConfig. Перед переносом файлов проверить
runtime-зависимости: часть рабочего кода ещё использует старый каркас.

## Проверка и история

npm test проверяет утилиты очереди, оценки, геометрии и пути/освещения. Успешная
сборка проверяет сборку, но не весь пользовательский сценарий. Сценарии приёмки —
[USER_FLOW](../docs/USER_FLOW.md), результаты аудита — [PROJECT_AUDIT](../docs/PROJECT_AUDIT.md).
Старые кадры и отчёты находятся в docs/exports; локальные снимки в shots вне Git.
