# chewy — Storybook

Мастерская дизайна основного приложения. Цель и порядок завершения —
[MVP_PLAN](../docs/MVP_PLAN.md), очередь — [TODO](../docs/TODO.md),
экраны/готовность — [SCREEN_STUDIES](../docs/SCREEN_STUDIES.md).
Онбординг и пейвол не входят в текущую приёмку core. Отдельный черновик знакомства
открывается через «Онбординг / Первый запуск».

## Запуск

```bash
cd prototype
npm ci
npm run dev             # http://localhost:6006
npm test
npm run build           # storybook-static/
node scripts/check-rewards.mjs  # браузерная проверка 3.2 при запущенном Storybook
node scripts/check-daily-cycle.mjs  # анализ, вклад и герой: 3.3
node scripts/check-backpack.mjs  # покупка, примерка и применение: 3.4
node scripts/check-journey-history.mjs  # история дней через путь и повторный заход: 3.5
node scripts/check-demo-session.mjs  # единый успешный цикл с чистой сессии и сброс: 3.6
node scripts/check-session-tabs.mjs  # несколько вкладок, передача записи, часы и сброс
node scripts/check-review-ui.mjs  # дата уведомления и выбранная стоянка при смене размера
node scripts/check-exploration.mjs  # активность, находки-шляпы, сохранение и перенос сессии
node scripts/check-onboarding.mjs  # знакомство, имя, пропуск, первый снимок и изоляция
```

storybook / build-storybook — алиасы dev / build. В аудите 28 октября тесты и
сборка прошли; среда предупреждала о несовместимой паре npm 12 / Node 20.
Версия окружения пока не закреплена в проекте. Реальные Gemini и камера для работы
над дизайном не нужны. Файлы public раздаются по /assets/.

## Основной вход

Начинать с [Прототип → Приложение](http://localhost:6006/?path=/story/core-sandbox--all-screens).
Переходы работают внутри телефона. Кнопка «Инструменты пробы» раскрывает инспектор:
прямой выбор состояния, три размера телефона, темы камеры/анализа и демонстрационные
настройки мира/питания. Знакомство, имя и напоминания исключены из основного селектора.

В каталоге 23 истории:

| Раздел | Истории и назначение |
|---|---|
| Прототип | Один главный вход в приложение с контентом |
| Состояния | 13 прямых входов: пустой лагерь, Сегодня, камера, галерея, обработка, результат, рюкзак, путь, возвращение и четыре проблемных исхода |
| Мастерская | Шесть инструментов: канвас, блочная композиция, редактор слоёв, раскладка владельца, очередь еды с таймером, проба активности и окрестностей |
| Онбординг | Первый запуск → имя → пустой лагерь; прямой вход в имя и отдельная проба напоминаний |

URL оставшихся прежних историй сохранены через `parameters.__id`; повторные входы
убраны. Снимок исходных 51 истории лежит в [archive/storybook-before-cleanup](archive/storybook-before-cleanup/).
Архивы не участвуют в сборке. Общие компоненты канваса и прототипа остаются в src/core.

## Активность, окрестности и шляпы

В основном приложении: «Путь» → текущая стоянка → «Исследовать рядом» → выбрать
берег или сосновую тропу. В «Инструментах пробы» передать подставную активность:
ходьбу/бег в шагах, велосипед, плавание или другие занятия в минутах.
Любой вид сам по себе открывает находки, обязательных шагов нет.
Берег приносит панаму, тропа — походную шляпу. Карточка находки или
«Рюкзак» → «Находки» открывает примерку: отменить, надеть или снять головной убор.
Надетая вещь видна в лагере и на карте; снятие не удаляет её из коллекции.

Маршрут, исходная стоянка, прогресс, находки и надетая вещь сохраняются в общей
сессии. Новый день и переезд не обнуляют исследование; повтор и исправление
активности вниз ничего не отнимают. В демо два маршрута на весь проход.
[Мастерская → Активность · окрестности](http://localhost:6006/?path=/story/workshop--exploration)
использует те же экраны, но хранит свою пробу в памяти до перезагрузки и не меняет
основную сессию.

Health не подключён. Коэффициенты в `exploration-study.js` — демонстрационные,
не нормы нагрузки или согласованный тюнинг. За день берём наибольший условный
вклад среди видов без сложения: шаги и запись того же занятия не удваивают
продвижение. Независимые занятия пока тоже не суммируются. Новый прирост
относится к выбранному при получении месту, время самой активности не моделируется.
Объединение реальных эпизодов/источников, участие без Health, финальный арт и тексты
остаются для ревью. Отключение источника не отзывает находки.

Проверены 18 тестов модели исследования, 13 тестов интеграции/переноса сессии,
весь `npm test`, сборка и `check-exploration.mjs`: перенос прежнего сохранения,
активность, день/переезд, обе находки, примерка/отмена/надевание/снятие,
перезагрузка, отказ записи и повтор, три размера, уведомления, сброс и изоляция.
Повторно пройдены `check-demo-session.mjs`, `check-session-tabs.mjs` и `check-review-ui.mjs`.

Схема сохранения теперь v2; ключ остаётся `chewy.demo-session.v1`.
Перед переносом валидной v1 владелец Web Lock сохраняет точную исходную строку
в `chewy.demo-session.v1.before-exploration-v1`. Ошибка резервной копии/записи,
повреждённые данные или конфликт существующей копии блокируют перенос, сохраняя
исходник. Сброс не импортирует резервную копию повторно и не удаляет её.
Для ручного отката к старой сборке нужно закрыть вкладки, отдельно сохранить
текущую v2, затем восстановить v1 из копии. Откат возвращает прогресс на момент
копии; новые данные остаются только в отдельно сохранённой v2. Автоотката нет.

## Что действительно моделируется

Три дефекта повторной проверки 29 октября исправлены: устаревшая вкладка
больше не перезаписывает прогресс, карточка использует день демосессии, карта
сохраняет выбранную стоянку при смене размера. После полной регрессии этап 3 закрыт.
Этап 4 закрыт: ошибки и повтор связаны в 4.1, не-еда и неопределённость — в 4.2,
разрешения, отмены и удаление — в 4.3, границы дня/зоны и несколько результатов
проверены в 4.4. Следующий этап — визуальная доводка; очередь — [TODO](../docs/TODO.md).

- На первом фото сохраняются идентификатор записи, местная дата и награда.
  Монеты выдаются за каждую новую запись, рост множителя и шаг пути — один раз
  за день. Сами фото черновика до отправки остаются в памяти. **«Разобрать» сохраняет набор одной
  демозадачей** с тем же идентификатором и возвращает в лагерь.
- Основной прототип использует одну сессию схемы v2 под ключом `chewy.demo-session.v1`:
  записи, очередь, баланс, владение, оформление, исследование и надетую шляпу. Модель содержит
  события наград, засчитанные дни и регулярность. Награда сохраняется до анализа;
  пересъёмка, дополнительные кадры, уточнение и просмотр её не повторяют.
  После перезагрузки готовность определяется сроком задачи, реального фонового запроса нет.
- Постоянную сессию изменяет одна вкладка: эксклюзивный Web Lock принадлежит ей
  до выхода со страницы или закрытия. Другая вкладка показывает сообщение об ожидании
  и доступна для просмотра; фото, покупка, сброс, тестовые часы и присутствие в ней
  не записываются. После освобождения доступа ожидающая вкладка заново читает
  сохранённую сессию и часы, затем разрешает изменения. Это последовательная работа
  с одним сохранением, без объединения правок двух вкладок. При отсутствии Web Locks
  запись блокируется с сообщением; изолированные примеры в памяти не требуют блокировки.
- Старая очередь `chewy.capture-study.v1` переносится при первом открытии новой
  сессии без выдачи монет/дней задним числом. Исходное сохранение остаётся нетронутым.
  У старых задач нет времени первого фото: сохраняется их прежняя дата создания.
- «Инструменты пробы» → «Сбросить демосессию» → подтверждение очищает весь игровой
  прогресс, сохраняя настройки мастерской. После сброса старая очередь не импортируется
  повторно. Повреждённые/неподдерживаемые данные вызывают ошибку и блокируют изменения
  до перезагрузки или явного сброса; ошибка записи не подтверждает сохранение.
- «Состояния», канвас и знакомство используют изолированные сессии в памяти.
  Истории пути/возвращения содержат свои подготовленные даты и записи; выбор
  примера в инспекторе заменяет только эту изолированную сессию.
  Самостоятельный стенд «Еда · очередь и таймер» сохраняется отдельно под
  `chewy.capture-workbench.v1`. Они не читают и не изменяют основной проход.
- Уточнение меняет ту же запись, прежние данные и снимки сохраняются до ответа.
  Во время повтора и после его ошибки кнопка «Прежний результат» открывает старый
  разбор; «К разбору» возвращает к задаче. При ошибке новые фото и правки остаются
  для повтора. Неотправленные правки/черновики не переживают перезагрузку.
- «Инструменты пробы» → «Ответ анализа»: готовый результат, нет сети, ошибка,
  долго нет ответа, не-еда и неясный состав. Исход записывается с очередной попыткой и не меняется при
  выборе другого пункта или перезагрузке. Состояния задачи — `processing`, `ready`,
  `failed`, `notFood`; `failure` хранит техническую причину, `mockOutcome` — заданный ответ, `attempt` —
  номер попытки. Старые задачи без новых полей совместимы. Ошибка не повторяется
  сама; кнопка «Повторить» сохраняет ту же запись с её фото/деталями и исходным днём.
  Для успешного повтора выбери «Готовый результат» перед нажатием. Карточка лагеря
  показывает последнюю задачу, предыдущие ошибки доступны через день в «Пути».
  Stories «Нет сети», «Не удалось узнать еду» и «Неуверенный анализ» используют
  изолированные задачи с тем же поведением.
- Первичный `notFood` сохраняет снимки без подтверждённой еды/вклада. При таком
  исходе уточнения прежний результат с его фото и вкладом остаётся. «Уточнить запись»
  открывает последние отправленные фото/правки для исправления той же задачи;
  название не обязательно для исправления нераспознанных снимков. Монеты и день
  не меняются. Явное удаление и отмена отправленного анализа ещё не подключены.
- `uncertain` сохраняет готовый частичный ответ с `assessment.tone: unknown`.
  Известные группы/источники учитываются в сводке и лагере, неизвестное масло
  не добавляет жиры. Неопределённость видна без раскрытия пояснений. Уточнение
  «С оливковым маслом» у овощного примера показывает успешное обновление.
  Произвольные несовместимые название/детали остаются неизвестными: мок не
  разбирает свободный текст и не утверждает состав по фотографии.
- Камера и галерея используют три подготовленных фотографии; AI, сеть и системные
  разрешения не вызываются. Отказ камеры пока отдельный макет.
- Главный вход начинается без выдуманных блюд и монет. Фото уже даёт награду
  и продвигает путь по дням. Завершённый разбор сохраняет ответ: результат, «Сегодня»
  и лагерь используют его без повторной оценки при просмотре.
  Рюкзак использует общий заработанный баланс и сохраняет покупки/применение.
  Ручные примеры баланса, еды и продвижения доступны в отдельных историях.
  Время суток по умолчанию следует тестовым часам; ручная фаза и подробная
  визуальная стадия лагеря остаются настройками примерки.
- Дневные компоненты и индикаторы в основном проходе условно серые/цветные:
  наличие подтверждённого вклада включает цвет, повторный вклад его сохраняет.
  Это не норма питания. Новый день пустой; старые ответы и накопления сохраняются.
- «Сегодня» содержит текущий день. Через «Путь» можно выбрать стоянку, сохранённую
  дату и открыть сводку, готовую запись или её обработку. «К дню» возвращает
  к выбранной дате, «К пути» — к выбранной стоянке. «Показать мою стоянку» возвращает
  просмотр карты к текущему лагерю; просмотр прошлого не меняет лагерь, биом, награды
  или вещи. История строится из сохранённых дат записей/задач и засчитанных дней.
  Дни отсутствия не добавляются ради заполнения календаря. Если фото засчитано, но готовых записей
  нет, день доступен с пустым состоянием. Выбор дня не повторяет анализ.
- Разделы «Магазин» и «Моё» в рюкзаке проверяют сад: базовый вид и три условных оформления
  на готовом арте. «Магазин» показывает карточки без примерки; покупка добавляет
  в «Моё», где доступны примерка, применение и отмена. Примерка хранится в памяти,
  постоянный выбор сохраняется только при применении. Можно вернуться к базовому
  виду без потери купленного. Отказ записи не списывает монеты и не меняет выбор.
  Старая покупка цветов узнаётся; прочие прежние владения/применения не удаляются.
  Изолированная история рюкзака содержит готовый купленный вариант и примеры
  достаточного/недостаточного баланса; в чистом основном проходе покупок нет.
  Раздел «Находки» содержит полученные за исследование шляпы без покупки;
  примерка и надевание независимы от оформления сада.
- Мок состава выбирается первым снимком: ужин даёт белок, завтрак — углеводы
  с клетчаткой и растения, обед — белок/углеводы/растения. Для обеда точная деталь
  «С оливковым маслом» добавляет жиры. Это заданные примеры, не распознавание
  ингредиентов; дополнительные кадры одной записи не умножают вклад.
  Кнопка «Завершить анализ» в инспекторе ускоряет успешный ответ всех текущих задач.
- Герой условно показывает обычное состояние, радость после фото, сон или
  приветствие после отсутствия. Сон приоритетен, награда выдаётся независимо.
  Последний визит сохраняется, краткая радость не воспроизводится при перезагрузке.
  Значки и реплики — заглушки до этапа 5, таймер голода не включён.
- В кошельке виден множитель за регулярность и пояснение по нажатию; на первом
  фото показаны монеты и переход множителя, если он вырос. После длинного перерыва
  множитель снижается постепенно до базы, без уменьшения баланса/вещей/пути.
- «Тестовое время» в инспекторе переводит дату на следующий день или неделю.
  Смещение сохраняется отдельно под `chewy.demo-session.v1.clock` (у стенда — свой ключ),
  используется наградами, очередью и дневной сводкой, переживает перезагрузку
  и сброс игрового прогресса. Оно не двигает системные часы.
- Демонастройки экономики и интервалов реакций живут в `src/core/demo-config.js`; это условия проверки,
  не утверждённый продуктовый тюнинг. Готовая карта имеет конечное число стоянок:
  указатель остаётся на последней при превышении, все сохранённые даты остаются
  доступны в истории и группируются на последней стоянке.

## Как убрать лишние страницы и экраны

«Экраны → Удалить эту страницу» в верхней панели скрывает выбранную историю;
«Удалённые страницы → Вернуть» восстанавливает её. В инспекторе «Удалить экран
из списка» отдельно скрывает пункт селектора; его также можно вернуть.

Это два независимых списка. Они не удаляют исходники, медиа, переходы или еду.
Выбор хранится в этом браузере под chewy.review-archive.v1 и синхронизируется
между вкладками одного адреса. Прежние скрытия сохранены; меню восстановления
показывает только истории, оставшиеся в текущем каталоге. Записи об архивированных
историях не удалялись из хранилища. Если главный вход ранее скрыт, его можно вернуть
через «Экраны». У другого проверяющего доступны все 22 истории; личное скрытие
применяется поверх общего каталога.

## Черновик онбординга

[Онбординг / Первый запуск](http://localhost:6006/?path=/story/core-sandbox--welcome):
знакомство можно пропустить, имя оставить или изменить, затем перейти в лагерь
и добавить первое фото обычным способом. До снимка баланс и путь пустые.
Выбранное имя видно у героя. Через инструменты доступен подтверждаемый сброс
пробы; повторное открытие знакомства через селектор само прогресс не стирает.
Три прежних URL сохранены. Напоминания — отдельный старый макет, в маршрут не входят.
Состояние только в памяти, перезагрузка начинает пробу заново; основное сохранение
не меняется. Сохранение завершения/профиля, момент напоминаний и финальный контент
ещё не согласованы. Нативная клавиатура/VoiceOver требуют проверки на iOS.

### Отмена и доставка ответа

`cancelCapture(id)` и `deleteCapture(id)` меняют только задачи, сохраняя события
первого фото, награды, засчитанные дни, вещи и исследование. Отмена уточнения
возвращает прежний результат и набор фото; удаление исключает запись и её вклад.
Операции возвращают `false` при отказе записи/доступа или уже изменившейся задаче.
Диалог остаётся открыт с пояснением, пока операция не сохранена.

`prepareCaptureReply(job)` запоминает ID и номер попытки вместе с ответом.
`deliverCaptureReply(reply)` принимает его только для той же активной попытки;
отменённые, удалённые, повторные и неполные ответы игнорируются. Номер попытки
после отмены уточнения не откатывается. Таймер и принудительное завершение идут
через ту же проверку. `replaceJobs` остаётся внутренним способом изменения
очереди в UI/fixtures; доставлять через него асинхронные ответы нельзя.

Инспектор моделирует доступ к камере и позволяет запомнить ответ попытки,
отменить её, затем доставить старый ответ. Это локальная проверка гонки;
реальных запросов, системных разрешений и фонового анализа здесь нет.
