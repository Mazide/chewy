## Вывод

Есть содержательная и работающая мастерская дизайна. До передачи в native не хватает
единого утверждённого поведения, общего состояния приложения и связанного покрытия
ошибок. Рисовать заново все экраны не требуется. Главная избыточность — повторные
входы Storybook и накопленная история в рабочих документах, а не одинаковые картинки.

## Storybook: текущее состояние

В сборке **51 история: 8 Skeleton, 21 Canvas, 22 Sandbox**. Активны только три
story-файла из src/core; prototype/archive уже исключён из story glob.
В src — 72 файла, включая 4 файла тестов. Canvas и Sandbox в основном используют
общий ScreenStudy; это полезное переиспользование, не два независимых приложения.

| Область | Факт и доказательство | Значение для передачи |
|---|---|---|
| Основной поток | [capture-session.js](../prototype/src/core/capture-session.js) и [AddFoodCanvas.jsx](../prototype/src/core/AddFoodCanvas.jsx) сохраняют демозадачу, несколько фото и прежний результат при уточнении | Эту основу сохраняем; не переписываем с нуля |
| Общий прогресс | [ScreenStudy.jsx](../prototype/src/core/ScreenStudy.jsx) хранит coins, applied, journey и growth отдельно от jobs; инспектор прямо говорит, что еда не меняет монеты/героя | Успешный сценарий пока заканчивается разбором/визуальным откликом, а не полным игровым циклом |
| Ошибки | Status в ScreenStudy меняет экран; offline открывает waiting без jobId, а AddFoodCanvas подставляет fixture | Нет проверки ошибки и повтора той же сохранённой задачи; отдельная картинка ошибки не доказывает сценарий |
| Герой | [sandbox-assets.js](../prototype/src/core/sandbox-assets.js) и [CampSandbox.jsx](../prototype/src/core/CampSandbox.jsx) показывают первый кадр; ночь меняет [освещение](../prototype/src/core/WorldLighting.jsx) | Еда/благодарность/сон/возвращение ещё не образуют проверяемую матрицу состояний |
| Покупка палатки | Палатка есть в STUDY_ITEMS; applied.decor обновляется, но replacements лагеря включают pet/garden/light, не tent | «Поставить в лагере» не даёт ожидаемого видимого изменения для этой вещи |
| Сохранение | Очередь в localStorage, инвентарь/мир в useState; изолированные results — fixtures; «Показать пустой день» не очищает persisted очередь | Stories не гарантируют одинаковый старт; перезапуск не проверяет целое приложение |
| День и первый заход | captureDay фильтрует по дате создания в зоне браузера, освещение использует Europe/London; EmptyCamp скрывает jobs, но оставляет week/step=2 | Нет единого тестового времени и сквозного покрытия полуночи/смены зоны; первый день не является изолированной чистой сессией |
| Конкурирующие модели | [CoreSkeleton.jsx](../prototype/src/core/CoreSkeleton.jsx) использует старые сектора/монеты, современный ScreenStudy — четыре запаса; captureDay считает каждую еду как salad | Старый каркас и game.js нельзя передавать как спецификацию нового продукта |
| Повторные входы | Canvas Walkthrough/CampWithMeal/Overview/AllScreens рендерят camp; Canvas Result/EditableResult — result; Sandbox AllScreens/Camp совпадают | Убрать точные повторы, состояния делать отдельными данными, не названиями одного экрана |
| Навигация | [.storybook/preview.js](../prototype/.storybook/preview.js) ставит Skeleton первым; локальное скрытие историй меняет лишь один браузер | Нужна общая структура каталога, одинаковая для всех проверяющих |

Продуктовые развилки собраны в DESIGN Q1–Q7. До их решения нельзя подставлять старые
DAYS_PER_BIOME, цены или «mirror of future GameConfig» из src/data/game.js как утверждённые числа.
Удаление готовой/ожидающей записи и полноценная демомодель ошибок пока не реализованы.

## Native и инструменты

iOS — ранняя заготовка, **9 Swift-файлов, 830 строк**: лагерь, камера/галерея,
вызов анализа и простая реакция. Нет связанного журнала, хранения приёмов, пути,
рюкзака, роста, GameConfig и native-тестов. Target проекта — iOS 26.2; выбор
поддерживаемой версии для будущей реализации ещё не проверялся этим аудитом.

- [FoodAnalyzer.swift](../chewy/chewy/FoodAnalyzer.swift) возвращает ккал/БЖУ,
  а [benchmark](../scripts/gemini-benchmark.mjs) уже ожидает сектора. Это разные
  контракты; старый native-ответ не описывает текущий продукт. В UI эти числа не найдены.
- [AppState.swift](../chewy/chewy/AppState.swift) после ошибки печатает её и всё равно
  показывает happy. Это не готовая обработка ошибок нового сценария.
- [SpriteKitHeroView.swift](../chewy/chewy/SpriteKitHeroView.swift) использует idle
  с изменённой скоростью/масштабом для eating/happy, отдельных готовых анимаций нет.
- scripts/gen-assets.mjs использует отсутствующий абсолютный macOS-путь и старый
  стиль/каталог; не является рабочим производственным пайплайном нынешних сцен.
- tools/video_to_spritesheet.py остаётся полезным инструментом. В его README
  ссылка на отсутствующий idle.mp4 заменена существующим idle_from_mov.mp4;
  конвертация не запускалась, атласы не перезаписывались.
- Бенчмарк требует собственных фото/доступа и использует macOS sips; здесь не запускался.
  Ключи не читались, сетевые AI-запросы не отправлялись.

## Файлы и медиа

503 отслеживаемых медиафайла занимают около 345 МБ. Основной объём — нативные
атласы (121 кадр героя и 242 кадра фона), исходные видео и варианты арта.
Точные копии — три группы, около 5,56 МБ избыточных байтов: общие фото/герой/иконка
между native, архивом и активным прототипом. Их разные назначения объяснимы.
Внутри активного public точных бинарных дублей не найдено.

Неиспользуемые camp-v1 и camp-v2 (~24 МБ) и прежняя перспективная дорога (~1,64 МБ)
лежат в public и поэтому попадают в сборку. Это кандидаты на перенос в архив с
проверкой ссылок и manifests, не повод удалять исходники генераций. Старый Skeleton
ещё имеет зависимости из рабочих компонентов; простой перенос папки может сломать сборку.

Код/медиа этим аудитом не удалялись и не перерабатывались. Техническая уборка
Storybook — следующий этап, не выполненный результат документационного прохода.
