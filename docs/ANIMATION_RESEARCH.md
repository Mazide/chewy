# Способы создания новых анимаций для Chewy

> Проверено 29 октября 2026 по официальной документации. Кандидаты для пилота,
> без сравнительного теста качества на нашем арте. Производственный процесс —
> [ANIMATION_PRODUCTION](ANIMATION_PRODUCTION.md), текущий инструмент —
> [локальная мастерская](../content-pipeline/README.md).

Для Chewy предлагается сочетать **генерацию движения кодом**, **анимацию подготовленных
частей рисунка** и **нейросетевое видео**. Первые два способа дают контроль над
повторением и правками; видео полезно для поиска новой пластики и выразительных
жестов. Выбирать исполнителя следует по объекту и выходу пригодных игровых ассетов.

**Выбор для первой интеграции:** по решению владельца используем Runway API.
Один ключ даёт доступ к Runway и Kling, поэтому модели можно сравнивать на одном
исходнике внутри мастерской. Это выбор удобства производства, а не доказанного
превосходства качества. Adobe остаётся альтернативой с явным alpha-выходом.
[Модели Runway API](https://docs.dev.runwayml.com/guides/models/).

## Что именно делает Claude

У Claude есть несколько разных путей создания анимации. Без ссылки на увиденный
пример нельзя определить, какой из них использовался.

| Вариант | Как создаётся движение | Значение для Chewy |
|---|---|---|
| HTML/SVG в Artifacts | Claude пишет графику и управляющий код | Быстрые пробы движения форм и наших изображений. [Claude Help](https://support.claude.com/en/articles/9002504-can-claude-produce-images) |
| Claude Code + Remotion | Агент пишет композицию на React, Remotion вычисляет и рендерит кадры | Локальный повторяемый авторинг, редактирование темпа и отдельных частей. Официальные skills поддерживают также Codex и другие coding agents. [Remotion](https://www.remotion.dev/docs/ai/skills) |
| Claude Motion | Шаблон Artifacts создаёт кодовую анимацию текста, графиков, форм и изображений; экспорт MP4 | На дату проверки beta на Team/Enterprise. Удобен для объясняющих роликов; описанный экспорт ещё не подтверждает выпуск прозрачных игровых кадров. [Claude Motion](https://support.claude.com/en/articles/17454997-get-started-with-claude-motion) |
| Управление редактором | Агент меняет сцену и запускает инструменты, например через официальный Blender MCP | Можно создавать ключи, сцены и рендеры в редакторе. Сам рендер выполняет Blender. [Blender MCP](https://www.blender.org/lab/mcp-server/) |

Claude Motion прямо описан как кодовая анимация без видеогенеративной модели.
Идея «агент написал движение, движок отрисовал» применима и к нашему инструменту.
Совместимость Remotion с разными агентами не доказывает одинаковое художественное
качество их результатов: это нужно сравнивать на одном задании.

## Основные способы

Оценки пригодности в последнем столбце — инженерная рекомендация для нашего
плоского рисованного арта, а не рейтинг качества моделей.

| Способ | Вход и результат | Что приходится готовить или исправлять | Кандидат для Chewy |
|---|---|---|---|
| **Анимация кодом**: SVG/Canvas, Remotion, Motion Canvas, SpriteKit | Рисунки/формы + рецепт → движение, частицы, деформации, кадры | Разделение частей, закреплённые основания, художественные кривые и формы. Простое перемещение целой PNG не создаёт новую пластику | Цветы, листва, пламя, дыхание, небольшие реакции |
| **Риг и ключевые позы**: Rive, Spine, Live2D | Части рисунка + кости/сетка/параметры → редактируемый персонаж или предмет | Дорисовка скрытых частей, веса деформации, мимика и позы | Повторно используемый Чуви, библиотека жестов, интерактивные растения |
| **Покадровая анимация**: рисование и AI-помощь | Опорные рисунки → промежуточные фазы → последовательность | Согласованность контура, лица и размеров во всех кадрах; ручная чистка | Выразительные жесты и рисованный огонь с точным контролем стиля |
| **Генерация видео по изображению** | Эталон + действие, иногда конечный кадр → короткий видеоклип | Дрейф рисунка/камеры, прозрачность, замыкание цикла, удаление нежелательных изменений | Поиск сложной пластики героя или пламени |
| **Перенос движения с видео** | Картинка героя + видео действия → анимированный герой | Соответствие анатомии и пропорций, стабильность лица, отделение фона | Конкретный новый жест Чуви; отдельно проверять на стилизованном теле |
| **Сцена и симуляция в 2D/3D-редакторе** | Модель/рисунок/сцена + ключи или симуляция → рендер | Подготовка сцены и сохранение рисованного стиля | Резерв для сложной пространственной постановки; для одного цветка слишком большая подготовка |

У кодового маршрута есть готовая техническая база: SpriteKit умеет деформировать
спрайты и создавать частицы; Remotion — экспортировать PNG-последовательность с
alpha. Для повторяемого рендера движение должно зависеть от номера кадра, а не
от времени запуска CSS-перехода. [Apple: деформация](https://developer.apple.com/documentation/spritekit/animate-the-warping-of-a-sprite),
[Apple: частицы](https://developer.apple.com/documentation/spritekit/skemitternode),
[Remotion: кадры](https://www.remotion.dev/docs/renderer/render-frames),
[Remotion: время](https://www.remotion.dev/docs/animating-properties).

Rive поддерживает mesh для растровых изображений, Live2D — подготовку отдельных
частей рисунка. Это позволяет сохранять наш арт, но скрытая часть руки или фон
за сдвинувшимся кустом всё равно должны существовать в исходниках.
[Rive meshes](https://rive.app/docs/editor/manipulating-shapes/meshes),
[Live2D: разделение материала](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/).

Для покадрового маршрута Aseprite умеет экспортировать последовательности,
листы кадров и JSON; Blender Grease Pencil поддерживает традиционную 2D-анимацию
и перекладку. Aseprite можно использовать для упаковки кадров, не переводя
стиль Chewy в пиксельный. Независимую генерацию каждой фазы или целого листа
кадров одним промптом следует считать черновиком до проверки согласованности.
[Aseprite CLI](https://www.aseprite.org/docs/cli/),
[Grease Pencil](https://docs.blender.org/manual/en/5.3/grease_pencil/introduction.html).

## Инструменты для ближайшего сравнения

### Rive с AI agent

Официальный CLI собирает анимации из текстового RML. Агент может менять проект,
проверять структуру и рендерить кадры без окна. Указаны Claude Code, Codex и Cursor.
Это перспективный путь «описание → редактируемая анимация» для повторного использования
персонажа. Локальный старт возможен без аккаунта; публикация и некоторые экспортные
операции имеют требования к аккаунту/плану. Полностью бесплатное производство
из этого не следует. [Rive for agents](https://rive.app/agents),
[условия CLI](https://github.com/rive-app/rive-docs/blob/main/cli/getting-started.mdx).

Для SwiftUI/UIKit есть официальный Apple runtime. Вариант с `.riv` потребует
отдельной интеграции; SpriteKit сам этот формат не проигрывает. До выбора runtime
можно сравнивать результат через кадры. [Rive Apple](https://rive.app/docs/runtimes/apple/apple).

### Видеогенераторы

| Кандидат | Подтверждённая возможность | Практический вывод |
|---|---|---|
| **Adobe Firefly Video** | Режим прозрачного фона; прозрачные PNG первого/последнего кадров; загрузка foreground video и alpha video в одном архиве | Приоритетная видеопроба для изолированного объекта. Два видео нужно совместить в RGBA-кадры. Наличие этого режима в публичном API не подтверждено. [Adobe](https://helpx.adobe.com/firefly/web/work-with-audio-and-video/work-with-video/generate-videos-with-transparent-backgrounds.html) |
| **Runway** | Image-to-video API; Act-Two для переноса исполнения | Кандидат для жеста. Act-Two с картинкой может добавлять движение камеры и среды, поэтому неподвижность требуется проверять. [API](https://docs.dev.runwayml.com/api/), [Act-Two](https://help.runwayml.com/hc/en-us/articles/42311337895827-Performance-Capture-with-Act-Two) |
| **Kling** | Image-to-video со стартом/концом; Motion Control по картинке и видео действия | Кандидат для переноса конкретного жеста. Ограничения сохранения внешности остаются даже при использовании Elements. [I2V](https://kling.ai/document-api/apiReference/model/imageToVideo), [Motion Control](https://kling.ai/quickstart/motion-control-user-guide) |
| **Luma** | API поддерживает loop и опорные кадры, с ограничениями совместимости режимов | Кандидат для сравнения циклов; нельзя одновременно обещать произвольные keyframes и loop. [Agents API](https://docs.agents.lumalabs.ai/api/go/resources/generations/), [генерация видео](https://docs.lumalabs.ai/ue/docs/video-generation) |
| **Veo** | Первый/последний кадры и референсные изображения | Дополнительный кандидат. Канал доступа и актуальный model ID проверить перед интеграцией: документация Gemini сообщает об отключении Veo 3.1 Preview 22 октября 2026. [Google](https://ai.google.dev/gemini-api/docs/veo?hl=en) |

Для Firefly использована специальная инструкция от 18 августа 2026; она новее
общего руководства, где встречались другие ограничения начального кадра.
Для остальных перечисленных сервисов нативный alpha-выход в просмотренных
источниках не подтверждён. Прозрачный PNG на входе сам по себе не гарантирует
прозрачного результата.

### Локальный workflow с открытыми моделями

**ComfyUI — среда сборки процесса, а не отдельный способ анимации.** В ней можно
собрать image-to-video, управление опорными кадрами или перенос движения.
Официальные workflows Wan2.2 включают эти маршруты; Wan2.2-Animate использует
изображение персонажа и видео движения/мимики. У более поздних Wan-workflows
могут использоваться платные Partner Nodes: наличие названия в ComfyUI не
означает локальные открытые веса. [Wan2.2](https://github.com/Wan-Video/Wan2.2),
[ComfyUI Wan](https://comfy.org/workflows/model/wan/),
[Wan Animate](https://docs.comfy.org/tutorials/video/wan/wan2-2-animate).

AnimateDiff добавляет движение к моделям Stable Diffusion. Это вариант для
настроенного исследовательского процесса и стилизации; для нашего старта он
потребует больше инфраструктуры и поддержки, чем кодовый цикл.
Локальный запуск таких моделей требует подходящего GPU; его доступность в текущей
среде не проверялась. [AnimateDiff](https://github.com/guoyww/AnimateDiff).

## Рекомендация по объектам

| Объект | Первый маршрут | Когда нужен другой |
|---|---|---|
| Костёр | Новые формы/деформации нескольких слоёв пламени; неподвижные поленья | Сравнить с Firefly transparent; Luma loop — дополнительная проба, если цикл видео требует доработки |
| Цветы | Изгиб от корня, задержка головки, разные фазы отдельных стеблей; код или Rive | Новая сложная пластика или смена ракурса потребует дополнительных фаз/рисунков |
| Фон | Неподвижная основа и небольшие независимые движения крон/травы | Генерировать новую сцену целиком только как отдельную художественную задачу |
| Чуви в покое | Разделённые части, дыхание и моргание; код или риг | Новые жесты требуют ключевых поз, покадровой работы либо переноса движения |
| Чуви делает жест | Опорные позы; сравнение рига с видео движения | Kling Motion Control / Runway Act-Two / Wan Animate проверять по сохранению личности и основания |

Remotion стоит проверить как **локальный авторинг и рендер**, а Rive — как
**редактируемую систему частей и состояний**. Для простого движения растений
существующего SpriteKit может быть достаточно: отдельная зависимость должна
окупаться удобством производства. Spine и Live2D остаются альтернативами для
серьёзного рига; оба требуют подготовки исходника. Spine и Live2D также умеют
выпускать кадры. [Spine export](https://en.esotericsoftware.com/spine-export/),
[Live2D export](https://docs.live2d.com/en/cubism-editor-manual/exporting-images/).

## Пилот и критерий выбора

1. **Один костёр, два способа:** код/слои и Runway API на одном исходнике;
   Firefly transparent остаётся альтернативой, если выделение объекта слишком трудоёмко.
   Сначала сравнить новые движения; интегрировать сервис после оценки пригодности.
2. **Один цветок:** кодовая деформация и Rive через агента. Проверить цену подготовки
   и удобство просьбы «помедленнее, основание неподвижно, головка запаздывает».
3. **Один жест Чуви:** одинаковое действие через опорные позы/риг и перенос движения.
   Этот тест отдельный: успех пламени ничего не доказывает о стабильности лица.

Для каждого кандидата записывать: сохранение рисунка и палитры; неподвижность
камеры и основания; чистоту alpha на светлом/тёмном фоне; стык и характер движения;
число попыток, время ручной правки и стоимость **принятого ассета**; размер результата
и способ воспроизведения. Цены подписок без количества переделок не дают сравнения.

Общий выход: исходный арт → слои/позы и задание → рецепт/проект/запрос модели →
новые кадры → проверка в мастерской → художественная приёмка → пакет для приложения.
Паспорт включает источник, исполнителя и версию, настройки, длительности, общий
холст и точку опоры, тип повторения, статичный вариант и редактируемый исходник.

Текущая мастерская принимает и проигрывает PNG-последовательности. Добавлен вызов
Runway API для видеочерновиков; первая реальная проба костра Gen-4.5 получена
29 октября: новое движение пламени, сохранённый общий рисунок, чёрный фон и
неподготовленный стык повтора. Это один кандидат, а не сравнительный бенчмарк моделей.
Выделение alpha, сборка цикла и выпуск игровых кадров остаются следующими этапами.
