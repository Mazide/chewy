## 0. Скоуп

**Входит (= TODO.md NEXT):** онбординг (имя героя + карточки + пуш opt-in), лагерь-хаб,
анализ (камера + порция + FEED, темы), результат, журнал дня (+ мини-тарелка на хабе),
путь героя, рюкзак (декор / питомцы / темы — **без одежды героя**), каталог ~18–20 позиций,
SwiftData-лог, понятие дня, скоринг «вклад в тарелку дня», монеты, стрик-уголёк, анти-фарм,
оффлайн-очередь, Gemini-схема (пропорции + цельность + is_food + confidence), телеметрия
TelemetryDeck, локальные пуши (1–2/день, quiet hours, opt-in), спрайты 5 состояний,
диегетическая полировка.

**Не входит:** одежда героя, просьбы героя, вылазки/находки, деградация за молчание, виджет,
рост кемпа, монетизация, редактирование секторов (только удаление записи), аккаунты, история
по дням дальше пути героя. Новые идеи, всплывшие при написании, — в §16 «За скоупом».

**Инварианты (абсолют, из CLAUDE.md):** ноль цифр наружу (кроме стрика и монет); герой никогда
не умирает; джанк не наказывается; грусть героя — только за молчание и чисто визуальная
(оговорка — уголёк); без стыда в текстах; накопленное не отнимается.

**Ощущение (планка исполнения):** мультик, не приложение (референсы Haven, Focus Friend).
Каждый экран — диегетический: мир за UI, хром из материалов мира, герой присутствует и
реагирует, ambient-жизнь. «Плоский iOS-экран» в этой спеке — баг.

## 1. Глоссарий

| Термин | Значение |
|---|---|
| **Сектор** | Одна из трёх частей тарелки: `veg` (овощи/фрукты), `protein`, `grain`. |
| **Юнит** | Внутренняя единица объёма еды. Порция = 2/3/4 юнита (GameConfig). Наружу не показывается. |
| **Тарелка дня** | Цели дня по секторам в юнитах (GameConfig: 4/2/2) + текущее заполнение. |
| **Вклад** | Часть приёма, попавшая в незакрытые сектора тарелки дня. База монет. |
| **Цельность** | `wholeness` из Gemini: `whole` / `processed`. Processed → коэф. вклада <1 + `sluggish`. |
| **Уголёк** | Состояние стрика после 1 пропущенного дня: замер, костёр тлеет, не сгорел. |
| **dayKey** | Локальная календарная дата `YYYY-MM-DD` устройства. Ключ дня для лога/тарелки/стрика. |
| **Лог** | Успешно проанализированный приём (или приём в очереди). Не-еда логом не является. |

## 3. Модель данных (SwiftData)

```swift
@Model final class MealRecord {
    var id: UUID
    var capturedAt: Date          // момент нажатия FEED
    var dayKey: String            // локальная дата capturedAt
    var title: String             // короткое имя блюда от Gemini
    var portion: Portion          // .small / .medium / .large
    var vegFraction: Double       // пропорции Gemini 0..1
    var proteinFraction: Double
    var grainFraction: Double
    var wholeness: Wholeness      // .whole / .processed
    var confidence: Double        // 0..1
    var reaction: Reaction        // .happy / .sluggish
    var coinsAwarded: Int
}

@Model final class DayState {
    var dayKey: String
    var hasLog: Bool              // липкий флаг: единожды true — назад не снимается
    var fullRewardSlotsUsed: Int  // анти-фарм счётчик, не уменьшается при удалении записей
}

@Model final class PlayerState {   // singleton
    var heroName: String
    var coins: Int
    var streakCurrent: Int
    var streakRecord: Int
    var streakState: StreakState  // .unlit / .lit / .ember / .out
    var lastLoggedDayKey: String?
    var installDayKey: String
    var onboardingDone: Bool
    var pushOptIn: Bool
    var ownedItemIds: [String]
    var equippedPetId: String?
    var equippedDecorId: String?
    var equippedThemeId: String?  // nil = tavern (дефолт)
    var lastFeedAt: Date?         // для таймера потребности (hungry)
}

@Model final class QueuedPhoto {
    var id: UUID
    var capturedAt: Date
    var dayKey: String
    var portion: Portion
    var imagePath: String         // JPEG в Application Support, чистится после успеха
    var attempts: Int
}
```

Правила:
- **Тарелка дня — всегда derived**: replay всех `MealRecord` дня в порядке `capturedAt`
  через скоринг-функцию (§5). Ничего не кэшируется как истина.
- **Липкие флаги**: `DayState.hasLog` и `fullRewardSlotsUsed` не откатываются при удалении
  записей (инвариант «накопленное не отнимается» + защита от фарма, §5).
- Каталог косметики — статический конфиг (не SwiftData), owned/equipped — в `PlayerState`.

## 5. Скоринг: вклад в тарелку дня

Чистая функция (задача A3), вход: состояние тарелки дня + приём, выход: applied-юниты по
секторам + монеты + реакция.

```
U = portionUnits[portion]                        // юниты приёма
raw_s = U × fraction_s × coef                    // s ∈ {veg, protein, grain}
        coef = 1.0 (whole) | processedCoef (processed)
applied_s = min(raw_s, goal_s − filled_s)        // только в незакрытую часть
applied = Σ applied_s
bonus = ступенчатая функция applied → {0, 1, 2}  // пороги ⚠️ нет в таблице → GameConfig
coins = logCoin + bonus                          // если слот анти-фарма есть
      = logCoin                                  // если fullRewardSlotsUsed ≥ antiFarmFullRewardMeals
      = logCoin                                  // если confidence < confidenceFloor (минимум)
```

- Пропорции Gemini: `veg + protein + grain + other = 1.0`; `other` (сладкое, «пустое»)
  вклада не даёт.
- Реакция: `processed` → `sluggish`; иначе `happy`. `stuffed` — фразой (не стейтом):
  `portion == .large && wholeness == .processed`. `energized` — фразой при большом
  protein-вкладе (после валидации; в Сборке 1 не обязателен).
- 5-й и далее приём дня: монеты = `logCoin`, но тарелка дня заполняется, реакция играет,
  запись в лог идёт — кап не наказание, копирайт нейтральный.
- Джанк: любой лог ≥ `logCoin`. Никогда 0 монет за еду.
- Удаление записи: тарелка дня пересчитывается replay'ем без неё; **монеты не отзываются,
  анти-фарм слот не возвращается** — закрывает фарм «лог → удалил → лог».

Прогоны примеров из DESIGN (качественно; точные пороги — GameConfig):
овсянка+ягоды утром — большой applied → +2, `happy`; та же овсянка 3-й раз — злаки закрыты,
applied мал → +0..1; яблоко при недоборе фруктов — весь вклад в veg → хороший бонус;
пицца XL вечером при полных злаках — applied ≈ 0 → 1 монета + `sluggish` + stuffed-фраза.

## 6. Стрик-машина «уголёк»

Состояния `StreakState`: `unlit` (ещё не было логов) · `lit` · `ember` (замер) · `out` (погас).

Переходы (оценка на каждом day-rollover / открытии приложения):
- пропущенных дней с `lastLoggedDayKey` до вчера включительно = 0 → `lit`;
- = 1 → `ember` (стрик замер, значение не меняется, костёр тлеет);
- ≥ 2 → `out`, `streakCurrent = 0` (рекорд остаётся навсегда).

На **первом логе дня**: `streakCurrent += 1` (из `ember` — продолжение, пропущенный день не
считается); из `out`/`unlit` — `streakCurrent = 1`. `streakRecord = max(record, current)`.
`DayState.hasLog = true` ставится в момент FEED (в т.ч. для приёма, ушедшего в очередь —
оптимистично; см. §8).

Рендер костров на «Пути героя» (heat-map по дням):
- день с логом → 🔥 lit;
- тихий день, одиночный (соседи-логи с обеих сторон либо это «вчера» при живом стрике) → 🟠 ember;
- тихий день в серии ≥ 2 → ⚫ out;
- дни до `installDayKey` → пустая тропа (без костров).

⚠️ Мок `WEEK` в прототипе (`data/game.js`: одиночная пятница = out) правилу противоречит —
в iOS следовать правилу, не моку.

## 7. Gemini

Модель `gemini-2.5-flash` (текущий код), JPEG ≤768px / 0.7. Промпт — пропорции, не калории.
Ответ — строгий JSON (structured output):

```json
{
  "is_food": true,
  "confidence": 0.86,
  "title": "Oatmeal with berries",
  "proportions": { "veg_fruit": 0.3, "protein": 0.1, "grain": 0.5, "other": 0.1 },
  "wholeness": "whole"
}
```

Ветки:
- `is_food == false` → игровая реакция героя («это не едят!»), **без лога и монет**.
- `confidence < confidenceFloor` → фраза неуверенности, минимум монет (`logCoin`), сектора
  применяются как есть (приблизительные); лечится удалением записи.
- Сетевая ошибка / HTTP ≠ 200 / кривой JSON / таймаут → приём в оффлайн-очередь (§8).

`MockFoodAnalyzer` переезжает на эту схему и умеет все ветки: норм / джанк / не-еда /
низкая уверенность (задача A5). Без ключа приложение работает на моке.

## 8. Оффлайн-очередь

- Триггер: любая ошибка анализа (§7) при нажатом FEED → `QueuedPhoto` + `DayState.hasLog = true`
  (стрик не сгорает — гарантия DESIGN).
- Ретрай: при запуске/активации приложения и при восстановлении сети (NWPathMonitor),
  последовательно, старые первыми.
- Успех: `MealRecord` создаётся с **исходным** `capturedAt`/`dayKey`; вклад считается против
  тарелки того дня (replay); монеты начисляются сейчас; телеметрия `feed` стреляет сейчас;
  JPEG удаляется. Если юзер в приложении — тихое обновление + короткая реплика героя.
- Если ретрай вернул `is_food == false`: запись не создаётся, монет нет, но липкий
  `hasLog` дня **не снимается** (принятый эксплойт-хвост; ретро-наказаний не бывает).
- В журнале и логе хаба ожидающий приём виден строкой «ждёт у костра…».

## 9. Локальные пуши

- Opt-in на онбординге (диегетическая карточка → системный prompt только при согласии).
  Отказ → в Сборке 1 пушей нет (ре-запроса нет — принятое ограничение).
- 1–2 пуша/день, планирование локальное, quiet hours ночью (часы ⚠️ нет в таблице).
  Драфт-логика: слот-1 днём «если сегодня ещё нет лога», слот-2 вечером «если 0 логов за день»;
  при каждом логе — перепланирование (лишние пуши дня снимаются).
- Тексты — от героя, диегетичные, без вины (§13, драфты).
- Тап по пушу → лагерь; `app_open(source: push)`.

## 11. Экраны

Формат: назначение · композиция · состояния · действия · переходы · герой · телеметрия.

### 11.1 Онбординг

- **Назначение:** имя героя (привязанность), объяснение лупа 2–3 карточками, пуш opt-in.
- **Композиция:** поверх живой сцены лагеря (не слайды на заливке). Карточка 1 — герой у
  костра машет, деревянная табличка «как его зовут?» + поле имени (дефолт предзаполнен).
  Карточка 2 — луп в 3 пиктограммах: 📷 сфоткай → герой реагирует → 🪙 монеты → 🎒 красота.
  Карточка 3 — пуш opt-in: герой «можно я позову тебя к костру?» + две чанки-кнопки.
- **Состояния:** обычный проход; пустое имя → остаётся дефолт.
- **Действия:** ввод имени, Next, согласие/отказ на пуши.
- **Переходы:** → Лагерь. Онбординг не повторяется (`onboardingDone`).
- **Герой:** присутствует на всех карточках, реагирует на ввод имени (радуется).
- **Телеметрия:** `onboarding_done(hero_named, push_optin)`.

### 11.2 Лагерь (хаб)

- **Назначение:** дом. Состояние героя и мира с порога; вход во всё остальное.
- **Композиция** (по `HomeScreen.jsx` + TODO «мини-тарелка на хабе»): анимированный кемп
  на весь экран; герой в центре; слева сверху — `CoinBadge` 🪙 и под ним мини-`PlateRing`
  (тарелка дня); справа сверху — три деревянных орба: 🗺️ журнал, 🧭 путь, 🎒 рюкзак;
  низ — лог приёмов дня (строки: эмодзи, title, время) и FAB «Add Food» (деревянная
  тарелка/руна — существующий ассет). Экипированные питомец/декор живут в сцене.
- **Idle-петля сцены (Haven-планка):** костёр мерцает и искрит, дым/облака плывут, листва
  колышется, питомец бродит/дышит, герой в idle-цикле; ночью сцена темнеет, герой спит 💤,
  костёр приглушён. Сцена должна хотеться открываться «просто посмотреть».
- **Состояния:** пусто (нет логов — «No meals yet — feed your hero!»); день идёт; ночь
  (quiet hours — герой спит); стрик ember/out — костёр сцены тлеет/потух до первого лога
  дня (первый лог зажигает костёр — маленькое событие).
- **Действия:** FAB → Анализ; орбы → Журнал/Путь/Рюкзак; лог-строка → Журнал.
- **Герой:** `idle` ↔ `hungry` по таймеру от `lastFeedAt` (⚠️ значение таймера — GameConfig);
  после кормления играет реакция → возврат в idle; спит ночью. Реплики-в-idle редкие, от
  характера (Focus Friend-тон), не сервисные.
- **Телеметрия:** `app_open` (на активации приложения).

### 11.3 Анализ

- **Назначение:** сфоткать еду, выбрать порцию, скормить. 30-секундный кор.
- **Композиция** (по `AnalyzeScreen.jsx`): скин из активной темы (таверна дефолт / лаборатория /
  магия — из конфига тем); вывеска-баннер («SCAN PROVISION»…), круглое окно камеры с
  ink-обводкой, герой выглядывает у окна и смотрит на еду; панель порции — 3 стопа с
  тематическими именами (Bite/Half/Feast…), **без процентов и грамм**; кнопки: ретейк
  (предмет мира) и FEED! (чанк). Дефолт порции — medium. Вход из галереи — второстепенная
  кнопка (уже в коде).
- **Состояния:** камера live; permission denied (герой щурится: «не вижу еду…» + Gallery +
  Open Settings); анализ в полёте (FEED заблокирован); оффлайн — FEED работает, уходит в
  очередь (§8).
- **Действия:** снять фото / выбрать из галереи, выбрать порцию, FEED, ретейк, назад.
- **Переходы:** FEED → Результат (сразу, в состоянии loading); назад → Лагерь.
- **Герой:** выглядывает, тянется к еде; на FEED — «ест» (анимация на Результате).
- **Телеметрия:** нет своих событий (`feed` стреляет по завершению анализа).

### 11.4 Результат

- **Назначение:** момент награды: реакция героя, вердикт, вклад, монеты.
- **Композиция** (по `ResultScreen.jsx`): поверх размытого лагеря; вывеска-вердикт; герой
  крупно играет реакцию; speech bubble с фразой; `PlateRing` + строка блюда (эмодзи+title)
  + `+🪙`; чанк «Back to camp».
- **Состояния:** `loading` (герой ест, «жуёт…»); `success` (happy/sluggish + фраза, ринг,
  монеты); `nonfood` (игровая реакция «это не едят!», без лога/монет, кнопка «попробовать
  ещё»); `low-confidence` (как success, фраза неуверенности, `+1`); `queued` (ошибка сети —
  герой: «отложу у костра, попробую позже», back to camp).
- **Действия:** Back to camp; (nonfood) снять ещё раз → Анализ.
- **Переходы:** → Лагерь (тарелка дня дополнилась, монеты выросли — видно сразу).
- **Герой:** центральный актёр экрана; реакция = контент.
- **Телеметрия:** `feed(plate_score, portion, reaction)` при success/low-confidence.

### 11.5 Журнал дня

- **Назначение:** «как прошёл день» — настроение, тарелка дня, лог, удаление ошибок.
- **Композиция** (по `JournalScreen.jsx`): свиток-пергамент поверх размытого лагеря; вывеска
  «TODAY'S JOURNAL»; шапка: настроение героя + `PlateRing` дня; чернильные строки приёмов;
  внизу орб 🧭 (Путь) и чанк «Back to camp».
- **Состояния:** пусто («страница чиста — покорми героя!»); есть записи; есть очередь
  («ждёт у костра…»); ночь — как обычно.
- **Действия:** удалить запись (жест/тап → диегетичное подтверждение «вычеркнуть из
  журнала?» → чернильное зачёркивание); переход на Путь; назад.
- **Переходы:** → Путь; → Лагерь.
- **Герой:** настроение-лицо в шапке = последняя реакция дня / idle.
- **Телеметрия:** нет своих событий.

### 11.6 Путь героя

- **Назначение:** длинный прогресс: тропа по дням, костры-heat-map, стрик и рекорд.
- **Композиция** (по `PathScreen.jsx`): пергамент-карта поверх размытого лагеря; вывеска
  «HERO'S PATH»; строка «🔥 N days on the road» (+ рекорд); змейка-тропа последних дней:
  костёр (🔥/🟠/⚫ по §6), метка дня; на сегодня — фигурка героя. Никакого веса, никаких
  цифр кроме стрика/рекорда.
- **Состояния:** свежий аккаунт (короткая тропа); ember (вчера тлеет); out (стрик 0,
  рекорд виден); обычный.
- **Действия:** назад.
- **Герой:** фигурка на «сегодня».
- **Телеметрия:** нет своих событий.

### 11.7 Рюкзак

- **Назначение:** тратить монеты: купить/экипировать декор, питомцев, темы анализа.
- **Композиция** (по `BackpackScreen.jsx`): поверх размытого лагеря; вывеска «BACKPACK» +
  `CoinBadge`; герой-витрина (реагирует на экипировку); кожаные карманы-сетка предметов:
  эмодзи/превью, имя, цена в 🪙 или Equip/Unequip; чанк «Back to camp».
- **Состояния:** хватает монет / не хватает (кнопка потушена, без стыда); куплено /
  экипировано; пустых состояний нет (каталог статичен, ≥18 позиций).
- **Действия:** купить (списание монет, owned); экипировать/снять (слот на вид: питомец ×1,
  декор ×1, тема ×1; unequip темы = дефолт-таверна).
- **Переходы:** → Лагерь (экипированное сразу видно в сцене).
- **Герой:** витрина; радуется покупке, смотрит на нового питомца.
- **Телеметрия:** `shop_buy(item_kind)`; `theme_switch(theme)` при смене темы.

Каталог: ~18–20 позиций по ступеням цен GameConfig; состав (декор ~14, питомцы 2, темы 2) —
деливерабл B5, спека фиксирует структуру: `{ id, kind, name, priceTier, asset }`.

## 12. Сквозные юзкейсы

1. **Первый запуск:** онбординг (имя, луп, пуши) → лагерь пуст, герой idle → FAB → системный
   prompt камеры → фото → FEED → Результат → лагерь: тарелка ожила, +монеты, стрик 1.
2. **Обычное кормление:** лагерь → FAB → фото+порция → FEED → loading (герой ест) →
   happy + фраза + вклад + монеты → лагерь.
3. **Джанк:** как (2), Gemini: processed → вклад ×processedCoef, `sluggish` + сонная фраза,
   ≥1 монета, стрик жив. Ни слова упрёка.
4. **Не-еда:** FEED → `is_food=false` → игровая реакция, без лога/монет → «попробовать ещё».
5. **Низкая confidence:** FEED → фраза неуверенности, +1 монета, сектора приблизительные;
   юзер может удалить запись в Журнале.
6. **Оффлайн:** FEED без сети → `queued`-состояние Результата → лагерь: строка «ждёт у
   костра», `hasLog = true` (стрик жив) → сеть вернулась → тихий flush: запись, монеты,
   `feed`-событие.
7. **Анти-фарм (5-й приём):** всё как обычно, монеты = `logCoin`; тарелка и лог honest.
8. **Полночь:** приём в 00:30 → dayKey нового дня: тарелка пуста, слоты анти-фарма новые,
   стрик-оценка вчерашнего дня по §6. Очередь со вчера flush'ится во вчерашний день.
9. **Пропуск дня:** день без логов → на rollover `ember`: стрик замер, костёр тлеет,
   герой грустнеет (визуально; ничего не отнято).
10. **Два пропуска:** ≥2 тихих дня → `out`: стрик 0, костёр потух, рекорд навсегда; первый
    лог зажигает костёр заново, стрик 1.
11. **Покупка/экипировка:** рюкзак → купить фонарь → Equip → лагерь: фонарь в сцене.
    `shop_buy(decor)`.
12. **Смена темы:** рюкзак → купить «Lab theme» → Equip → `theme_switch(lab)` → Анализ в
    скине лаборатории.
13. **Пуши:** онбординг opt-in yes → слоты по §9; тап по пушу → лагерь, `app_open(push)`.
    Отказ → пушей нет, всё работает.
14. **Удаление записи:** журнал → вычеркнуть → тарелка дня пересчиталась; монеты/слот/стрик
    не тронуты (§5).

## 13. Копирайт-принципы (+ драфты)

Тон: герой — **друг-приключенец у костра** (Focus Friend-тон: занимается своим делом,
радуется тебе), не тренер и не диетолог и не «приложение». Запрещены: «ты переел», «плохая
еда», диет-лексика, проценты/граммы/ккал, канцелярит («ошибка сети» → герой говорит
по-своему; системные формулировки только в неигровых местах — системные пермишены).

Драфты (EN — язык продукта как в прототипе; **все фразы — драфты на утверждение владельцу**):

| Ситуация | Драфт |
|---|---|
| happy | “Yum! That hit the spot!” |
| sluggish | “So warm and heavy… nap time…” |
| stuffed-фраза | “Oof… full up to my ears. Something fresh tomorrow?” |
| низкая confidence | “Hmm, can’t quite make it out… I’ll trust you on this one!” |
| не-еда | “Hey! You can’t eat THAT!” |
| оффлайн/очередь | “I’ll keep it by the fire and try again soon.” |
| hungry (idle) | “Getting a little hungry over here…” |
| пуш днём | “{name} is by the fire… got anything tasty today?” |
| пуш вечером | “The campfire’s quiet today. Even a tiny snack counts!” |
| удаление, подтверждение | “Cross this one out of the journal?” |
