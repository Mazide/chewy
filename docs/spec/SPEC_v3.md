## 0. Скоуп

**Входит (= TODO.md NEXT):** онбординг (имя героя + карточки лупа + пуш opt-in); лагерь-хаб
(+ мини-тарелка дня); анализ (камера + порция 3 стопа + FEED; темы таверна/лаборатория/магия);
результат; журнал дня (свиток, удаление записей); путь героя (тропа, костры, стрик, рекорд);
рюкзак (декор / питомцы / темы — **без одежды героя**; каталог ~18–20 позиций); SwiftData-лог;
понятие дня; скоринг «вклад в тарелку дня»; монеты; стрик-уголёк; анти-фарм; оффлайн-очередь;
Gemini-схема (пропорции + цельность + is_food + confidence); телеметрия TelemetryDeck
(5 событий VALIDATION); локальные пуши (1–2/день, quiet hours, opt-in); спрайты
`idle/eating/happy/hungry/sluggish`; диегетическая полировка (мир за UI, живой idle-мир).

**Не входит:** одежда героя (манекен — витрина), просьбы героя, вылазки/находки, деградация
за молчание, виджет, рост кемпа, монетизация, редактирование секторов (только удаление
записи), аккаунты, vacation mode, «итог вчера». Идеи — только в §16.

**Инварианты (CLAUDE.md, абсолют):**
1. Ноль цифр наружу (никаких ккал/БЖУ/процентов/веса). Цифры в UI — только стрик и монеты.
2. Герой никогда не умирает; дно — `hungry` (грустит, костёр тлеет).
3. Джанк не наказывается: любой лог = стрик жив + минимум монет; джанк = `sluggish`, не упрёк.
4. Грусть героя — только за молчание, чисто визуальная; ничего не сгорает и не отнимается
   (оговорка — уголёк); ночью герой спит.
5. Без стыда в текстах; герой — друг, не тренер и не диетолог.
6. Накопленное (косметика, стрик-рекорд, прогресс) назад не откатывается.

**Планка исполнения:** мультик, не приложение (Haven, Focus Friend). Мир всегда за UI; хром =
материал мира (вывески/свитки/чанки с ink-обводкой); «назад» — предмет мира; герой присутствует
и реагирует на каждом экране; мир живёт и без юзера. Реплики — от характера героя;
системный язык — только вне мира (iOS-алерты пермишенов). «Плоский iOS-экран» = баг спеки.

## 1. Глоссарий

| Термин | Значение |
|---|---|
| **Сектор** | `veg` (овощи/фрукты), `protein`, `grain` — три части тарелки (визуальные доли ринга — по пропорции целей: половина/четверть/четверть). |
| **Юнит** | Внутренняя единица объёма еды. Наружу не показывается никогда. |
| **Тарелка дня** | Цели дня в юнитах по секторам (`GameConfig.dayPlateGoals`) + текущее заполнение. |
| **Вклад (applied)** | Юниты приёма, засчитанные в незакрытую часть целей. База бонуса монет. |
| **Цельность** | `wholeness` от Gemini: `whole` / `processed`. Processed → коэф. <1 + `sluggish`. |
| **Уголёк (ember)** | Ровно 1 пропущенный день: стрик замер, костёр тлеет. Не сгорел. |
| **dayKey** | Локальная календарная дата `"yyyy-MM-dd"` момента FEED. |
| **Лог** | Приём, учтённый за день: успешный анализ **или** элемент очереди. Не-еда — не лог. |
| **Липкий флаг** | Однажды выставленный `hasLog` / потраченный анти-фарм-слот не откатываются. |
| **FEED** | Нажатие главной кнопки анализа: захват кадра + отправка. Точка учёта дня/стрика. |

## 2. Архитектура

### 2.1 Стек и принципы

- SwiftUI + SpriteKit. `HeroView` — единственная точка входа визуала героя (интерфейс не
  трогать). `AppState: ObservableObject` через `.environmentObject` — единый рут-стейт.
- Персист — SwiftData (§3). Все тюнинг- и UI-константы — `GameConfig.swift` (§4).
- Скоринг (§5) и стрик (§6) — **чистые функции без I/O** (тестируемость A3/A4).
- Слои: `FoodAnalyzerService` (Gemini/Mock), `Scoring`, `StreakMachine`, `OfflineQueue`,
  `PushScheduler`, `Telemetry`.

### 2.2 Навигация и жизненный цикл

```swift
enum Route: Equatable {
    case camp, analyze, result(ResultPayload), journal, path, backpack
}
```

- Рут — Лагерь; сцена лагеря рендерится всегда. Журнал / Путь / Рюкзак / Результат —
  оверлеи поверх **размытого живого лагеря** (сцена продолжает жить под блюром).
- Анализ — fullScreenCover (свой мир-скин с камерой). Онбординг — fullScreenCover при
  `!onboardingDone`.
- Из Журнала доступен Путь (орб 🧭) — как в прототипе.

Активация (`scenePhase == .active`), **строгий порядок** (rollover до первого рендера
данных дня, иначе мигает вчерашняя тарелка):
1. Day-rollover: `currentDayKey != lastSeenDayKey` → стрик-переход §6.3, сброс derived-кэшей,
   `lastSeenDayKey = currentDayKey`.
2. Пересчёт героя (§2.3) и костра сцены (§11.2).
3. `Telemetry.appOpen(source:)` (`push`, если вход через notification response).
4. `OfflineQueue.retry()` (асинхронно).
5. `PushScheduler.replan()`.

Полночь при открытом приложении: `NSNotification.Name.NSCalendarDayChanged` → шаги 1, 2, 5.

### 2.3 Состояния героя

Две оси (DESIGN, 5 спрайтов: `idle`, `eating`, `happy`, `hungry`, `sluggish`):

- **Потребность** (чисто визуальная; ничего не сгорает): `idle` → `hungry`, когда
  `effectiveElapsed(lastFeedAt) ≥ GameConfig.hungerAfterHours`, где `effectiveElapsed` =
  астрономическое время **минус пересечение с quiet hours** («ночью таймер на паузе»).
  `lastFeedAt` обновляется на **любом FEED**, включая ушедший в очередь (иначе герой
  грустнел бы у честно логировавшего юзера — нарушение инварианта 4).
- **Реакция на еду**: `eating` (на время анализа) → `happy` | `sluggish`; проигрывается на
  Результате и коротким эхом на хабе после возврата; затем возврат к оси потребности.
- **Ночь (quiet hours):** герой спит — отдельного спрайта нет: сцена темнеет, герой в
  `idle` + 💤-эмоут, костёр — угли. Таймер потребности на паузе.

`hungry` — дно. Никаких `starving`/смерти/деградации (инвариант 2). `stuffed`/`energized` —
фразы поверх `sluggish`/`happy`, не стейты (USER_FLOW).

## 3. Модель данных (SwiftData)

### 3.1 Модели

```swift
enum Portion: String, Codable { case small, medium, large }
enum Wholeness: String, Codable { case whole, processed }
enum Reaction: String, Codable { case happy, sluggish }
enum StreakState: String, Codable { case unlit, lit, ember, out }

@Model final class MealRecord {
    var id: UUID
    var capturedAt: Date          // момент FEED
    var dayKey: String            // локальная дата capturedAt
    var title: String             // короткое имя блюда (Gemini)
    var portion: Portion
    var vegFraction: Double       // пропорции Gemini, 0..1 (veg+protein+grain+other=1)
    var proteinFraction: Double
    var grainFraction: Double
    var wholeness: Wholeness
    var confidence: Double
    var coinsAwarded: Int         // исторический факт; не пересчитывается никогда
}

@Model final class DayState {
    @Attribute(.unique) var dayKey: String
    var hasLog: Bool              // липкий
    var fullRewardSlotsUsed: Int  // липкий (анти-фарм)
}

@Model final class PlayerState {  // singleton
    var heroName: String
    var coins: Int
    var streakCurrent: Int
    var streakRecord: Int
    var streakState: StreakState
    var lastLoggedDayKey: String?
    var lastSeenDayKey: String
    var installDayKey: String
    var onboardingDone: Bool
    var pushOptIn: Bool
    var ownedItemIds: [String]
    var equippedPetId: String?
    var equippedDecorId: String?
    var equippedThemeId: String?  // nil = tavern (дефолт-тема бесплатна)
    var lastFeedAt: Date?
}

@Model final class QueuedPhoto {
    var id: UUID
    var capturedAt: Date
    var dayKey: String
    var portion: Portion
    var imagePath: String         // JPEG в Application Support; удаляется после успеха
    var attempts: Int
}
```

### 3.2 Хранится vs выводится

| Хранится | Выводится (не хранить) |
|---|---|
| пропорции, wholeness, confidence, portion, `coinsAwarded` | тарелка дня — replay записей дня (§5.3) |
| липкие `hasLog`, `fullRewardSlotsUsed` | реакция: `processed → sluggish`, иначе `happy` |
| стрик-поля `PlayerState` | stuffed-фраза: `portion == .large && processed`; фраза неуверенности: `confidence < floor` |
| — | эмодзи лог-строки: по доминирующему сектору 🥦/🍗/🌾; `processed` → 🍔; low-confidence → 🍽️ |
| — | костры Пути (§6.5); настроение в Журнале (§11.5) |

Реакции и фразы выводимы из хранимого → правка копирайта/порогов не требует миграции данных.

### 3.3 dayKey и таймзоны

`dayKey` = `"yyyy-MM-dd"` от `Calendar.current` в момент FEED. Граница дня — локальная
полночь (без сдвигов «до 3 ночи» — не усложняем до валидации). Смена таймзоны: новые логи
получают dayKey текущей зоны; стрик оценивается по календарной цепочке dayKey как записано.
Артефакты перелётов (30-часовой день) — принятое ограничение. Тесты A2: полночь, смена
зоны, DST-переход, идемпотентность rollover.

## 5. Скоринг: вклад в тарелку дня (A3)

### 5.1 Функция (чистая)

```
вход:  plateFilled  — юниты по секторам на момент приёма (replay записей дня до него),
       slotsUsed    — DayState.fullRewardSlotsUsed,
       meal         — {portion, fractions, wholeness, confidence}
выход: applied (по секторам), coins, reaction

U         = GameConfig.portionUnits[meal.portion]
coef      = meal.wholeness == .processed ? GameConfig.processedCoef : 1.0
raw_s     = U × meal.fraction_s × coef              // s ∈ {veg, protein, grain}
applied_s = min(raw_s, goals_s − plateFilled_s)     // вклад — только в незакрытую часть
applied   = Σ applied_s

bonus = applied ≥ t2 ? 2 : applied ≥ t1 ? 1 : 0     // (t1, t2) = GameConfig.bonusThresholds
coins = logCoin + (slotsUsed < antiFarmFullRewardMeals
                   && confidence ≥ confidenceFloor ? bonus : 0)

reaction = meal.wholeness == .processed ? .sluggish : .happy
```

Свойства (тест-инварианты A3):
- `coins ≥ logCoin` всегда: ноль монет за еду не бывает (инвариант 3).
- Полные сектора вклада не дают → умеренность встроена: перебор не приносит монет.
- **Processed-еда может заработать бонус** — через вклад ×`processedCoef` (джанк не
  наказывается; минимум — гарантия, не потолок). Пицца XL из day-in-life получает минимум
  из-за закрытых секторов, а не из-за «джанковости».
- `other`-доля (сладкое/«пустое») вклада не даёт.
- Низкая confidence: бонус не начисляется (минимум), но **вклад в тарелку применяется**
  (приблизительные сектора лучше пустых; средство от ошибки — удаление записи, §11.5).

### 5.2 Фразовые надстройки (не стейты)

- `stuffed`-фраза: `portion == .large && wholeness == .processed`; анимация — `sluggish`.
  Отдельного поля «тяжести» в Gemini-схеме нет (схема зафиксирована DECISIONS) — вопрос
  владельцу §15.6.
- `energized`-фраза (опционально): `wholeness == .whole` и protein-вклад доминирует.

### 5.3 Тарелка дня — derived

`plate(dayKey) = fold(MealRecord дня, отсортированных по capturedAt, через §5.1)`.
Кэш — только как оптимизация с инвалидацией на вставку/удаление записи дня.
`coinsAwarded` исторические: replay никогда не меняет уже выданные монеты (инвариант 6).

### 5.4 Анти-фарм и удаление записи

- Слот занимается в момент **создания MealRecord** (успешный анализ; для очереди — при flush).
- Удаление записи: тарелка дня пересчитывается без неё; **монеты не отзываются; слот не
  возвращается; `hasLog` дня не снимается**. Следствие: цикл «лог → удалил → лог» не
  фармится — максимум `antiFarmFullRewardMeals` полных наград в день при любых удалениях.
- 5-й+ приём дня: `coins = logCoin`; тарелка заполняется, реакция играет, лог пишется,
  стрик жив. Копирайт нейтральный — кап одинаков для любой еды и не является наказанием.

### 5.5 Sanity-check экономики (справочно, не тюнинг)

Цели 4+2+2 = 8 юнитов; типовой день из 2–3 приёмов по 3–4 юнита почти закрывает тарелку →
2–3 × (1 + 1..2) ≈ 4–8 монет/день — сходится с DESIGN («~4–8/день»; tier-1 5–10 🪙 →
первая покупка на 1–2-й день; каталог ≥18 позиций ≈ 4 недели трат — окно замера).

### 5.6 Прогоны примеров DESIGN (тест-кейсы A3; численно — при выбранных t1/t2)

| Кейс | Ситуация | Ожидание |
|---|---|---|
| Овсянка+ягоды утром (M, whole, grain-heavy) | тарелка пуста → applied велик | бонус +2, `happy` |
| Та же овсянка 3-й раз за день | злаки закрыты → applied мал | +0..1, `happy` |
| Яблоко (S, whole, veg≈1.0) при недоборе фруктов | весь объём в незакрытый veg | заметный бонус |
| Пицца XL вечером (L, processed), злаки полны | raw×coef и закрытые сектора → applied≈0 | `logCoin`, `sluggish`, stuffed-фраза |
| Любой джанк, любое время | — | ≥ `logCoin`, стрик жив, без упрёка |
| 5-й приём (любая еда) | слоты кончились | ровно `logCoin`; тарелка/лог honest |

### 5.7 Кор-флоу `didFeed()` (последовательность; связывает A2–A8)

```
FEED (Анализ) → didFeed(image, portion):
 1. capturedAt = now; dayKey = local(capturedAt)
 2. lastFeedAt = capturedAt                       // потребность-таймер сброшен в любом исходе
 3. DayState(dayKey).hasLog = true (липко); StreakMachine.onFirstLogOfDay(dayKey)  (§6.4)
 4. PushScheduler.replan()                        // сегодняшние слоты сняты
 5. Route → .result(loading); герой .eating
 6. analyzer.analyze(image) с таймаутом GameConfig.analysisTimeout
 7a. успех, is_food, confidence любой:
     scoring §5.1 (replay дня) → MealRecord (слот занят) → coins += → Telemetry.feed →
     Result.success / .lowConfidence (минимум ждём minChewingSeconds)
 7b. is_food == false:
     Result.nonfood; записи/монет нет. (hasLog из шага 3 остаётся — принятый хвост, §8)
 7c. транзиентная ошибка (сеть/HTTP/parse/timeout):
     QueuedPhoto (JPEG на диск) → Result.queued
 8. Back to camp → Лагерь: обновлённые тарелка/лог/монеты; эхо реакции reactionEchoSeconds;
    если стрик был out — «розжиг» костра именно в этот момент возврата
```

Шаг 3 до анализа — гарантия «стрик не сгорает из-за сети/ошибок» (DESIGN, оффлайн-очередь).

## 6. Стрик-машина «уголёк» (A4)

### 6.1 Семантика числа

`streakCurrent` = **число дней с логом** в непрерывной цепочке, где одиночные тихие дни
прощаются (не считаются, но и не рвут). Пример: лог-дни Пн(6-й), Вт тихо, Ср лог → 7.
Копирайт «7 days on the road» — дни у костра, тихая веха остаётся на тропе угольком.

### 6.2 Источник истины

Цепочка `DayState.hasLog`. `PlayerState.streak*` — материализованный итог переходов.
`hasLog` ставится в момент FEED (включая очередь) и не снимается (§3.2).
`missedDays(today)` = число календарных дней **строго между** `lastLoggedDayKey` и `today`
без `hasLog`. Сегодня не «пропущен», пока не кончился.

### 6.3 Переходы на rollover / активации (идемпотентно)

| Условие | `streakState` | Эффект |
|---|---|---|
| логов ещё не было | `unlit` | current = 0 |
| missedDays == 0 | `lit` | без изменений |
| missedDays == 1 | `ember` | current **замер** (число не падает) |
| missedDays ≥ 2 | `out` | current = 0; `record` не трогается — навсегда |

### 6.4 На первом логе дня (`onFirstLogOfDay`, из §5.7 шага 3)

```
guard lastLoggedDayKey != today
state ∈ {lit, ember} → current += 1     // ember: цепь продолжилась, пропущенный день не считается
state ∈ {out, unlit} → current = 1      // костёр зажжён заново
record = max(record, current); state = .lit; lastLoggedDayKey = today
```

Ember — не одноразовая «заморозка»: каждый одиночный пропуск тлеет; гасит только серия 2+.
Никакой продажи/траты на заморозку (WON'T DO).

### 6.5 Рендер костров «Пути» (heat-map)

| День | Костёр |
|---|---|
| `hasLog == true` | 🔥 lit |
| тихий день, одиночный в цепи | 🟠 ember |
| тихий день в серии ≥ 2 подряд | ⚫ out |
| сегодня без лога (день не кончился) | тлеющий «ждёт» (не ⚫) |
| до `installDayKey` | пустая тропа в тумане, без костров |

⚠️ Мок `WEEK` в `prototype/src/data/game.js` (одиночная тихая пятница показана `out`)
правилу противоречит — iOS следует правилу, не моку.

## 7. Gemini (A5)

### 7.1 Запрос

Модель `GameConfig.geminiModel`; JPEG ≤ `imageMaxSide`, качество `jpegQuality`; таймаут
`analysisTimeout`. **Structured output**: `response_mime_type: "application/json"` +
`responseSchema` (enum для `wholeness`, границы 0..1 для долей) — не «ответь только JSON»-
надежда, как в текущем коде.

Драфт промпта (EN; финализирует бенчмарк A13):

```
You are a nutrition-plate analyzer. Look at the photo of a meal.
Estimate the proportions of the MEAL VOLUME by plate sectors:
- veg_fruit: vegetables and fruits
- protein: meat, fish, eggs, legumes, dairy protein
- grain: grains, bread, pasta, potatoes and other starchy sides
- other: sweets, sauces, deep-fried coating, drinks, anything else
Proportions must sum to 1.0.
wholeness: "processed" if the meal is dominated by heavily processed food
(fast food, sweets, packaged snacks, deep-fried), else "whole".
is_food: false if there is no edible food in the photo.
confidence: 0..1 — overall certainty.
title: short dish name (2–4 words).
For mixed dishes (soup, pasta, sandwich) estimate sector shares inside the dish.
```

### 7.2 Ответ и валидация парсинга

```json
{
  "is_food": true,
  "confidence": 0.86,
  "title": "Oatmeal with berries",
  "proportions": { "veg_fruit": 0.30, "protein": 0.10, "grain": 0.50, "other": 0.10 },
  "wholeness": "whole"
}
```

Правила A5: clamp долей в 0..1; сумма ∉ [0.9, 1.1] → нормализовать; неизвестный `wholeness`
→ `whole` (в сомнении не наказываем); пустой `title` → «Meal»; нет `is_food`/`proportions`
→ ошибка парсинга (= транзиент → очередь).

### 7.3 Ветки результата

| Ветка | Условие | Поведение |
|---|---|---|
| Норм | is_food && confidence ≥ floor | лог, скоринг §5.1, реакция |
| Джанк | то же, wholeness == processed | лог, вклад ×coef, `sluggish`, монеты ≥ logCoin |
| Не-еда | is_food == false | игровая реакция, **без лога и монет**, [Try again] |
| Низкая уверенность | is_food && confidence < floor | лог, фраза неуверенности, `coins = logCoin`, сектора применяются |
| Транзиент | сеть / HTTP≠200 / parse / timeout | оффлайн-очередь §8 |

### 7.4 MockFoodAnalyzer

Та же схема; детерминированная ротация веток: норм → джанк → не-еда → низкая уверенность
(+ инъекция ошибки для тестов очереди). Без ключа приложение полностью живо (UI-работа,
скриншоты A9–A12).

### 7.5 Бенчмарк (A13, до сборки)

Скрипт (`scripts/gemini-benchmark.mjs`) гоняет **боевые** промпт и схему §7.1–7.2 на ~30
своих фото (вкл. смешанные блюда: борщ, паста, бутерброд) → CSV (сектора, цельность,
confidence, время, цена) + сводка misread-кандидатов. Misread-rate > 20% — стоп: анализ
переосмысливается до сборки (TODO §0). Значение `confidenceFloor` калибруется здесь же.

## 8. Оффлайн-очередь (A6)

- **Постановка** (шаг 7c §5.7): транзиентная ошибка → `QueuedPhoto` (JPEG на диск).
  `hasLog`/стрик/`lastFeedAt` уже выставлены на шагах 2–3 — **стрик не сгорает** (DESIGN).
  Монеты до анализа не начисляются.
- **Ретрай**: на активации приложения и на восстановлении сети (`NWPathMonitor`);
  FIFO, последовательно; `attempts += 1`; внутри сессии — экспоненциальная пауза.
  Постоянного капа нет: фото живёт до успеха или ручного вычёркивания (данные юзера
  не выбрасываем).
- **Flush-успех**: `MealRecord` с **исходными** `capturedAt`/`dayKey`; скоринг — против
  записей того дня с `capturedAt` раньше вставляемого (replay-вставка по времени);
  анти-фарм-слот **того** дня занимается сейчас; монеты — сейчас; `Telemetry.feed` — сейчас;
  JPEG удаляется. Юзер в приложении → тихое обновление лога/тарелки, звяк монеты, короткая
  реплика героя. Отдельного Результат-экрана пост-фактум нет.
- **Flush-не-еда**: записи нет, монет нет; липкий `hasLog` дня не снимается — ретро-наказаний
  не бывает (редкий принятый эксплойт; инвариант 6 важнее симметрии).
- **Вычёркивание юзером**: pending-строка удаляется в Журнале как обычная запись (§11.5);
  `QueuedPhoto` + JPEG удаляются; монет не было; `hasLog` остаётся.
- **UI**: строка «ждёт у костра…» (🕯️) в логе хаба и Журнале; без таймеров/процентов/бейджей.

## 9. Локальные пуши (A8)

- **Opt-in**: карточка онбординга — диегетический пре-промпт от героя; системный запрос —
  только после согласия. Отказ: пушей в Сборке 1 нет, повторных уговоров нет
  (`push_optin=false` в телеметрии — принятое ограничение).
- **Слоты**: максимум `pushesPerDayMax` в день, строго вне `quietHours`:
  - слот-1 «день»: стреляет, только если к моменту слота сегодня нет ни одного лога;
  - слот-2 «вечер»: только если за день 0 логов.
- **Планирование**: локальные нотификации на 1–2 дня вперёд с условной отменой:
  `replan()` вызывается на (а) любом логе — снимает оставшиеся сегодняшние слоты,
  (б) rollover — планирует новые, (в) активации, (г) выдаче разрешения на онбординге.
- **Контент**: от героя, с его именем, диегетично, без вины и диет-лексики (§13);
  никаких «вы давно не заходили». Пул фраз на слот, ротация.
- **Тап** → Лагерь; `app_open(source: push)` через notification response handler.
- Quiet hours = «ночь» героя (§2.3): ночью герой спит и не пишет.

    [Back to camp];
  - `queued`: герой: «The fog's thick today. I'll keep this by the fire and try again
    soon.»; без ринга и монет; [Back to camp]. Стрик уже жив (§5.7 шаг 3).
- **Действия:** Back to camp; (nonfood) Try again.
- **Переходы:** → Лагерь (тарелка/лог/монеты уже обновлены; монеты долетают в бейдж);
  nonfood → Анализ.
- **Герой:** центральный актёр; реакция проигрывается один раз, затем мягкий луп.
- **Телеметрия:** `feed(...)` в момент создания MealRecord (success/lowConfidence);
  nonfood/queued не стреляют (queued выстрелит при flush).
- **Acceptance:** все 5 состояний воспроизводимы на MockFoodAnalyzer; дельта ринга
  анимируется; минимальное «жевание» соблюдается; из nonfood можно немедленно переснять.

### 11.5 Журнал дня

- **Назначение:** «как прошёл день»: настроение героя, тарелка дня, лог, удаление ошибок.
- **Композиция** (`JournalScreen.jsx`): свиток-пергамент с закрученными краями поверх
  размытого лагеря; вывеска «TODAY'S JOURNAL»; шапка: мини-портрет героя в текущем
  настроении + «{Name} feels …» + `PlateRing` дня; чернильные строки приёмов (сепия:
  эмодзи + title + время), pending-строки «ждёт у костра…» (🕯️); низ: орб 🧭 (Путь) +
  чанк «Back to camp».
- **Мир/ambient:** записи «проявляются» чернилами при открытии; свиток чуть колышется;
  лагерь под блюром живёт.
- **Состояния:** пусто («The page is blank — feed your hero!»); записи; записи + pending.
  Вычеркнутые записи не показываются (день выглядит как обычный).
- **Действия:** long-press (или свайп) записи → диегетическое подтверждение «Cross this
  one out of the journal?» [Cross out]/[Keep] → анимация чернильного зачёркивания →
  запись удалена, тарелка дня пересчитана (§5.4: монеты/слот/`hasLog` не тронуты).
  Pending-строка вычёркивается так же (§8). Орб 🧭 → Путь.
- **Переходы:** → Путь; → Лагерь.
- **Герой:** портрет-настроение: реакция последнего приёма дня, иначе ось потребности;
  ночью — спит.
- **Телеметрия:** своих событий нет.
- **Acceptance:** удаление пересчитывает мини-тарелку хаба и журнала одинаково; монеты
  и слоты не меняются (юнит-тест §5.4 + UI-проверка); pending-строка отображается и
  вычёркивается.

### 11.6 Путь героя

- **Назначение:** длинный прогресс без цифр питания: тропа, костры-heat-map, стрик, рекорд.
- **Композиция** (`PathScreen.jsx`): пергамент-карта поверх размытого лагеря; вывеска
  «HERO'S PATH»; заголовок «🔥 {N} days on the road», мельче — «best: {record}»;
  змейка-тропа по дням (окно `pathDaysWindow`): точки-следы между вехами; у вехи — костёр
  🔥/🟠/⚫ (§6.5) и подпись дня; на сегодняшней вехе — фигурка героя («hero is here»).
  Дни до установки — тропа в тумане. Единственные цифры экрана — стрик и рекорд.
- **Мир/ambient:** пергамент «дышит»; сегодняшний костёр мерцает; туман клубится по краям.
- **Состояния:** свежий аккаунт (коротка тропа, много тумана); обычный; ember (вчерашняя
  веха 🟠); out (стрик 0 — но рекорд в заголовке: «накопленное не отнимается» наглядно).
- **Действия:** назад.
- **Переходы:** → Лагерь.
- **Герой:** фигурка на «сегодня»; при `lit` — бодрая поза.
- **Телеметрия:** своих событий нет.
- **Acceptance:** костры соответствуют §6.5 на подготовленных фикстурах истории (вкл.
  кейс «одиночный пропуск = 🟠, серия = ⚫»); рекорд остаётся после `out`; сегодня — герой.

### 11.7 Рюкзак

- **Назначение:** тратить монеты: покупка/экипировка декора, питомцев, тем анализа.
  Одежды героя нет (после сигнала); герой-манекен остаётся витриной.
- **Композиция** (`BackpackScreen.jsx`): поверх размытого лагеря; вывеска «BACKPACK» +
  `CoinBadge`; герой-витрина (реагирует на действия); кожаная панель, карманы-сетка:
  карточка = превью/эмодзи + имя + [🪙 цена] либо [Equip]/[Unequip]; экипированное
  подсвечено. Чанк «Back to camp».
- **Мир/ambient:** карманы топорщатся; купленное вылетает из кармана к герою; питомец
  в карточке поворачивается к герою при экипировке.
- **Состояния:** монет хватает / не хватает (кнопка цены потушена — недоступна без
  стыда/таймеров); куплено/экипировано; каталог статичен — пустых состояний нет.
- **Действия:** купить (списание; `ownedItemIds += id`; `coins ≥ price` обязательное);
  Equip/Unequip по слотам: питомец ×1, декор ×1, тема ×1 (unequip темы → таверна).
  Продажи/возврата нет (и не наказание — инвариант 6 про «не отнимается» самим приложением).
- **Переходы:** → Лагерь (экипированное сразу в сцене — подтверждение миром).
- **Герой:** витрина: радуется покупке; разглядывает нового питомца; на теме — жест с
  пропсом темы.
- **Телеметрия:** `shop_buy(item_kind)` на покупке; `theme_switch(theme)` на смене темы.
- **Acceptance:** покупка списывает монеты ровно один раз (защита от двойного тапа);
  слоты соблюдаются; экипированное видно в лагере и меняет скин Анализа; оба события
  телеметрии стреляют.

**Каталог** (структура — спека; состав и имена — B5):

```swift
struct CosmeticItem: Identifiable {
    let id: String
    let kind: CosmeticKind        // .pet / .decor / .theme
    let name: String              // имя в тоне мира (B5)
    let price: Int                // из GameConfig.priceTiers
    let asset: String             // спрайт/превью
    let anchor: SceneAnchor?      // decor/pet: точка сцены лагеря
    let themeId: AnalysisTheme?   // для kind == .theme
}
```

Состав ~18–20: декор ~14–16 (анкеры сцены — у костра, у палатки, на дереве, у входа…),
питомцы 2 (арт-ограничение TODO: 1–2 отдельных спрайта), темы 2 (lab, magic; tavern —
бесплатный дефолт). Ступени цен — `GameConfig.priceTiers`; ориентир распределения:
дешёвый декор в tier-1 (первая покупка в 1–2 день), питомцы/темы в tier-2..3.

## 12. Сквозные юзкейсы

Формат: шаги → слои → телеметрия → чек инвариантов.

1. **Первый запуск.** Онбординг (имя → луп → пуш-выбор) → Лагерь: пусто, костёр спокоен,
   герой idle → FAB → камера-prompt → фото + порция → FEED → Результат loading→success →
   Лагерь: тарелка ожила, монеты долетели, стрик 1, костёр ярче. Слои: PlayerState,
   PushScheduler, Analyzer, Scoring, Streak. События: `onboarding_done`, `app_open`, `feed`.
2. **Обычное кормление.** Лагерь → Анализ → FEED → жуёт ≥`minChewingSeconds` → `happy` +
   вердикт + дельта тарелки + `+🪙` → Лагерь (эхо реакции). `feed(plate_score, portion,
   happy)`.
3. **Джанк.** `processed` → вклад ×`processedCoef`, `sluggish` + сонная фраза, монеты ≥
   `logCoin` (бонус возможен при большом вкладе — не наказываем), стрик жив. Чек: ни слова
   упрёка (инв. 3, 5).
4. **Не-еда (тролль-фото).** `is_food=false` → nonfood: игровая реакция, без лога/монет →
   [Try again]/[Back]. Журнал не тронут, `feed` не стреляет. Чек: реакция — игра, не претензия.
5. **Низкая confidence.** Фраза неуверенности, `+logCoin`, сектора применены; запись
   можно вычеркнуть (→ юзкейс 14). Чек: доверие юзеру, не сомнение в нём.
6. **Оффлайн-кормление.** FEED без сети → шаги 1–4 §5.7 выполнены (стрик жив, таймер
   сброшен) → Result.queued → Лагерь: pending-строка → сеть вернулась → flush: MealRecord
   в исходный день, монеты, `feed`; герой коротко радуется, если юзер в приложении.
   Чек: за сеть не наказываем.
7. **Анти-фарм: 5-й приём дня.** Как (2), но `+logCoin` без бонуса; тарелка/лог/реакция
   honest; копирайт не меняется. Чек: кап ≠ наказание (одинаков для любой еды).
8. **Переход через полночь.** Приём в 00:30 → dayKey нового дня: пустая тарелка, свежие
   слоты; вчерашний день оценён §6.3 (открытое приложение ловит `NSCalendarDayChanged`).
   Очередь со вчерашним `capturedAt` flush-ится **во вчера** (replay того дня) — сегодняшняя
   тарелка не искажается.
9. **Пропуск дня.** Вчера 0 логов → на активации `ember`: стрик замер (число не упало),
   вчерашняя веха 🟠, костёр хаба тлеет, герой грустнеет визуально. Чек инв. 4: ничего не
   сгорело и не отнято; оговорка-уголёк работает как задумано.
10. **Два пропуска.** ≥2 тихих дня → `out`: стрик 0, костёр потух, вехи ⚫; рекорд навсегда
    в заголовке Пути (инв. 6). Первый лог → «розжиг» на возврате в Лагерь, стрик 1.
11. **Покупка и экипировка.** Рюкзак → [🪙 8] фонарь → списание, `shop_buy(decor)` →
    [Equip] → Лагерь: фонарь на анкере, ночью светится.
12. **Смена темы анализа.** Рюкзак → купить «Lab theme» → [Equip] → `theme_switch(lab)` →
    Анализ в скине лаборатории (вывеска/стопы/пропсы из конфига). [Unequip] →
    `theme_switch(tavern)`.
13. **Пуши: opt-in и отказ.** Opt-in: слоты §9; день без лога → дневной пуш от героя;
    тап → Лагерь, `app_open(push)`; лог в 11:00 → сегодняшние слоты сняты. Отказ: пушей
    нет, ре-запросов нет, всё прочее идентично.
14. **Удаление записи.** Журнал → long-press → «Cross this one out?» → зачёркнуто:
    тарелка дня пересчитана; монеты остались, слот занят, `hasLog` true. Чек: исправление
    ошибки Gemini не наказывается; фарм закрыт (§5.4).

## 13. Копирайт-принципы (+ драфты)

**Тон:** герой — друг-приключенец у костра. Принцип Focus Friend: он **занят своим делом и
радуется тебе**, а не обслуживает; говорит от характера, не от «приложения». Haven-принцип:
мягкость и уют важнее информативности.

Запрещено: стыд («ты переел», «плохая еда»), диет-лексика (calories, macros, cheat meal,
clean eating, guilt-free…), цифры питания в любом виде, канцелярит и системный язык в мире
(«network error» → «the fog is thick today…»). Системные формулировки — только в неигровых
местах (iOS-алерты пермишенов, [Open Settings]).

Все фразы — **драфты на утверждение владельцу** (тон = продукт; протокол AGENT_BACKLOG C).
Язык продукта — EN (прототип/код/когорта; подтвердить — §15.7). На каждую ситуацию — пул
2–3 вариантов (ротация против «заезженной пластинки»); в таблице по одному примеру:

| Ситуация | Драфт (EN) | Принцип |
|---|---|---|
| happy | “Yum! That hit the spot!” | радость встречи, не оценка еды |
| sluggish | “So warm and heavy… nap time…” | сонливость, не упрёк |
| stuffed-фраза | “Oof… full up to my ears. Something fresh tomorrow?” | мягкий вопрос-приглашение |
| energized-фраза (опц.) | “Whoa, I could climb a mountain now!” | сила, без «правильной еды» |
| низкая confidence | “Hmm, can’t quite make it out… I’ll trust you on this one!” | доверие юзеру |
| не-еда | “Hey! You can’t eat THAT!” | игра, не претензия |
| оффлайн/очередь | “The fog’s thick today. I’ll keep this by the fire and try again soon.” | мир вместо «сети» |
| flush при юзере | “Oh! That meal from before — got it!” | |
| hungry (idle) | “Getting a little hungry over here…” | просьба, не обвинение |
| ночь | (спит; никаких реплик) | инв. 4: ночью тишина |
| пуш днём (нет лога) | “{name} is poking the fire… got anything tasty going on?” | зовёт герой, не сервис |
| пуш вечером (0 логов) | “The campfire’s quiet tonight. Even a tiny snack counts!” | «counts» = честность лога |
| камера denied | “I can’t see the food…” + [Open Settings] | системное — в кнопке |
| удаление | “Cross this one out of the journal?” [Cross out]/[Keep] | нейтрально, без «удалить данные» |
| пустой лог хаба | “No meals yet — feed your hero!” | из прототипа |
| пустой журнал | “The page is blank — feed your hero!” | из прототипа |
| розжиг после out | “The fire’s back! Missed you.” | тепло, без «наконец-то» |

Анти-паттерны (примеры того, как НЕЛЬЗЯ): «You've eaten too much today», «Bad choice!»,
«You broke your streak» (стрик не «ломается» юзером — костёр гаснет сам и молча),
«Error 500», «Your daily calorie goal…».

8. **Слот декора** — один (прототип) или несколько одновременно (богаче «рост лагеря»,

9. **Телеметрия ошибок** (`analysis_error` / nonfood) — добавить к замороженному списку

11. **Дефолт-имя героя** — список кандидатов даст B6; нужен выбор владельца.

## 16. За скоупом (идеи, всплывшие при написании — НЕ в Сборку 1)

- «Итог вчера» в первой сессии дня (открытый вопрос USER_FLOW — остаётся открытым).
- Значок «приблизительной» записи в журнале (прозрачность low-confidence).
- Ре-запрос пуш-разрешения через героя спустя N дней после отказа.
- Именование питомца при покупке.
- Idle-реплики героя, зависящие от времени суток и погоды сцены.
- Кнопка «поделиться» карточкой пути (виральность) — после сигнала.
