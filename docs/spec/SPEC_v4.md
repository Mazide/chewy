## Ревью v3 (самокритика → исправлено в этой версии)

1. **`fullRewardSlotsUsed` — неверная семантика имени.** DESIGN: «полная награда — первые N
   **приёмов** дня» — слот тратит каждый приём (включая low-confidence), а не каждая
   «награда». → переименовано в `mealSlotsUsed` («порядковый номер приёма дня», липкий);
   формула не изменилась, семантика проговорена. §3.1, §5.4.
2. **Приоритет состояний героя на хабе не задан** (что показывать, когда пересекаются ночь,
   эхо реакции и голод). → таблица приоритетов §2.3.
3. **`app_open` при холодном старте из пуша**: notification-хендлер может сработать позже
   шага телеметрии → двойное событие или неверный `source`. → правило «одно событие на
   активацию; delegate ставит `pendingSource` до шага 3». §10.
4. **Судьба фото не оговорена.** → зафиксировано: фото приёма **не хранится** (только JPEG
   очереди до успешного flush) — приватность и место. §3.4, §8.
5. **Гонка: вычёркивание pending во время ретрая.** → очередь перед созданием записи
   проверяет, что элемент не удалён; ретрай реентерабельно-защищён. §8.
6. **Полночь во время «жевания»** (FEED 23:59, ответ 00:00) не оговорена. → запись уходит
   в день FEED (`capturedAt`); Результат показывает дельту тарелки того дня; хаб после
   возврата — уже новый день. Тест в A2/A3. §12.8.
7. **Атомарность шагов didFeed не оговорена** (крэш между «hasLog» и очередью). → шаги 1–4
   в одной транзакции SwiftData; flush-эффекты атомарны. §5.7.
8. **Журнал: не сказано явно, что он только про сегодня** (история дней — вне скоупа,
   кроме костров Пути). → §11.5.
9. **Пуши: не учтён отзыв разрешения в iOS-настройках после opt-in.** → `replan()` читает
   `UNAuthorizationStatus`; revoked = opt-out. §9.
10. **Телеметрия queued-приёмов приходит с задержкой** (день события ≠ день приёма в
    аналитике) — не отмечено как принятое искажение. → §10.
11. **Инвариант «цифры — только стрик и монеты» и время в логе**: время приёма — не цифра
    питания; проговорено, чтобы не «чинили» лишнего. → §0.
12. **В Рюкзаке не заявлено отсутствие функциональных товаров** (нет заморозок стрика и
    бустов — WON'T DO). → §11.7.
13. **Мелкие дыры**: lazy-создание `DayState`; guard двойного `didFeed`; поведение Result
    при возврате из фона. → §3, §5.7, §11.4.

## 0. Скоуп и рамки

**Входит (= TODO.md NEXT):** онбординг (имя героя + карточки лупа + пуш opt-in); лагерь-хаб
(+ мини-тарелка дня); анализ (камера + порция 3 стопа + FEED; темы таверна/лаборатория/магия);
результат; журнал дня (свиток, удаление записей); путь героя (тропа, костры, стрик, рекорд);
рюкзак (декор / питомцы / темы — **без одежды героя**; каталог ~18–20 позиций); SwiftData-лог;
понятие дня; скоринг «вклад в тарелку дня»; монеты; стрик-уголёк; анти-фарм; оффлайн-очередь;
Gemini-схема (пропорции + цельность + is_food + confidence); телеметрия TelemetryDeck
(5 событий VALIDATION); локальные пуши (1–2/день, quiet hours, opt-in); спрайты
`idle/eating/happy/hungry/sluggish`; диегетическая полировка (мир за UI, живой idle-мир).

**Не входит:** одежда героя (манекен — витрина), просьбы героя, вылазки/находки, деградация
за молчание, виджет, рост кемпа, монетизация, редактирование секторов (только удаление
записи), аккаунты, vacation mode, история дней в журнале, «итог вчера». Идеи — только §16.

**Инварианты (CLAUDE.md, абсолют):**
1. **Ноль цифр наружу**: никаких ккал/БЖУ/процентов/веса. Числа в UI — только стрик, рекорд
   стрика и монеты (цены — в монетах). Время приёма в логе («13:45») — не цифра питания,
   инвариант не нарушает.
2. **Герой никогда не умирает**: дно — `hungry` (грустит, костёр тлеет). Никаких game over.
3. **Джанк не наказывается**: любой лог = стрик жив + минимум монет. Джанк — `sluggish`, не упрёк.
4. **Грусть героя — только за молчание**, чисто визуальная: ничего не сгорает и не отнимается
   (единственная оговорка — уголёк, §6); ночью герой спит.
5. **Без стыда в текстах**: герой — друг, не тренер и не диетолог.
6. **Накопленное не отнимается**: косметика, стрик-рекорд, монеты, прогресс не откатываются.

**Планка исполнения (Haven, Focus Friend):** мультик, не приложение. Мир всегда за UI
(под-экраны — поверх размытого живого лагеря); хром = материал (вывески, свитки, чанки с
ink-обводкой); «назад» — предмет мира; герой присутствует и реагирует на каждом экране; мир
живёт и без юзера (idle-петли). Реплики — от характера героя (он занят своим делом и рад
тебе), не от «сервиса»; системный язык — только вне мира (iOS-алерты, [Open Settings]).
Экран, описанный как «плоский iOS-экран», — баг спеки.

## 1. Глоссарий

| Термин | Значение |
|---|---|
| **Сектор** | `veg` (овощи/фрукты), `protein`, `grain`. Доли ринга — по пропорции целей (½ / ¼ / ¼). |
| **Юнит** | Внутренняя единица объёма еды. Наружу не показывается никогда. |
| **Тарелка дня** | Цели дня в юнитах (`GameConfig.dayPlateGoals`) + заполнение из записей дня. |
| **Вклад (applied)** | Юниты приёма, засчитанные в незакрытую часть целей. База бонуса монет. |
| **Цельность** | `wholeness`: `whole` / `processed`. Processed → коэф. <1 + `sluggish`. |
| **Уголёк (ember)** | Ровно 1 пропущенный день: стрик замер, костёр тлеет. Не сгорел. |
| **dayKey** | Локальная календарная дата `"yyyy-MM-dd"` момента FEED. |
| **Лог** | Приём, учтённый за день: успешный анализ **или** элемент очереди. Не-еда — не лог. |
| **Липкий флаг** | `hasLog` / `mealSlotsUsed` не откатываются ни удалением, ни исходом анализа. |
| **FEED** | Нажатие главной кнопки анализа: захват кадра + отправка. Точка учёта дня, стрика, таймера потребности. |

### 2.2 Навигация и жизненный цикл


- Рут — Лагерь; сцена лагеря рендерится всегда. Журнал / Путь / Рюкзак / Результат —

Активация (`scenePhase == .active`), **строгий порядок** (rollover до первого рендера

1. Day-rollover: `currentDayKey != lastSeenDayKey` → стрик-переход §6.3, инвалидация
   derived-кэшей, `lastSeenDayKey = currentDayKey`.
2. Пересчёт героя (§2.3) и костра сцены (§11.2).
3. `Telemetry.appOpen(source:)` — с учётом `pendingSource` от notification-хендлера (§10).
4. `OfflineQueue.retry()` (асинхронно, реентерабельно-защищённо).
5. `PushScheduler.replan()`.

Полночь при открытом приложении: `NSNotification.Name.NSCalendarDayChanged` → шаги 1, 2, 5.

### 2.3 Состояния героя

5 спрайтов: `idle`, `eating`, `happy`, `hungry`, `sluggish` (реализованы `idle/eating/happy`;
дорисовать `hungry/sluggish` — TODO §5). `stuffed`/`energized` — фразы, не стейты.

Две оси (DESIGN):
- **Потребность** (чисто визуальная; ничего не сгорает): `idle` → `hungry`, когда
  `effectiveElapsed(lastFeedAt) ≥ GameConfig.hungerAfterHours`, где `effectiveElapsed` —
  астрономическое время **минус пересечение с quiet hours** («ночью таймер на паузе»).
  `lastFeedAt` обновляется на **любом FEED**, включая ушедший в очередь и не-еду (герой
  не грустнеет у честно логировавшего юзера — инвариант 4).
- **Реакция на еду**: `eating` (на время анализа) → `happy` | `sluggish` — проигрывается
  на Результате, эхом `reactionEchoSeconds` на хабе; затем возврат к оси потребности.

**Приоритет отображения на хабе** (сверху — сильнее):

| Приоритет | Состояние | Условие |
|---|---|---|
| 1 | сон (idle + 💤, тёмная сцена) | quiet hours |
| 2 | эхо реакции (`happy`/`sluggish`) | ≤ `reactionEchoSeconds` после результата |
| 3 | `hungry` | таймер потребности истёк |
| 4 | `idle` | иначе |

`hungry` — дно (инвариант 2). Никаких `starving`, смерти, деградации.

## 3. Модель данных (SwiftData)

### 3.1 Модели

```swift
enum Portion: String, Codable { case small, medium, large }
enum Wholeness: String, Codable { case whole, processed }
enum Reaction: String, Codable { case happy, sluggish }
enum StreakState: String, Codable { case unlit, lit, ember, out }

@Model final class MealRecord {
    var id: UUID
    var capturedAt: Date          // момент FEED
    var dayKey: String            // локальная дата capturedAt
    var title: String             // короткое имя блюда (Gemini)
    var portion: Portion
    var vegFraction: Double       // пропорции Gemini 0..1 (veg+protein+grain+other = 1)
    var proteinFraction: Double
    var grainFraction: Double
    var wholeness: Wholeness
    var confidence: Double
    var coinsAwarded: Int         // исторический факт; не пересчитывается никогда
}

@Model final class DayState {     // создаётся лениво при первом FEED дня
    @Attribute(.unique) var dayKey: String
    var hasLog: Bool              // липкий
    var mealSlotsUsed: Int        // липкий: порядковый счётчик приёмов дня (анти-фарм)
}

@Model final class PlayerState {  // singleton
    var heroName: String
    var coins: Int
    var streakCurrent: Int
    var streakRecord: Int
    var streakState: StreakState
    var lastLoggedDayKey: String?
    var lastSeenDayKey: String
    var installDayKey: String
    var onboardingDone: Bool
    var pushOptIn: Bool
    var ownedItemIds: [String]
    var equippedPetId: String?
    var equippedDecorId: String?
    var equippedThemeId: String?  // nil = tavern (бесплатный дефолт)
    var lastFeedAt: Date?
}

@Model final class QueuedPhoto {
    var id: UUID
    var capturedAt: Date
    var dayKey: String
    var portion: Portion
    var imagePath: String         // JPEG в Application Support; удаляется после успеха/вычёркивания
    var attempts: Int
}
```

### 3.2 Хранится vs выводится

| Хранится | Выводится (не хранить) |
|---|---|
| пропорции, wholeness, confidence, portion, `coinsAwarded` | тарелка дня — replay записей дня (§5.3) |
| липкие `hasLog`, `mealSlotsUsed` | реакция: `processed → sluggish`, иначе `happy` |
| стрик-поля `PlayerState` | stuffed-фраза (`large && processed`); фраза неуверенности (`confidence < floor`) |
| — | эмодзи лог-строки: доминирующий сектор 🥦/🍗/🌾; `processed` → 🍔; low-confidence → 🍽️ |
| — | костры Пути (§6.5); настроение в Журнале (§11.5); состояние героя (§2.3) |

Реакции/фразы выводимы из хранимого → правка копирайта и порогов не требует миграций.
Тихие дни не имеют `DayState` — выводятся из разрывов цепочки dayKey.

### 3.3 dayKey и таймзоны

`dayKey` = `"yyyy-MM-dd"` от `Calendar.current` в момент FEED. Граница дня — локальная
полночь (без «до 3 ночи»-сдвигов — не усложняем до валидации). Смена таймзоны: новые логи
получают dayKey текущей зоны; стрик идёт по календарной цепочке dayKey как записано;
артефакты перелётов — принятое ограничение. Тесты A2: полночь; FEED 23:59 → ответ 00:00
(запись во «вчера»); смена зоны; DST; идемпотентность rollover.

### 3.4 Фото

Фото приёма **не хранится**: после успешного анализа JPEG нигде не остаётся; на диске живут
только JPEG элементов очереди — до успешного flush или вычёркивания. (Приватность: фото
уходит только в Gemini; журнал работает на title+эмодзи.)

## 5. Скоринг: вклад в тарелку дня (A3)

### 5.1 Функция (чистая)

```
вход:  plateFilled — юниты по секторам на момент приёма (replay записей дня до него),
       slotsUsed   — DayState.mealSlotsUsed,
       meal        — {portion, fractions, wholeness, confidence}
выход: applied (по секторам), coins, reaction

U         = GameConfig.portionUnits[meal.portion]
coef      = meal.wholeness == .processed ? GameConfig.processedCoef : 1.0
raw_s     = U × meal.fraction_s × coef              // s ∈ {veg, protein, grain}
applied_s = min(raw_s, goals_s − plateFilled_s)     // вклад — только в незакрытую часть
applied   = Σ applied_s

bonus = applied ≥ t2 ? 2 : applied ≥ t1 ? 1 : 0     // (t1, t2) = GameConfig.bonusThresholds
coins = logCoin + (slotsUsed < antiFarmFullRewardMeals
                   && confidence ≥ confidenceFloor ? bonus : 0)

reaction = meal.wholeness == .processed ? .sluggish : .happy
```

Свойства (тест-инварианты A3):
- `coins ≥ logCoin` всегда — ноль монет за еду не бывает (инвариант 3).
- Полные сектора вклада не дают → умеренность встроена; перебор монет не приносит.
- **Processed-еда может заработать бонус** через вклад ×`processedCoef` — минимум это
  гарантия, не потолок. Пицца XL из day-in-life получает минимум из-за **закрытых
  секторов**, а не из-за «джанковости».
- `other`-доля (сладкое, «пустое») вклада не даёт.
- Низкая confidence: бонуса нет, но **вклад в тарелку применяется** (приблизительные
  сектора лучше пустых; средство от ошибки — удаление записи, §11.5).

### 5.2 Фразовые надстройки (не стейты)

- `stuffed`-фраза: `portion == .large && wholeness == .processed`; анимация — `sluggish`.
  Отдельного поля «тяжести» в схеме нет (схема зафиксирована DECISIONS) — вопрос §15.6.
- `energized`-фраза (опционально): `whole` и protein-вклад доминирует.

### 5.3 Тарелка дня — derived

`plate(dayKey) = fold(MealRecord дня по capturedAt, через §5.1)`. Кэш — только оптимизация
с инвалидацией на вставку/удаление записи дня. `coinsAwarded` — исторические: replay
никогда не меняет уже выданные монеты (инвариант 6).

### 5.4 Анти-фарм и удаление записи

- `mealSlotsUsed` инкрементится в момент **создания MealRecord** (успешный анализ; для
  очереди — при flush). Слот тратит каждый учтённый приём — включая low-confidence
  (DESIGN: «первые N **приёмов** дня»).
- Удаление записи: тарелка дня пересчитывается без неё; **монеты не отзываются; слот не
  возвращается; `hasLog` не снимается**. Следствие: «лог → удалил → лог» не фармится —
  максимум `antiFarmFullRewardMeals` полных наград в день при любых манипуляциях.
- 5-й+ приём: `coins = logCoin`; тарелка заполняется, реакция играет, лог пишется, стрик
  жив. Копирайт не меняется — кап одинаков для любой еды и наказанием не является.

### 5.5 Sanity-check экономики (справочно)

Цели 4+2+2 = 8 юнитов; типовой день из 2–3 приёмов по 3–4 юнита почти закрывает тарелку →
2–3 × (1 + 1..2) ≈ 4–8 монет/день — сходится с DESIGN («~4–8/день»; tier-1 = 5–10 🪙 →
первая покупка на 1–2-й день; каталог ≥18 позиций ≈ 4 недели трат = окно замера).

### 5.6 Прогоны примеров DESIGN (обязательные тест-кейсы A3)

| Кейс | Ситуация | Ожидание |
|---|---|---|
| Овсянка+ягоды утром (M, whole, grain-heavy) | тарелка пуста → applied велик | бонус +2, `happy` |
| Та же овсянка 3-й раз за день | злаки закрыты → applied мал | +0..1, `happy` |
| Яблоко (S, whole, veg≈1.0) при недоборе фруктов | весь объём в незакрытый veg | заметный бонус |
| Пицца XL вечером (L, processed), злаки полны | raw×coef + закрытые сектора → applied≈0 | `logCoin`, `sluggish`, stuffed-фраза |
| Любой джанк, любое время | — | ≥ `logCoin`, стрик жив, без упрёка |
| 5-й приём (любая еда) | слоты кончились | ровно `logCoin`; тарелка/лог honest |
| FEED 23:59 → ответ 00:00 | dayKey = день FEED | вклад во «вчера», сегодняшняя тарелка чиста |

### 5.7 Кор-флоу `didFeed()` (связывает A2–A8)

```

    — шаги 1–4 атомарны (одна транзакция SwiftData) —

     scoring §5.1 (replay дня) → атомарно: MealRecord + mealSlotsUsed+1 + coins+= →
```

## 6. Стрик-машина «уголёк» (A4)

### 6.1 Семантика числа

`streakCurrent` = **число дней с логом** в непрерывной цепочке, где одиночные тихие дни
прощаются (в число не входят, цепь не рвут). Пример: Пн — 6-й лог-день, Вт тихо (ember,
стрик 6), Ср лог → 7. Копирайт «7 days on the road» — дни у костра; тихая веха остаётся
на тропе угольком.

### 6.2 Источник истины

Цепочка `DayState.hasLog` (+ `lastLoggedDayKey` как материализованный хвост цепочки).
`hasLog` ставится в момент FEED (включая очередь) и не снимается.
`missedDays(today)` = число календарных дней **строго между** `lastLoggedDayKey` и `today`
без `hasLog`. Сегодняшний день не «пропущен», пока не кончился.

### 6.3 Переходы на rollover / активации (идемпотентно)

| Условие | `streakState` | Эффект |
|---|---|---|
| логов ещё не было | `unlit` | current = 0 |
| missedDays == 0 | `lit` | без изменений |
| missedDays == 1 | `ember` | current **замер** (число не падает) |
| missedDays ≥ 2 | `out` | current = 0; `record` не трогается — навсегда |

### 6.4 На первом логе дня (`onFirstLogOfDay`, шаг 3 §5.7)

```
guard lastLoggedDayKey != today
state ∈ {lit, ember} → current += 1     // ember: цепь продолжилась, тихий день не считается
state ∈ {out, unlit} → current = 1      // костёр зажжён заново
record = max(record, current); state = .lit; lastLoggedDayKey = today
```

Ember — не одноразовая заморозка: каждый одиночный пропуск тлеет; гасит только серия 2+.
Заморозка не продаётся ни за что (WON'T DO).

### 6.5 Рендер костров «Пути» (heat-map)

| День | Костёр |
|---|---|
| `hasLog == true` | 🔥 lit |
| тихий день, одиночный в цепи | 🟠 ember |
| тихий день в серии ≥ 2 подряд | ⚫ out |
| сегодня без лога (день не кончился) | тлеющий «ждёт» (не ⚫) |
| до `installDayKey` | пустая тропа в тумане, без костров |

⚠️ Мок `WEEK` в `prototype/src/data/game.js` (одиночная тихая пятница показана `out`)
правилу противоречит — iOS следует правилу §6.5, не моку.

## 7. Gemini (A5)

### 7.1 Запрос

Модель `GameConfig.geminiModel`; JPEG ≤ `imageMaxSide`, качество `jpegQuality`; таймаут
`analysisTimeout`. **Structured output**: `response_mime_type: "application/json"` +
`responseSchema` (enum `wholeness`, границы 0..1 долей) — вместо «ответь только JSON»-
надежды текущего кода. Ключ — `Secrets.plist`; без ключа — Mock (§7.4).

Драфт промпта (EN; финализирует бенчмарк A13):

```
You are a nutrition-plate analyzer. Look at the photo of a meal.
Estimate the proportions of the MEAL VOLUME by plate sectors:
- veg_fruit: vegetables and fruits
- protein: meat, fish, eggs, legumes, dairy protein
- grain: grains, bread, pasta, potatoes and other starchy sides
- other: sweets, sauces, deep-fried coating, drinks, anything else
Proportions must sum to 1.0.
wholeness: "processed" if the meal is dominated by heavily processed food
(fast food, sweets, packaged snacks, deep-fried), else "whole".
is_food: false if there is no edible food in the photo.
confidence: 0..1 — overall certainty.
title: short dish name (2–4 words).
For mixed dishes (soup, pasta, sandwich) estimate sector shares inside the dish.
```

### 7.2 Ответ и валидация

```json
{
  "is_food": true,
  "confidence": 0.86,
  "title": "Oatmeal with berries",
  "proportions": { "veg_fruit": 0.30, "protein": 0.10, "grain": 0.50, "other": 0.10 },
  "wholeness": "whole"
}
```

Правила A5: clamp долей в 0..1; сумма ∉ [0.9, 1.1] → нормализовать на сумму; неизвестный
`wholeness` → `whole` (в сомнении не наказываем); пустой `title` → «Meal»; отсутствие
`is_food`/`proportions` → ошибка парсинга (= транзиент → очередь).

### 7.3 Ветки результата

| Ветка | Условие | Поведение |
|---|---|---|
| Норм | is_food && confidence ≥ floor | лог, скоринг §5.1, реакция |
| Джанк | то же, `processed` | лог, вклад ×coef, `sluggish`, монеты ≥ logCoin |
| Не-еда | is_food == false | игровая реакция, **без лога/монет/слота**, [Try again] |
| Низкая уверенность | is_food && confidence < floor | лог, фраза неуверенности, `coins = logCoin`, сектора применяются |
| Транзиент | сеть / HTTP≠200 / parse / timeout | оффлайн-очередь §8 |

### 7.4 MockFoodAnalyzer

Та же схема; детерминированная ротация веток: норм → джанк → не-еда → низкая уверенность
(+ инъекция транзиент-ошибки для тестов очереди). Без ключа приложение полностью живо —
на моке снимаются все скриншоты A9–A12 и гоняются все состояния Результата.

### 7.5 Бенчмарк (A13; TODO §0 — до сборки)

Скрипт `scripts/gemini-benchmark.mjs` гоняет **боевые** промпт и схему §7.1–7.2 на ~30

## 8. Оффлайн-очередь (A6)

- **Постановка** (шаг 7c §5.7): транзиент → `QueuedPhoto` (JPEG на диск). `hasLog`, стрик,
  `lastFeedAt`, пуш-replan уже сделаны шагами 2–4 — **стрик не сгорает** (DESIGN). Монеты
  до анализа не начисляются.
- **Ретрай**: на активации и при восстановлении сети (`NWPathMonitor`); FIFO,
  последовательно, реентерабельно-защищённо (одна прокачка за раз); `attempts += 1`;
  внутри сессии — экспоненциальная пауза. Постоянного капа нет: фото живёт до успеха или
  вычёркивания (данные юзера не выбрасываем).
- **Flush-успех**: перед созданием записи проверить, что элемент не вычеркнут (гонка с
  удалением). Атомарно: `MealRecord` с **исходными** `capturedAt`/`dayKey`; скоринг —
  против записей того дня с `capturedAt` раньше вставляемого (replay-вставка по времени);
  `mealSlotsUsed` **того** дня +1; монеты +=; `Telemetry.feed`; JPEG удалить. Юзер в
  приложении → тихое обновление лога/тарелки, звяк, короткая реплика героя. Отдельного
  Результат-экрана пост-фактум нет.
- **Flush-не-еда**: записи/монет/слота нет; JPEG удаляется; липкий `hasLog` дня не
  снимается — ретро-наказаний не бывает (редкий принятый эксплойт; инвариант 6 важнее).
- **Вычёркивание юзером**: pending-строка удаляется в Журнале как запись (§11.5);
  `QueuedPhoto` + JPEG удаляются; монет не было; `hasLog` остаётся.
- **UI**: строка «ждёт у костра…» (🕯️) в логе хаба и Журнале; без таймеров/процентов/бейджей.

## 9. Локальные пуши (A8)

- **Opt-in**: карточка онбординга — диегетический пре-промпт героя; системный запрос
  только после [Sure]. Отказ: пушей нет, повторных уговоров нет (`push_optin=false`).
  Отзыв разрешения в iOS-настройках после opt-in: `replan()` читает
  `UNUserNotificationCenter.authorizationStatus` — не authorized ⇒ вести себя как opt-out.
- **Слоты** (max `pushesPerDayMax`/день, строго вне `quietHours`):
  - слот-1 «день»: стреляет, только если к моменту слота сегодня нет ни одного лога;
  - слот-2 «вечер»: только если за день 0 логов.
- **Планирование**: локальные нотификации на 1–2 дня вперёд; `replan()` вызывается на
  (а) любом логе — снимает оставшиеся сегодняшние, (б) rollover, (в) активации,
  (г) выдаче разрешения на онбординге. Идемпотентно: полная пересборка pending-запросов.
- **Контент**: от героя, с его именем, диегетично, без вины и диет-лексики (§13); пул фраз
  на слот, ротация. Никаких «вы давно не заходили», бейджей и звуковых атак.
- **Тап** → Лагерь; `app_open(source: push)` (§10).
- Quiet hours = «ночь» героя (§2.3): ночью герой спит и не пишет.

  как обход; FEED в полёте — заблокирован (guard §5.7); оффлайн — FEED работает, итог
  на Результате (queued).
- **Действия:** FEED; Gallery; порция; выход.
- **Переходы:** FEED → Результат (loading); выход → Лагерь.
- **Герой:** у окна камеры; на FEED потирает руки.
- **Телеметрия:** своих событий нет.
- **Acceptance:** три темы применяются из конфига без правки скелета; дефолт порции medium;
  one-tap с блокировкой повторного тапа; ветки permission (prompt/denied) работают;
  Gallery работает.

### 11.4 Результат

- **Назначение:** момент награды: реакция героя (главный контент), вердикт, вклад, монеты.
- **Композиция** (`ResultScreen.jsx`): поверх размытого живого лагеря; вывеска-вердикт;
  герой крупно; speech bubble; ряд: `PlateRing` **тарелки дня** с анимированной дельтой
  приёма (сектора доливаются на глазах — механика вклада видна без слов) + строка блюда
  (эмодзи + title) + бейдж `+🪙 N`; чанк «Back to camp».
- **Мир/ambient:** лагерь под блюром живёт; звяк при начислении; при большом вкладе —
  искры от костра. Жевание — и есть лоадер: никаких спиннеров и прогресс-баров.
- **Состояния (машина):**

  ```
  loading ──успех──▶ success | lowConfidence
     │────is_food=false────▶ nonfood
     │────транзиент────────▶ queued
  ```

  - `loading`: герой `eating`, вывеска «Munching…»; держится ≥ `minChewingSeconds`;
    уход приложения в фон не ломает машину — по возвращении показывается достигнутое
    состояние (анализ продолжается в Task);
  - `success`: реакция `happy`/`sluggish`, вердикт, дельта ринга, +монеты; stuffed /
    energized — фразами;
  - `lowConfidence`: как success + фраза неуверенности, `+logCoin`;
  - `nonfood`: игровая реакция «You can't eat THAT!»; без лога и монет; [Try again] →
    Анализ, [Back to camp];
  - `queued`: «The fog's thick today. I'll keep this by the fire and try again soon.»;
    без ринга и монет; [Back to camp]. Стрик уже жив (§5.7 шаг 3).
- **Действия:** Back to camp; (nonfood) Try again.
- **Переходы:** → Лагерь (данные уже обновлены; монеты долетают в бейдж); nonfood → Анализ.
- **Герой:** центральный актёр; реакция один раз, затем мягкий луп.
- **Телеметрия:** `feed(...)` в момент создания MealRecord (success/lowConfidence);
  nonfood/queued не стреляют (queued выстрелит при flush).
- **Acceptance:** все 5 состояний воспроизводимы на моке; дельта анимируется; минимальное
  жевание соблюдается; из nonfood можно немедленно переснять; фоновый/возвратный цикл
  не ломает машину состояний.

### 11.5 Журнал дня

- **Назначение:** «как прошёл день»: настроение героя, тарелка дня, лог, удаление ошибок
  анализа. **Только сегодняшний день** (история — вне Сборки 1; долгий взгляд — Путь).
- **Композиция** (`JournalScreen.jsx`): свиток-пергамент с закрученными краями поверх
  размытого лагеря; вывеска «TODAY'S JOURNAL»; шапка: мини-портрет героя в текущем
  настроении + «{Name} feels …» + `PlateRing` дня; чернильные строки приёмов (сепия:
  эмодзи + title + время), pending-строки «ждёт у костра…» (🕯️); низ: орб 🧭 (Путь) +
  чанк «Back to camp».
- **Мир/ambient:** записи «проявляются» чернилами при открытии; свиток колышется;
  лагерь под блюром живёт.
- **Состояния:** пусто («The page is blank — feed your hero!»); записи; записи + pending.
  Вычеркнутые не показываются (день выглядит обычным).
- **Действия:** long-press (или свайп) записи → диегетическое подтверждение «Cross this
  one out of the journal?» [Cross out]/[Keep] → чернильное зачёркивание → запись удалена,
  тарелка дня пересчитана (§5.4: монеты/слот/`hasLog` не тронуты). Pending вычёркивается
  так же (§8). Орб 🧭 → Путь.
- **Переходы:** → Путь; → Лагерь.
- **Герой:** портрет-настроение: реакция последнего приёма дня, иначе ось потребности
  (§2.3); ночью — спит.
- **Телеметрия:** своих событий нет.
- **Acceptance:** удаление пересчитывает тарелку одинаково в журнале и на хабе; монеты и
  слоты не меняются (юнит-тест §5.4 + UI-прогон); pending отображается и вычёркивается.

### 11.6 Путь героя

- **Назначение:** длинный прогресс без цифр питания: тропа, костры-heat-map, стрик, рекорд.
- **Композиция** (`PathScreen.jsx`): пергамент-карта поверх размытого лагеря; вывеска
  «HERO'S PATH»; заголовок «🔥 {N} days on the road», мельче «best: {record}»; змейка-тропа
  по дням (окно `pathDaysWindow`): точки-следы между вехами; костёр 🔥/🟠/⚫ (§6.5) +
  подпись дня; на сегодняшней вехе — фигурка героя («hero is here»). Дни до установки —
  тропа в тумане. Единственные числа экрана — стрик и рекорд.
- **Мир/ambient:** пергамент «дышит»; сегодняшний костёр мерцает; туман клубится по краям.
- **Состояния:** свежий аккаунт (тропа коротка, туман); обычный; ember (вчерашняя веха 🟠);
  out (стрик 0, рекорд в заголовке — «накопленное не отнимается» наглядно).
- **Действия:** назад.
- **Переходы:** → Лагерь.
- **Герой:** фигурка на «сегодня»; при `lit` — бодрая поза.
- **Телеметрия:** своих событий нет.
- **Acceptance:** костры соответствуют §6.5 на фикстурах истории (вкл. «одиночный пропуск =
  🟠, серия = ⚫»); рекорд остаётся после `out`; сегодня — герой.

### 11.7 Рюкзак

- **Назначение:** тратить монеты: покупка/экипировка декора, питомцев, тем анализа.
  Одежды героя нет (после сигнала; манекен — витрина). **Только косметика**: никаких
  функциональных товаров (заморозок стрика, бустов монет) — WON'T DO.
- **Композиция** (`BackpackScreen.jsx`): поверх размытого лагеря; вывеска «BACKPACK» +
  `CoinBadge`; герой-витрина (реагирует на действия); кожаная панель, карманы-сетка:
  карточка = превью/эмодзи + имя + [🪙 цена] либо [Equip]/[Unequip]; экипированное
  подсвечено. Чанк «Back to camp».
- **Мир/ambient:** карманы топорщатся; купленное вылетает из кармана к герою; питомец
  в карточке поворачивается к герою при экипировке.
- **Состояния:** монет хватает / не хватает (цена потушена — просто недоступна, без стыда
  и таймеров); куплено / экипировано; каталог статичен — пустых состояний нет.
- **Действия:** купить (guard `coins ≥ price`, защита от двойного тапа; списание;
  `ownedItemIds += id`); Equip/Unequip по слотам: питомец ×1, декор ×1, тема ×1
  (unequip темы → таверна). Продажи/возврата нет.
- **Переходы:** → Лагерь (экипированное сразу в сцене — подтверждение миром).
- **Герой:** витрина: радуется покупке; разглядывает нового питомца; на теме — жест с
  пропсом темы.
- **Телеметрия:** `shop_buy(item_kind)`; `theme_switch(theme)` при смене темы.
- **Acceptance:** покупка списывает монеты ровно один раз; слоты соблюдаются;
  экипированное видно в лагере и меняет скин Анализа; оба события стреляют.

**Каталог** (структура — спека; состав/имена — B5):

```swift
struct CosmeticItem: Identifiable {
    let id: String
    let kind: CosmeticKind        // .pet / .decor / .theme
    let name: String              // имя в тоне мира (B5)
    let price: Int                // из GameConfig.priceTiers
    let asset: String
    let anchor: SceneAnchor?      // decor/pet: точка сцены лагеря
    let themeId: AnalysisTheme?   // для kind == .theme
}
```

Состав ~18–20: декор ~14–16 (анкеры: у костра, у палатки, на дереве, у входа…), питомцы 2
(арт-ограничение TODO: 1–2 отдельных спрайта), темы 2 (lab, magic; tavern — бесплатный
дефолт). Ступени — `GameConfig.priceTiers`; ориентир: дешёвый декор в tier-1 (первая
покупка на 1–2 день), питомцы и темы — tier-2..3.

## 12. Сквозные юзкейсы

Формат: шаги → слои → телеметрия → чек инвариантов.

1. **Первый запуск.** Онбординг (имя → луп → пуш-выбор) → Лагерь: пусто, костёр спокоен,
   герой idle → FAB → реплика + камера-prompt → фото + порция → FEED → Результат
   loading→success → Лагерь: тарелка ожила, монеты долетели, стрик 1, костёр ярче.
   События: `onboarding_done`, `app_open`, `feed`.
2. **Обычное кормление.** Лагерь → Анализ → FEED → жуёт ≥ `minChewingSeconds` → `happy` +
   вердикт + дельта тарелки + `+🪙` → Лагерь (эхо реакции). `feed(plate_score, portion, happy)`.
3. **Джанк.** `processed` → вклад ×`processedCoef`, `sluggish` + сонная фраза, монеты ≥
   `logCoin` (бонус возможен при большом вкладе — не наказываем), стрик жив. Чек: ни слова
   упрёка (инв. 3, 5).
4. **Не-еда (тролль-фото).** `is_food=false` → nonfood: игровая реакция, без лога/монет/
   слота → [Try again]/[Back]. Журнал не тронут, `feed` не стреляет. Чек: игра, не претензия.
5. **Низкая confidence.** Фраза неуверенности, `+logCoin`, сектора применены; запись можно
   вычеркнуть (→ 14). Чек: доверие юзеру.
6. **Оффлайн-кормление.** FEED без сети → шаги 1–4 §5.7 выполнены (стрик жив, таймер
   сброшен, пуши сняты) → Result.queued → Лагерь: pending-строка → сеть вернулась → flush:
   MealRecord в исходный день, монеты, `feed`; герой коротко радуется, если юзер в
   приложении. Чек: за сеть не наказываем.
7. **Анти-фарм: 5-й приём дня.** Как (2), но `+logCoin` без бонуса; тарелка/лог/реакция
   honest; копирайт не меняется. Чек: кап ≠ наказание (одинаков для любой еды).
8. **Переход через полночь.** (а) Приём в 00:30 → dayKey нового дня: пустая тарелка,
   свежие слоты; вчерашний день оценён §6.3 (открытое приложение ловит
   `NSCalendarDayChanged`). (б) FEED 23:59 → ответ 00:00: запись во «вчера» (dayKey от
   `capturedAt`), Результат показывает дельту вчерашней тарелки, хаб — уже новый день.
   (в) Очередь со вчерашним `capturedAt` flush-ится во вчера — сегодняшняя тарелка чиста.
9. **Пропуск дня.** Вчера 0 логов → на активации `ember`: стрик замер (число не упало),
   вчерашняя веха 🟠, костёр хаба тлеет, герой грустнеет визуально. Чек инв. 4: ничего не
   сгорело; оговорка-уголёк работает как задумано.
10. **Два пропуска.** ≥2 тихих дня → `out`: стрик 0, костёр потух, вехи ⚫; рекорд навсегда
    в заголовке Пути (инв. 6). Первый лог → «розжиг» на возврате в Лагерь, стрик 1,
    реплика «The fire's back! Missed you.»
11. **Покупка и экипировка.** Рюкзак → [🪙 8] фонарь → списание, `shop_buy(decor)` →
    [Equip] → Лагерь: фонарь на анкере, ночью светится.
12. **Смена темы анализа.** Рюкзак → купить «Lab theme» → [Equip] → `theme_switch(lab)` →
    Анализ в скине лаборатории (вывеска/стопы/пропсы из конфига). [Unequip] →
    `theme_switch(tavern)`.
13. **Пуши: opt-in и отказ.** Opt-in: слоты §9; день без лога → дневной пуш героя; тап →
    Лагерь, `app_open(push)`; лог в 11:00 → сегодняшние слоты сняты. Отказ: пушей нет,
    ре-запросов нет, всё прочее идентично.
14. **Удаление записи.** Журнал → long-press → «Cross this one out?» → зачёркнуто: тарелка
    дня пересчитана; монеты остались, слот занят, `hasLog` true. Чек: исправление ошибки
    Gemini не наказывается; фарм закрыт (§5.4).

## 13. Копирайт-принципы (+ драфты)

**Тон:** герой — друг-приключенец у костра. Принцип Focus Friend: он **занят своим делом и
радуется тебе**, а не обслуживает. Haven-принцип: мягкость и уют сцены — ценность сами по
себе. Реплики — от характера героя; «приложение» не говорит никогда.

Запрещено: стыд («ты переел», «плохая еда»), диет-лексика (calories, macros, cheat meal,
clean eating, guilt-free…), цифры питания в любом виде, канцелярит и системный язык в мире
(«network error» → «the fog is thick today…»). Системные формулировки — только в неигровых
местах (iOS-алерты, [Open Settings]).

Все фразы — **драфты на утверждение владельцу** (тон = продукт; AGENT_BACKLOG C). Язык
продукта — EN (прототип/код/когорта; подтвердить — §15.7). На каждую ситуацию — пул из
2–3 вариантов (ротация против «заезженной пластинки»); в таблице по одному примеру:

| Ситуация | Драфт (EN) | Принцип |
|---|---|---|
| happy | “Yum! That hit the spot!” | радость встречи, не оценка еды |
| sluggish | “So warm and heavy… nap time…” | сонливость, не упрёк |
| stuffed-фраза | “Oof… full up to my ears. Something fresh tomorrow?” | мягкий вопрос-приглашение |
| energized-фраза (опц.) | “Whoa, I could climb a mountain now!” | сила, без «правильной еды» |
| низкая confidence | “Hmm, can’t quite make it out… I’ll trust you on this one!” | доверие юзеру |
| не-еда | “Hey! You can’t eat THAT!” | игра, не претензия |
| оффлайн/очередь | “The fog’s thick today. I’ll keep this by the fire and try again soon.” | мир вместо «сети» |
| flush при юзере | “Oh! That meal from before — got it!” | |
| hungry (idle) | “Getting a little hungry over here…” | просьба, не обвинение |
| ночь | (спит; никаких реплик) | ночью тишина (инв. 4) |
| пуш днём (нет лога) | “{name} is poking the fire… got anything tasty going on?” | зовёт герой |
| пуш вечером (0 логов) | “The campfire’s quiet tonight. Even a tiny snack counts!” | «counts» = честность |

| пустой журнал | “The page is blank — feed your hero!” | из прототипа |
| розжиг после out | “The fire’s back! Missed you.” | тепло, без «наконец-то» |

Анти-паттерны (как НЕЛЬЗЯ): «You've eaten too much today», «Bad choice!», «You broke your
streak» (костёр гаснет сам и молча — юзер ничего не «ломал»), «Error 500», «Your daily
calorie goal…», «You haven't opened the app in a while».

## 15. Открытые вопросы (владельцу)

1. **`bonusThresholds`** (t1, t2 applied-юнитов → +1/+2) — нет в тюнинг-таблице. Драфт

6. **`stuffed`-эвристика** `portion==large && processed` — ок, или расширить Gemini-схему
   полем «визуальной тяжести»? (Схема зафиксирована DECISIONS без него.)
7. **Язык продукта** — EN (прототип/код/когорта TikTok+Reddit)? Спека приняла EN.
8. **Слот декора** — один (прототип) или несколько одновременно (богаче «рост лагеря»,
   но анкеры/арт)?
9. **Телеметрия ошибок** (`analysis_error` / nonfood) — добавить к замороженному списку
   VALIDATION или не трогать до конца замера?
10. **`analysisTimeout`** — драфт 20 сек до ухода в очередь.
11. **Дефолт-имя героя** — список кандидатов даст B6; выбор владельца.

## 16. За скоупом (идеи, всплывшие при написании — НЕ в Сборку 1)

- «Итог вчера» в первой сессии дня (открытый вопрос USER_FLOW — остаётся открытым).
