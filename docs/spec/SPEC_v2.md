## Ревью v1 (самокритика → исправлено в этой версии)

1. **Стрик-машина недоспецифицирована**: не определено, в какой момент дня наступает
   `ember`/`out` (сегодняшний день «ещё не пропущен» до полуночи); не назван источник истины
   (цепочка `DayState.hasLog` vs `lastLoggedDayKey`). → §6: формула missed-дней, таблица
   переходов, источник истины.
2. **Результат: `PlateRing` неоднозначен** — тарелка приёма или тарелка дня? → решено:
   тарелка **дня** с анимированной дельтой приёма (учит механике вклада). §11.4.
3. **Пауза hungry-таймера ночью потеряна** (DESIGN: «Ночью спит, таймер на паузе»). → §2.3.
4. **Хаб: не задана таблица «костёр сцены = f(стрик, лог дня)»** и tap-действие мини-тарелки.
   → §11.2.
5. **Анализ: не решён флоу капчура** (фриз-кадр с подтверждением vs one-tap FEED); в прототипе
   «ретейк» на деле — выход. → решено: one-tap (FEED снимает и отправляет), §11.3.
6. **Gemini: нет драфта промпта, нет правил валидации ответа** (сумма пропорций, clamp,
   неизвестный enum). → §7.
7. **Не определён момент занятия анти-фарм-слота** (FEED vs успех анализа) и удаление
   pending-элемента очереди. → §5.4, §8.
8. **Пуши: нет правил перепланирования** (rollover, quiet hours как окно, отмена при логе).
   → §9.
9. **Полночь при открытом приложении** не ловится (только scenePhase). → подписка на
   `NSCalendar.dayChanged`, §2.2.
10. **Модель: лишнее/недостающее** — `reaction` хранится, а stuffed-фраза выводима; не
    описаны derived-поля. → §3.2 «что хранится vs что выводится».
11. **Экономика не сверена** с «~4–8 монет/день» из тюнинг-таблицы. → §5.5 sanity-check.
12. **Телеметрия**: `plate_score` без типа/округления; `app_open` без частотного правила.
    → §10.
13. **Диегетическая планка неровная**: у Журнала/Пути/Рюкзака не описана ambient-жизнь и
    «назад — предмет мира»; реплики местами от лица приложения. → в каждом экране §11
    добавлен блок «Мир/ambient», копирайт §13 прогнан через фильтр «говорит герой, не сервис».
14. **Нет карты файлов** для стыковки с A9–A12 (куда портировать экраны). → §2.4.

## 0. Скоуп

**Входит (= TODO.md NEXT):** онбординг (имя героя + 2–3 карточки + пуш opt-in); лагерь-хаб
(+ мини-тарелка дня); анализ (камера + порция 3 стопа + FEED, темы таверна/лаборатория/магия);
результат; журнал дня (свиток, удаление записей); путь героя (тропа, костры, стрик);
рюкзак (декор / питомцы / темы — **без одежды героя**; каталог ~18–20 позиций);
SwiftData-лог приёмов; понятие дня; скоринг «вклад в тарелку дня»; монеты; стрик-уголёк;
анти-фарм; оффлайн-очередь; Gemini-схема (пропорции + цельность + is_food + confidence);
телеметрия TelemetryDeck (5 событий VALIDATION); локальные пуши (1–2/день, quiet hours,
opt-in); спрайты `idle/eating/happy/hungry/sluggish`; диегетическая полировка.

**Не входит:** одежда героя (манекен — витрина), просьбы героя, вылазки/находки, деградация
за молчание, виджет, рост кемпа, монетизация, редактирование секторов (только удаление),
аккаунты, vacation mode, звук/haptics сверх минимума. Идеи — только в §16.

**Инварианты (CLAUDE.md, абсолют):**
1. Ноль цифр наружу (ккал/БЖУ/проценты/вес). Цифры в UI — только стрик и монеты.
2. Герой никогда не умирает; дно — `hungry`.
3. Джанк не наказывается: любой лог = стрик жив + минимум монет; джанк = `sluggish`-реакция.
4. Грусть героя — только за молчание, чисто визуальная; ничего не сгорает (оговорка — уголёк);
   ночью герой спит.
5. Без стыда в текстах; герой — друг, не тренер.
6. Накопленное (косметика, рекорд, прогресс) не отнимается.

**Планка исполнения:** мультик, не приложение (Haven, Focus Friend). Мир всегда за UI;
хром = материал мира; герой присутствует и реагирует на каждом экране; ambient-жизнь.
Система говорит системным языком только вне мира (алерты пермишенов iOS).

## 1. Глоссарий

| Термин | Значение |
|---|---|
| **Сектор** | `veg` (овощи/фрукты), `protein`, `grain` — три части тарелки. |
| **Юнит** | Внутренняя единица объёма еды. Наружу никогда не показывается. |
| **Тарелка дня** | Цели дня в юнитах по секторам (`GameConfig.dayPlateGoals`) + заполнение. |
| **Вклад (applied)** | Юниты приёма, попавшие в незакрытую часть целей. База бонуса монет. |
| **Цельность** | `wholeness` от Gemini: `whole`/`processed`. Processed → коэф. <1 + `sluggish`. |
| **Уголёк (ember)** | 1 пропущенный день: стрик замер, костёр тлеет. Не сгорел. |
| **dayKey** | Локальная календарная дата `"YYYY-MM-DD"` на момент FEED. |
| **Лог** | Приём, учтённый за день: успешный анализ **или** элемент оффлайн-очереди. Не-еда — не лог. |
| **Липкий флаг** | Однажды выставленный `hasLog`/потраченный анти-фарм-слот не откатываются. |

## 2. Архитектура

### 2.1 Стек и принципы

- SwiftUI + SpriteKit. `HeroView` — единственная точка входа визуала героя (интерфейс не
  трогать; SpriteKit — внутри). `AppState: ObservableObject` через `.environmentObject`.
- Персист — SwiftData (§3). Тюнинг — только `GameConfig.swift` (§4).
- Скоринг и стрик — **чистые функции/машины без I/O** (тестируемость A3/A4).

### 2.2 Навигация и жизненный цикл

Навигация — стейт-машина как в `ChewyApp.jsx`:

```swift
enum Route { case camp, analyze, result(ResultPayload), journal, path, backpack }
```

- Рут — Лагерь (живая сцена рендерится всегда). Журнал/Путь/Рюкзак/Результат — оверлеи
  **поверх размытого живого лагеря** (сцена продолжает жить под блюром — мир не исчезает).
- Анализ — fullScreenCover (камера, свой скин-мир). Онбординг — fullScreenCover при
  `!onboardingDone`.
- Из Журнала доступен Путь (орб 🧭) — как в прототипе.

Жизненный цикл, `scenePhase == .active`:
1. `Telemetry.appOpen(source:)` (source = `push`, если вход через notification response).
2. Day-rollover: если `currentDayKey != lastSeenDayKey` → §6.3.
3. `OfflineQueue.retry()`.
4. Пересчёт состояния героя (§2.3) и костра сцены (§11.2).
5. `PushScheduler.replan()`.

Полночь при открытом приложении: подписка на `NSNotification.Name.NSCalendarDayChanged` →
те же шаги 2, 4, 5.

### 2.3 Состояния героя (5 спрайтов + сон-оформление)

Две оси (DESIGN):
- **Потребность** (чисто визуальная, ничего не сгорает): `idle` → `hungry`, по таймеру
  `now − lastFeedAt ≥ GameConfig.hungerAfterHours` (⚠️ нет в тюнинг-таблице → §15).
  **Ночью (quiet hours) таймер на паузе**, герой спит: спец-спрайта нет — сцена темнеет,
  герой в `idle` + 💤-эмоут, костёр приглушён.
- **Реакция на еду**: `eating` (на время анализа) → `happy` | `sluggish` (проигрывается на
  Результате и коротко на хабе после возврата), затем возврат к оси потребности.

`hungry` — дно. Ни `starving`, ни каких-либо форм смерти/деградации нет (инвариант 2).

## 3. Модель данных (SwiftData)

### 3.1 Модели

```swift
enum Portion: String, Codable { case small, medium, large }
enum Wholeness: String, Codable { case whole, processed }
enum Reaction: String, Codable { case happy, sluggish }
enum StreakState: String, Codable { case unlit, lit, ember, out }

@Model final class MealRecord {
    var id: UUID
    var capturedAt: Date          // момент нажатия FEED
    var dayKey: String            // локальная дата capturedAt
    var title: String             // короткое имя блюда (Gemini)
    var portion: Portion
    var vegFraction: Double       // пропорции Gemini, 0..1
    var proteinFraction: Double
    var grainFraction: Double
    var wholeness: Wholeness
    var confidence: Double        // 0..1
    var coinsAwarded: Int         // исторический факт, не пересчитывается
}

@Model final class DayState {
    var dayKey: String            // уникальный
    var hasLog: Bool              // липкий
    var fullRewardSlotsUsed: Int  // липкий (анти-фарм)
}

@Model final class PlayerState { // singleton
    var heroName: String
    var coins: Int
    var streakCurrent: Int
    var streakRecord: Int
    var streakState: StreakState
    var lastLoggedDayKey: String?
    var lastSeenDayKey: String    // для rollover-детекта
    var installDayKey: String
    var onboardingDone: Bool
    var pushOptIn: Bool
    var ownedItemIds: [String]
    var equippedPetId: String?
    var equippedDecorId: String?
    var equippedThemeId: String?  // nil = tavern
    var lastFeedAt: Date?
}

@Model final class QueuedPhoto {
    var id: UUID
    var capturedAt: Date
    var dayKey: String
    var portion: Portion
    var imagePath: String         // JPEG в Application Support; удаляется после успеха
    var attempts: Int
}
```

### 3.2 Что хранится vs что выводится

| Хранится | Выводится (не хранить) |
|---|---|
| пропорции, wholeness, confidence, portion, coinsAwarded | тарелка дня (replay записей дня, §5.3) |
| липкие `hasLog`, `fullRewardSlotsUsed` | реакция (`processed → sluggish`, иначе `happy`) |
| стрик-поля PlayerState | stuffed-фраза (`portion==large && processed`), фраза неуверенности (`confidence < floor`) |
| — | эмодзи записи в логе: по доминирующему сектору (🥦/🍗/🌾), `processed` → 🍔, low-confidence → 🍽️ |
| — | костры пути (§6.4), настроение в журнале (§11.5) |

Реакция и фразы выводимы из хранимого → правки копирайта/порогов не мигрируют данные.

### 3.3 dayKey и таймзоны

`dayKey = формат "yyyy-MM-dd" от Calendar.current` в момент FEED. Граница дня — локальная
полночь, без «3 часов ночи»-сдвигов (не усложняем до валидации). Смена таймзоны: новые логи
получают dayKey новой зоны; стрик оценивается по календарным датам как записаны. Возможные
артефакты перелётов (день длиной 30 часов) — принятое ограничение; тесты A2 фиксируют
поведение: полночь, смена зоны, DST.

## 5. Скоринг: вклад в тарелку дня

### 5.1 Функция (A3, чистая)

```
вход:  plateFilled (юниты по секторам на момент приёма),
       slotsUsed (анти-фарм), meal {portion, fractions, wholeness, confidence}
выход: applied (юниты по секторам), coins, reaction

U       = GameConfig.portionUnits[meal.portion]
coef    = meal.wholeness == .processed ? GameConfig.processedCoef : 1.0
raw_s   = U × meal.fraction_s × coef                  // s ∈ {veg, protein, grain}
applied_s = min(raw_s, goals_s − plateFilled_s)       // только незакрытая часть
applied = Σ applied_s

bonus   = applied ≥ t2 ? 2 : applied ≥ t1 ? 1 : 0     // t1,t2 = GameConfig.bonusThresholds
coins   = logCoin
        + (slotsUsed < antiFarmFullRewardMeals && confidence ≥ confidenceFloor ? bonus : 0)

reaction = meal.wholeness == .processed ? .sluggish : .happy
```

- Пропорции: `veg + protein + grain + other = 1.0`; `other` (сладкое/«пустое») вклада не даёт.
- Полные сектора вклада не дают → умеренность встроена; перебор монет не приносит.
- Джанк: `coins ≥ logCoin` всегда. Ноль монет за еду не бывает (инвариант 3).
- Низкая confidence: минимум монет, но **вклад в тарелку применяется** (приблизительные
  сектора лучше пустых; лечится удалением записи — DESIGN «в Сборке 1 только удаление»).

### 5.2 Фразовые надстройки (не стейты)

- `stuffed`-фраза: `portion == .large && wholeness == .processed` (анимация — `sluggish`).
  Отдельного поля «тяжести» в схеме нет — вопрос владельцу (§15.6).
- `energized`-фраза — опциональна в Сборке 1 (USER_FLOW: «фразами до валидации»); если
  включаем: доминирующий protein-вклад при `whole`.

### 5.3 Тарелка дня — derived

`plate(dayKey) = fold(записи дня по capturedAt, скоринг-функция)`. Кэш допустим только как
оптимизация с инвалидацией на вставку/удаление записи дня. Удаление ранней записи меняет
applied поздних при replay — это ок для **визуала** тарелки; `coinsAwarded` исторические
и не пересчитываются никогда (инвариант 6).

### 5.4 Анти-фарм и удаление

- Слот занимается в момент **создания MealRecord** (успешный анализ; для очереди — при flush).
- `fullRewardSlotsUsed` не убывает при удалении записи; монеты не отзываются.
  Следствие: «лог → удалил → снова лог» не фармится (макс `antiFarmFullRewardMeals` полных
  наград/день, что бы ни удалялось).
- 5-й+ приём дня: монеты = `logCoin`; тарелка заполняется, реакция играет, лог пишется.
  Копирайт нейтральный, кап — не наказание (одинаков для любой еды).

### 5.5 Sanity-check экономики (信息 — не тюнинг)

Цели 4+2+2 = 8 юнитов; типовой день 2–3 приёма по 3–4 юнита закрывает тарелку почти
полностью → 2–3 × (1 + 1..2) ≈ 4–8 монет/день — сходится с таблицей DESIGN («заработок
~4–8/день», tier-1 цена 5–10 → первая покупка на 1–2 день).

### 5.6 Прогоны примеров DESIGN (качественно; пороги — GameConfig)

| Кейс | Расчёт | Итог |
|---|---|---|
| Овсянка+ягоды утром (M, whole, grain-heavy) | тарелка пуста → applied большой | +2 бонус, `happy` |
| Та же овсянка 3-й раз | злаки закрыты → applied мал | +0..1, `happy` |
| Яблоко (S, whole, veg=1.0) при недоборе фруктов | весь объём в veg | хороший бонус |
| Пицца XL вечером (L, processed), злаки полны | raw×coef, злаки не принимают → applied≈0 | `logCoin`, `sluggish` + stuffed-фраза |
| Любой джанк | — | ≥ `logCoin`, стрик жив |

## 6. Стрик-машина «уголёк» (A4)

### 6.1 Источник истины

Цепочка `DayState.hasLog` по dayKey. `PlayerState.streak*` — материализованный итог,
пересчитываемый переходами ниже. `hasLog` ставится в момент FEED (в т.ч. при уходе в
очередь) и не снимается (§3.2).

### 6.2 Определение

`missedDays(today) = число календарных дней строго между lastLoggedDayKey и today без hasLog`.
Сегодняшний день не считается пропущенным, пока не кончился.

### 6.3 Переходы (на rollover / активации; идемпотентно)

| Условие | Состояние | Эффект |
|---|---|---|
| ещё не было логов | `unlit` | current = 0 |
| missedDays == 0 | `lit` | current без изменений |
| missedDays == 1 | `ember` | current **замер** (не меняется) |
| missedDays ≥ 2 | `out` | current = 0; `record` не трогается — навсегда |

### 6.4 На первом логе дня (FEED)

```
если state ∈ {lit, ember}:  current += 1        // ember: пропущенный день не считается, стрик продолжился
если state ∈ {out, unlit}:  current = 1          // костёр зажжён заново
record = max(record, current); state = lit; lastLoggedDayKey = today; hasLog(today) = true
```

Ember — не одноразовая «заморозка»: каждый одиночный пропуск тлеет; сгорает только серия
из 2+ подряд. Продажи/траты на заморозку не существует (WON'T DO).

### 6.5 Рендер костров «Пути» (heat-map)

| День | Костёр |
|---|---|
| hasLog == true | 🔥 lit |
| тихий день, одиночный (соседний день с логом с обеих сторон, либо «вчера» при ещё живом стрике) | 🟠 ember |
| тихий день в серии ≥ 2 подряд | ⚫ out |
| до installDayKey | пустая тропа, без костра |
| сегодня без лога (день не кончился) | тлеющий «ждёт» (не ⚫) |

⚠️ Мок `WEEK` в `prototype/src/data/game.js` (одиночная тихая пятница = `out`) противоречит
правилу — iOS следует правилу, не моку.

## 7. Gemini (A5)

### 7.1 Запрос

Модель `GameConfig.geminiModel` (gemini-2.5-flash); JPEG ≤ `imageMaxSide` (768),
качество `jpegQuality` (0.7). Structured output: `response_mime_type: application/json`
+ `responseSchema` (не «ответь только JSON»-надежда). Таймаут `analysisTimeout`.

Драфт промпта (EN, финализируется бенчмарком A13 на ~30 фото):

```
You are a nutrition-plate analyzer. Look at the photo of a meal.
Estimate the proportions of the MEAL VOLUME by plate sectors:
- veg_fruit: vegetables and fruits
- protein: meat, fish, eggs, legumes, dairy protein
- grain: grains, bread, pasta, potatoes and other starchy sides
- other: sweets, sauces, fried coating, drinks, anything else
Proportions must sum to 1.0.
wholeness: "processed" if the meal is dominated by heavily processed food
(fast food, sweets, packaged snacks, deep-fried), else "whole".
is_food: false if there is no edible food in the photo.
confidence: 0..1 — how sure you are overall.
title: a short dish name (2-4 words).
Mixed dishes (soup, pasta, sandwich): estimate the share of each sector inside the dish.
```

### 7.2 Ответ

```json
{
  "is_food": true,
  "confidence": 0.86,
  "title": "Oatmeal with berries",
  "proportions": { "veg_fruit": 0.30, "protein": 0.10, "grain": 0.50, "other": 0.10 },
  "wholeness": "whole"
}
```

Валидация парсинга (A5): clamp каждой доли в 0..1; если сумма ∉ [0.9, 1.1] —
нормализовать на сумму; неизвестный `wholeness` → `whole` (безопаснее для юзера: не
наказываем сомнением); отсутствующее `title` → нейтральное «Meal»; отсутствующие поля
`is_food`/`proportions` → ошибка парсинга (транзиент → очередь).

### 7.3 Ветки результата

| Ветка | Условие | Поведение |
|---|---|---|
| Норм | is_food && confidence ≥ floor | лог, скоринг §5, реакция |
| Джанк | то же + processed | лог, вклад ×coef, `sluggish`; монеты ≥ logCoin |
| Не-еда | is_food == false | игровая реакция героя, **без лога и монет**, «попробовать ещё» |
| Низкая уверенность | is_food && confidence < floor | лог, фраза неуверенности, монеты = logCoin, сектора применяются |
| Транзиент | сеть/HTTP≠200/таймаут/кривой JSON | → оффлайн-очередь §8 |

### 7.4 MockFoodAnalyzer

Переезжает на новую схему; умеет все ветки (норм / джанк / не-еда / низкая уверенность /
ошибка) — детерминированная ротация для UI-работы и Storybook-паритета. Без ключа
приложение полностью живо на моке.

## 8. Оффлайн-очередь (A6)

- **Постановка**: транзиентная ошибка анализа → `QueuedPhoto` (JPEG на диск) +
  `DayState.hasLog = true` + стрик-переход §6.4 немедленно (**стрик не сгорает** — гарантия
  DESIGN). Монеты не начисляются до анализа.
- **Ретрай**: на активацию приложения и на восстановление сети (`NWPathMonitor`);
  последовательно, FIFO; `attempts += 1`; между попытками в одной сессии — экспоненциальная
  пауза. Постоянного капа нет: фото живёт до успеха или ручного удаления (данные юзера
  не выбрасываем).
- **Flush-успех**: `MealRecord` с **исходными** `capturedAt`/`dayKey`; скоринг против тарелки
  того дня (replay, вставка по времени); анти-фарм-слот того дня занимается сейчас;
  монеты начисляются сейчас; `Telemetry.feed` стреляет сейчас; JPEG удаляется.
  Юзер в приложении → тихое обновление лога/тарелки + короткая реплика героя
  («а, вот и та еда!» + звяк монеты). Отдельного Результат-экрана пост-фактум нет.
- **Flush-не-еда**: записи нет, монет нет; липкий `hasLog` дня **не снимается** — ретро-
  наказаний не бывает (принятый редкий эксплойт; инвариант 6 важнее).
- **Удаление юзером**: pending-строку можно вычеркнуть в Журнале — `QueuedPhoto` и JPEG
  удаляются; монет не было; `hasLog` остаётся.
- **UI**: строка «ждёт у костра…» в логе хаба и Журнале (эмодзи 🕯️, без таймеров и процентов).

## 9. Локальные пуши (A8)

- **Opt-in**: карточка онбординга (диегетический пре-промпт от героя) → системный запрос
  только при согласии. Отказ → пушей в Сборке 1 нет, ре-запроса нет (принятое ограничение;
  `push_optin=false` в телеметрии).
- **Расписание**: максимум `pushesPerDayMax` (1–2)/день, только вне `quietHours`.
  Слоты (`pushSlots`, ⚠️ §15): слот-1 «день» — стреляет, только если сегодня ещё нет лога;
  слот-2 «вечер» — только если за день 0 логов. Реализация: локальные нотификации
  планируются на 1–2 дня вперёд; **любой лог дня** → `PushScheduler.replan()` снимает
  оставшиеся слоты сегодняшнего дня; rollover — планирует завтрашние.
- **Контент**: от героя, диегетично, имя героя в тексте, без вины и диет-лексики (§13).
  Никаких «вы давно не открывали приложение».
- **Тап** → Лагерь; `app_open(source: push)` через notification response handler.
- Quiet hours совпадают с «ночью» героя (§2.3): ночью герой спит и не пишет.

## 11. Экраны

Формат: назначение · композиция · мир/ambient · состояния · действия · переходы · герой ·
телеметрия. Композиция — по обкатанному скелету `prototype/src/`; язык копирайта — EN (§13).

### 11.1 Онбординг (B6)

- **Назначение:** привязанность с первой минуты: имя героя, луп за 15 секунд, пуш opt-in.
- **Композиция:** не слайды на заливке — **живая сцена лагеря**, герой у костра; поверх —
  последовательные деревянные таблички:
  1. Герой машет. Табличка «He's been waiting for a fellow traveler. What's his name?»
     + поле имени (дефолт предзаполнен из короткого списка драфтов B6). Kbd не съедает сцену.
  2. Луп тремя пиктограммами на дощечке: 📷 snap your meal → 🙂 he reacts → 🪙 coins →
     🎒 camp goodies. Одна строка «He never judges. Any meal counts.»
  3. Пуш-карточка от героя: «Can I call you back to the campfire sometimes?» + чанки
     [Sure, call me] / [Maybe later]. Системный prompt — только после [Sure].
- **Мир/ambient:** костёр мерцает, светлячки; герой реагирует на набор имени (наклоняет
  голову, улыбка при подтверждении).
- **Состояния:** обычный проход; пустое имя → остаётся дефолт; отказ от пушей — без
  уговоров и повторов.
- **Действия:** ввод имени, далее, opt-in выбор.
- **Переходы:** → Лагерь (навсегда; `onboardingDone = true`). Камера-пермишен здесь **не**
  запрашивается (just-in-time на первом Анализе — меньше фрикций и отказов).
- **Герой:** на всех карточках, «своим делом занят» — подкидывает ветку в костёр.
- **Телеметрия:** `onboarding_done(hero_named, push_optin)`.

### 11.2 Лагерь (хаб)

- **Назначение:** дом; статус мира с порога; вход во всё.
- **Композиция** (`HomeScreen.jsx` + TODO «мини-тарелка на хабе»): анимированный кемп
  фуллскрин; герой в центре у костра; **слева сверху** `CoinBadge` 🪙, под ним — мини-
  `PlateRing` тарелки дня (тап → Журнал); **справа сверху** — вертикаль деревянных орбов:
  🗺️ Журнал, 🧭 Путь, 🎒 Рюкзак; **низ** — лог приёмов дня (эмодзи + title + время;
  pending-строки «ждёт у костра…»), под ним FAB «Add Food» (деревянная тарелка/руна —
  готовый ассет, пресс-анимация из текущего кода). Экипированный питомец бродит в сцене,
  экипированный декор стоит на своём анкере.
- **Мир/ambient (Haven-планка, idle-петля):** костёр мерцает/искрит (интенсивность по §
  таблице ниже); дым и облака плывут; листва колышется; питомец дышит/переступает; герой
  idle-цикл, изредка «своя жизнь» (подбрасывает ветку, потягивается); редкие реплики от
  характера. Ночью: сцена темнеет, звёзды, герой спит 💤, костёр приглушён до углей.
  Сцену должно хотеться открыть «просто посмотреть».
- **Костёр сцены** (единый визуальный язык со стриком и потребностью):

  | Ситуация | Костёр |
  |---|---|
  | сегодня есть лог | горит ярко |
  | лога сегодня нет, стрик `lit` | горит спокойно (ниже) |
  | стрик `ember` (вчера тихо) | тлеет |
  | стрик `out` | потух; **первый лог дня разжигает** (мини-момент, анимация) |
  | ночь | угли, вне зависимости от прочего |

- **Состояния:** пусто (нет логов: «No meals yet — feed your hero!» + FAB как явный CTA);
  день идёт; ночь; ember/out по таблице.
- **Действия:** FAB → Анализ; орбы → оверлеи; мини-тарелка/лог-строка → Журнал.
- **Герой:** `idle`/`hungry` по §2.3; после кормления доигрывает реакцию и возвращается;
  ночью спит. Реплики — редкие, «от себя», не сервисные.
- **Телеметрия:** `app_open` (на активации приложения, не на возврат с оверлеев).

### 11.3 Анализ

- **Назначение:** сфоткать → порция → FEED. Сердце 30-секундного лупа; одна механика,
  сменные скины-темы.
- **Композиция** (`AnalyzeScreen.jsx` + `themes.js`): скин активной темы (дефолт таверна /
  лаборатория / магия): фон, вывеска («SCAN PROVISION» / «ANALYZING SPECIMEN» / «ANALYZE
  ESSENCE»), пропсы. Центр — круглое окно живой камеры с ink-обводкой (+ прицел-ретикула
  в таверне); **герой выглядывает из-за окна и смотрит на еду**. Нижняя панель-материал:
  слайдер порции в 3 стопа с тематическими именами (Bite/Half/Feast · Sample/Mass/Capacity ·
  Sip/Draft/Elixir) — **без процентов и грамм**, дефолт — средний; ряд кнопок: выход
  (предмет мира: ↻/⚙/📖 по теме), Gallery (второстепенно; PhotosPicker уже в коде),
  FEED! (главный чанк).
- **Мир/ambient:** пропсы темы живут (пар из кружки таверны, пузырьки колбы, искры руны);
  герой ёрзает и принюхивается к окну камеры.
- **Флоу капчура:** **one-tap** — FEED снимает кадр и сразу отправляет (существующее
  поведение AddFoodView; скорость лупа важнее подтверждения кадра). Отдельного фриз-экрана
  «повторить?» в Сборке 1 нет. Gallery — альтернативный вход тем же путём.
- **Состояния:**
  - первый вход: системный запрос камеры (может предварять короткая реплика героя);
  - live-камера (норма);
  - permission denied: герой щурится «I can't see the food…» + [Open Settings] (системное
    действие — допустимое неигровое место) + Gallery как обход;
  - в полёте: FEED заблокирован (двойной тап невозможен), переход на Результат мгновенный;
  - оффлайн: FEED работает — уходит в очередь (юзер узнаёт на Результате, §11.4 queued).
- **Действия:** снять (FEED), выбрать из галереи, порция, выход.
- **Переходы:** FEED → Результат (state=loading); выход → Лагерь.
- **Герой:** присутствует у окна; на FEED — потирает руки.
- **Телеметрия:** своих событий нет (`feed` — по факту анализа).

### 11.4 Результат

- **Назначение:** момент награды: реакция героя (контент!), вердикт, вклад в тарелку дня,
  монеты.
- **Композиция** (`ResultScreen.jsx`): поверх размытого живого лагеря; вывеска-вердикт;
  герой крупно; speech bubble; ряд: `PlateRing` **тарелки дня** с анимированной дельтой
  приёма (сектора доливаются на глазах — механика вклада видна без слов) + строка блюда
  (эмодзи + title) + `+🪙 N`; чанк «Back to camp».
- **Мир/ambient:** лагерь под блюром живёт; монеты звякают при начислении; при большом
  вкладе — искры/конфетти из костра.
- **Состояния:**
  - `loading`: герой `eating` (жуёт), вывеска «Munching…», ринг ждёт; никаких спиннеров —
    жевание и есть индикатор;
  - `success`: реакция `happy`/`sluggish`, вердикт-фраза, дельта ринга, +монеты;
    stuffed/energized — фразами;
  - `low-confidence`: как success, фраза неуверенности, `+logCoin`;
  - `nonfood`: игровая реакция «You can't eat THAT!», без лога и монет; кнопки [Try again]
    (→ Анализ) и [Back to camp];
  - `queued`: герой: «I'll keep it by the fire and try again soon.», без ринга и монет;
    [Back to camp]. Стрик уже жив (§8).
- **Действия:** Back to camp; (nonfood) Try again.
- **Переходы:** → Лагерь (тарелка/монеты/лог уже обновлены — преемственность видна);
  nonfood → Анализ.
- **Герой:** центральный актёр; реакция проигрывается один раз, затем мягкий луп.
- **Телеметрия:** `feed(...)` — в момент создания MealRecord (success/low-confidence).
  nonfood/queued события не дают (queued даст при flush).

### 11.5 Журнал дня

- **Назначение:** «как прошёл день»: настроение героя, тарелка дня, лог, удаление ошибок
  анализа.
- **Композиция** (`JournalScreen.jsx`): свиток-пергамент с закрученными краями поверх
  размытого лагеря; вывеска «TODAY'S JOURNAL»; шапка свитка: мини-портрет героя в текущем
  настроении + подпись «{Name} feels …» + `PlateRing` дня; ниже — чернильные строки приёмов
  (сепия; эмодзи + title + время), pending-строки «ждёт у костра…»; низ: орб 🧭 (Путь) и
  чанк «Back to camp».
- **Мир/ambient:** свиток чуть колышется; лагерь под блюром живёт; чернильные записи
  «проявляются» при открытии.
- **Состояния:** пусто («The page is blank — feed your hero!»); записи; записи + pending;
  день с удалёнными записями выглядит как обычный (вычеркнутые строки не показываются).
- **Действия:** long-press/свайп записи → диегетическое подтверждение «Cross this one out
  of the journal?» [Cross out]/[Keep] → чернильное зачёркивание, запись исчезает,
  тарелка дня пересчитывается (§5.4: монеты/слоты/стрик не трогаются). Pending-строку
  можно вычеркнуть так же (§8).
- **Переходы:** → Путь; → Лагерь.
- **Герой:** портрет-настроение в шапке: реакция последнего приёма дня, иначе ось
  потребности (`idle`/`hungry`), ночью — спит.
- **Телеметрия:** своих событий нет.

### 11.6 Путь героя

- **Назначение:** длинный прогресс без цифр питания: тропа по дням, костры-heat-map,
  стрик и рекорд.
- **Композиция** (`PathScreen.jsx`): пергамент-карта поверх размытого лагеря; вывеска
  «HERO'S PATH»; заголовок «🔥 {N} days on the road» + мельче «best: {record}»; змейка-тропа
  вниз по дням (последние ~2 недели видимой истории): точки-следы между вехами, у каждой
  вехи костёр 🔥/🟠/⚫ по правилу §6.5 и подпись дня (Mon/Tue…); на сегодняшней вехе —
  фигурка героя («hero is here»). Дни до установки — пустая тропа в тумане.
- **Мир/ambient:** пергамент слегка «дышит»; костёр сегодняшней вехи мерцает; туман
  клубится на краях карты.
- **Состояния:** свежий аккаунт (тропа коротка, много тумана); обычный; ember (вчерашняя
  веха тлеет 🟠); out (стрик 0, рекорд остался в заголовке — «накопленное не отнимается»
  наглядно).
- **Действия:** назад (чанк «Back to camp»).
- **Переходы:** → Лагерь.
- **Герой:** фигурка на «сегодня»; при стрике `lit` — бодрая поза.
- **Телеметрия:** своих событий нет.

  с карманами-сеткой: карточка предмета = превью-ассет/эмодзи + имя + [🪙 цена] либо
  [Equip]/[Unequip]; активная вещь подсвечена. Чанк «Back to camp».
- **Мир/ambient:** карманы «топорщатся»; купленный предмет вылетает из кармана к герою;
  питомец из карточки поворачивается к герою при экипировке.
- **Состояния:** монет хватает / не хватает (кнопка цены потушена — просто недоступна,
  без стыда и таймеров); куплено/экипировано; каталог статичен (пустых состояний нет).
- **Действия:** купить (списание, `ownedItemIds += id`); Equip/Unequip по слотам:
  питомец ×1, декор ×1, тема ×1 (unequip темы → таверна). Продажи/отката покупок нет
  (инвариант 6 — и не нужно).
- **Переходы:** → Лагерь (экипированное сразу в сцене — подтверждение покупки миром).
- **Герой:** витрина: радуется покупке; смотрит на нового питомца; при экипировке темы —
  «примеряет» жестом пропс темы.
- **Телеметрия:** `shop_buy(item_kind)` на покупке; `theme_switch(theme)` на смене
  активной темы.

**Каталог** (деливерабл B5; спека фиксирует структуру):

```swift
struct CosmeticItem { let id, kind /* pet|decor|theme */, name: String
                      let price: Int          // из GameConfig.priceTiers
                      let asset: String       // спрайт/превью
                      let anchor: SceneAnchor // для decor/pet: точка в сцене лагеря
                      let themeId: String? }  // для kind == theme
```

Состав ~18–20 позиций: декор ~14–16, питомцы 2 (арт-ограничение: отдельные спрайты 1–2 —
TODO §5), темы 2 (lab, magic; таверна — бесплатный дефолт). Ступени цен — GameConfig.

## 12. Сквозные юзкейсы

Формат: шаги → задействованные слои → телеметрия → чек инвариантов.

1. **Первый запуск.** Онбординг (имя → луп → пуш-выбор) → Лагерь: пусто, герой idle, костёр
   `unlit`-спокойный → FAB → системный prompt камеры → фото+порция → FEED → Результат
   loading→success → Лагерь: тарелка ожила, +монеты, стрик 1, костёр горит.
   Слои: PlayerState, PushScheduler, Analyzer, Scoring, Streak. Телеметрия:
   `onboarding_done`, `app_open`, `feed`.
2. **Обычное кормление (happy path).** Лагерь → Анализ → FEED → Результат: жуёт → `happy`,
   вердикт, дельта тарелки дня, +1..3 🪙 → Лагерь. `feed(plate_score, portion, happy)`.
3. **Джанк.** Gemini `processed` → вклад ×`processedCoef`, `sluggish` + сонная фраза,
   монеты ≥ `logCoin`, стрик жив, тарелка подросла на коэф. Ни одного слова упрёка (чек
   инварианта 3/5).
4. **Не-еда (тролль-фото).** `is_food=false` → Результат nonfood: игровая реакция, без
   лога/монет → [Try again]/[Back]. Журнал не тронут; `feed` не стреляет.
5. **Низкая confidence.** Фраза неуверенности, `+logCoin`, сектора применены; запись
   в Журнале можно вычеркнуть (юзкейс 14).
6. **Оффлайн-кормление.** FEED без сети → Результат queued («keep it by the fire») →
   Лагерь: pending-строка, `hasLog=true`, стрик жив → сеть вернулась → flush: MealRecord
   в исходный день, монеты, `feed`; герой коротко радуется, если юзер в приложении.
7. **Анти-фарм: 5-й приём дня.** Всё как (2), но монеты = `logCoin` (слоты кончились);
   тарелка/лог/реакция honest; копирайт не меняется (кап ≠ наказание).
8. **Переход через полночь.** Приём в 00:30 → dayKey нового дня: пустая тарелка, свежие
   слоты; стрик: вчерашний день оценён по §6.3 на rollover (открытое приложение ловит
   `NSCalendarDayChanged`). Очередь со вчерашним `capturedAt` flush-ится **во вчера**
   (replay того дня), сегодняшняя тарелка не искажается.
9. **Пропуск дня.** Вчера 0 логов → на активации `ember`: стрик замер (число не падает),
   вчерашняя веха 🟠, костёр хаба тлеет, герой грустнеет визуально. Ничего не сгорело и
   не отнято (чек инварианта 4 + оговорка-уголёк).
10. **Два пропуска.** ≥2 тихих дня → `out`: стрик 0, костёр потух, вехи ⚫; рекорд в
    заголовке Пути навсегда (чек инварианта 6). Первый лог: «розжиг» костра, стрик 1.
11. **Покупка и экипировка.** Рюкзак → [🪙 8] фонарь → монеты списаны, `shop_buy(decor)` →
    [Equip] → Лагерь: фонарь на анкере, светится в ночной сцене.
12. **Смена темы анализа.** Рюкзак → купить «Lab theme» → Equip → `theme_switch(lab)` →
    Анализ в скине лаборатории (вывеска/стопы/пропсы из конфига тем). Unequip →
    `theme_switch(tavern)`.
13. **Пуши: opt-in и отказ.** Opt-in: слоты §9; день без лога → дневной пуш от героя;
    тап → Лагерь, `app_open(push)`. Отказ: пушей нет, ре-запросов нет, всё остальное
    идентично.
14. **Удаление записи.** Журнал → long-press записи → «Cross this one out?» → зачёркнуто:
    тарелка дня пересчитана без неё; монеты остались, слот анти-фарма остался занят,
    `hasLog` дня остался true (чек: не наказываем за исправление ошибки Gemini; фарм
    закрыт §5.4).

## 13. Копирайт-принципы (+ драфты)

**Тон:** герой — друг-приключенец у костра. Focus Friend-принцип: он **занимается своим
делом и радуется тебе**, а не обслуживает; реплики от его характера, не от «приложения».
Запрещено: стыд («ты переел», «плохая еда»), диет-лексика (calories, macros, cheat meal,
guilt-free…), цифры питания, канцелярит и системный язык в мире («network error» → герой
щурится на туман: «hm, the fog is thick today…»). Системные формулировки допустимы только
в неигровых местах (iOS-алерты пермишенов, Settings).

Все фразы ниже — **драфты на утверждение владельцу** (тон = продукт). Язык продукта — EN
(как прототип и код; когорта TikTok/Reddit) — подтверждение у владельца, §15.7.
На каждую ситуацию — пул из 2–3 вариантов (ротация, чтобы герой не был заезженной пластинкой);
здесь по одному примеру:

| Ситуация | Драфт (EN) | Заметка |
|---|---|---|
| happy | “Yum! That hit the spot!” | радость, не оценка еды |
| sluggish | “So warm and heavy… nap time…” | сонливость, не упрёк |
| stuffed-фраза | “Oof… full up to my ears. Something fresh tomorrow?” | мягко, вопрос-приглашение |
| energized-фраза (опц.) | “Whoa, I could climb a mountain now!” | |
| низкая confidence | “Hmm, can’t quite make it out… I’ll trust you on this one!” | доверие юзеру |
| не-еда | “Hey! You can’t eat THAT!” | игра, не претензия |
| оффлайн/очередь | “The fog’s thick today. I’ll keep this by the fire and try again soon.” | сеть — «туман» |
| flush очереди при юзере | “Oh! That meal from before — got it!” | |
| hungry (idle-реплика) | “Getting a little hungry over here…” | просьба, не обвинение |
| ночь | (спит; без реплик) | |
| пуш днём (нет лога) | “{name} is poking the fire… got anything tasty going on?” | от героя |
| пуш вечером (0 логов) | “The campfire’s quiet tonight. Even a tiny snack counts!” | «counts» = честность |
| камера denied | “I can’t see the food… (Open Settings)” | системная часть — в скобках-кнопке |
| удаление записи | “Cross this one out of the journal?” [Cross out]/[Keep] | нейтрально |
| пустой лог хаба | “No meals yet — feed your hero!” | из прототипа |
| пустой журнал | “The page is blank — feed your hero!” | из прототипа |

## 15. Открытые вопросы (владельцу)

1. `bonusThresholds` (t1, t2 applied-юнитов → +1/+2) — нет в тюнинг-таблице. Драфт-прикидка
   для обсуждения: t1=1.0, t2=2.0 юнита (сходится с прогонами §5.6).
2. `hungerAfterHours` — таймер `hungry` (ориентир «ритм еды ~3 ч» из DECISIONS). Драфт: 3.
3. `quietHours` и `pushSlots` — точные часы. Драфт: 22:00–08:00; слоты ~13:00 и ~19:30.
4. `confidenceFloor` — порог ветки неуверенности. Драфт: 0.5 (уточнит бенчмарк A13).
5. `startingCoins` — монеты нового игрока. Драфт: 0 (первая покупка и так на 1–2 день).
6. `stuffed` выводить из `portion==large && processed` — или добавить в Gemini-схему поле
   «визуальной тяжести»? (Схема в DECISIONS зафиксирована без него.)
7. Язык продукта — EN (прототип/код/когорта)? Спека приняла EN для драфтов.
8. Слот декора один (как в прототипе) — или несколько декоров в сцене одновременно
   (богаче «рост лагеря», но новые анкеры/арт)?
9. Телеметрия ошибок (`analysis_error`, nonfood) — добавить к замороженному списку
   VALIDATION или не трогать до конца замера?
10. `analysisTimeout` — драфт 20 сек до ухода в очередь.
