# chewy

iOS-тамагочи про еду: юзер фоткает приём пищи, Gemini оценивает пропорции тарелки,
герой реагирует и живёт от качества питания. SwiftUI + SpriteKit, соло-инди проект.

## Сборка

- Проект: `chewy/chewy.xcodeproj`, схема `chewy`, iOS Simulator.
- Проверка сборки: `xcodebuild -project chewy/chewy.xcodeproj -scheme chewy -destination 'generic/platform=iOS Simulator' build`. Для запуска выбрать установленный симулятор.
- Gemini-ключ: `Secrets.plist` с `GEMINI_API_KEY` в бандле (не в git). Без ключа работает `MockFoodAnalyzer` — для UI-работы ключ не нужен.

## Документы

Начать с `docs/MVP_PLAN.md`: порядок этапов и карта документов. Текущая очередь —
`docs/TODO.md`; продуктовый черновик для ревью — `docs/USER_FLOW.md`.
Правила продукта — `docs/DESIGN.md`, причины решений — `docs/DECISIONS.md`.
Покрытие Storybook — `docs/SCREEN_STUDIES.md`, актуальные медиа — `docs/ASSETS.md`.
Текущая цель — основной прототип для native; онбординг и пейвол отдельно.
Пороги `docs/VALIDATION.md` заморожены. `docs/archive/` — история, не инструкции.

## Инварианты дизайна (нарушать нельзя ни в коде, ни в копирайте)

1. **Без цифр питания**: никаких ккал/граммов БЖУ/процентов питания в UI. Питание — через вид героя, речь, визуальные запасы и тарелку секторами. Непищевые числа (монеты, цены, даты, множитель регулярности) разрешены владельцем 2026-10-29.
2. **Герой никогда не умирает**: дно деградации — `starving`. Никаких game over.
3. **Еда не ухудшает состояние героя**: любой лог = стрик жив + минимум энергии. Никаких `sluggish` / `stuffed`, вялости или реплик о тяжести и переедании из-за состава еды или размера порции. Подтверждено владельцем 2026-10-25.
4. **Деградация только за молчание** (нет лога), и только днём (quiet hours — герой спит).
5. **Без стыда в текстах**: герой — друг, не тренер и не диетолог. Никаких «ты переел», «плохая еда», диет-лексики.
6. **Рост не отнимается**: накопленный прогресс (рост, коллекция, стрик-рекорд) назад не откатывается.

## Процесс

- **Заморозка скоупа**: во время Сборки 1 новые идеи → только в `TODO.md` IDEAS / «После сигнала». NEXT не растёт.
- Новая механика: сначала DESIGN.md + TODO, потом код.
- Решения с причинами — в DECISIONS.md, одной строкой.
- Доки на русском, код и коммиты на английском.
- Тюнинг-цифры живут в `GameConfig.swift` (когда появится) — в доках на них только ссылаться, не дублировать.

## Работа агента

- «Бери следующую» = следующий незавершённый пункт NEXT в `docs/TODO.md`.
- iOS — после согласованного основного прототипа (см. `docs/MVP_PLAN.md`); онбординг и пейвол не блокируют эту приёмку.
- Текущая очередь только в TODO. Историю примерок не дописывать в рабочие правила и сценарии.
- Агент выполняет задачу и подходящие проверки, обновляет TODO; коммиты/пуши — только по явной команде.
- Новые механики, тюнинг, финальные реплики и арт согласуются с владельцем; черновики допустимы.
- Неоднозначные продуктовые правила оставить вопросом; не утверждать их через реализацию.
