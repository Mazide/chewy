# Chewy — локальная мастерская контента

Отдельный пайплайн: задание → сохранённый запрос и референсы → производство
изображения или анимации → импорт → проверка → решение владельца → исходный ZIP.
Каталог, история, изображения и кадры находятся на компьютере.

Общий план для иллюстраций, анимации, текстов, звука и нативных экспортов —
[CONTENT_PIPELINE](../docs/CONTENT_PIPELINE.md). Эта версия работает со статичными
PNG, покадровыми анимациями и видеочерновиками из Runway API. Она не подключена к Storybook или iOS.
Процесс изготовления **новых** движений героя, костра, цветов и фона описан в
[ANIMATION_PRODUCTION](../docs/ANIMATION_PRODUCTION.md). Импорт готовой последовательности
и её проигрывание сами по себе не являются генерацией новой анимации.
Сравнение способов создания движения и кандидатов для подключения —
[ANIMATION_RESEARCH](../docs/ANIMATION_RESEARCH.md).

## Запуск

Нужны Python 3.10+, Pillow и cryptography. Из корня репозитория:

```sh
python3 -m venv content-pipeline/.venv
content-pipeline/.venv/bin/python -m pip install -r content-pipeline/requirements.txt
content-pipeline/.venv/bin/python content-pipeline/pipeline.py serve --port 8766
```

Открыть [мастерскую](http://127.0.0.1:8766/). Если Pillow уже установлен,
достаточно `python3 content-pipeline/pipeline.py serve --port 8766`.
Сервер слушает только `127.0.0.1`; остановка — `Ctrl+C`. Для просмотра и импорта
ключ не нужен; для генерации видео требуется Runway API.

## Один полный проход для статичного PNG

1. Выбрать задание. Рядом доступны назначение, исходный образ, размер показа и
   критерии художественного ревью.
2. При необходимости изменить промпт и нажать «Подготовить запрос».
   Сохраняется новая версия: точный текст, параметры, копии референсов и их хеши.
   Старый запрос остаётся доступным в списке.
3. Нажать «Скопировать для Codex», вставить запрос в чат этого проекта и выполнить
   генерацию через ImageGen. Мастерская сама не вызывает генератор.
4. Выбрать соответствующий сохранённый запрос, загрузить полученный PNG,
   указать инструмент и, если известна, модель. Исходные байты сохраняются без
   изменений. Несколько результатов одного запроса появляются в списке вариантов.
5. Сравнить вариант с копией референса этого запроса: сетка, дневной/ночной фон,
   размер показа. Автопроверка показывает ошибки и предупреждения.
6. Владелец выбирает «Принять вариант» либо «На доработку» и может оставить
   комментарий. Для новой пробы изменить промпт и снова подготовить запрос.
7. После принятия скачать исходный пакет. Для примерки в экране и нативного
   использования нужна отдельная подготовка.

Смена задания и запроса сохраняет связь изображения с его происхождением.
Принятие варианта не заменяет файлы приложения. Решение можно снять; история
решений сохраняется. Непройденная техническая проверка блокирует принятие.

## Что проверяется и что экспортируется

Автопроверка полностью декодирует PNG, проверяет размер, наличие реальной
прозрачности и видимого содержимого. Касание краёв и недостаточный размер для
просмотра выводятся отдельно. Лимиты загрузки: 20 МиБ, сторона не более 8192 px,
не более 24 миллионов пикселей. Анимированный PNG не принимается.

Прозрачность сама по себе не доказывает чистоту контура, сохранение персонажа
или соответствие правилам продукта. Это проверяется глазами. Предупреждения
не равны техническому отказу: перед принятием их нужно оценить.

ZIP содержит исходный PNG, паспорт с результатом QA и решением, точный запрос и
копии референсов. При экспорте сверяются хеши файлов. Это пакет исходников:
`nativeReady: false`. Мастерская не обрезает и не масштабирует изображение,
не делает `@2x/@3x`, атлас или `.xcassets`.

## Анимация

В задании «Чуви в движении» работает проигрыватель настоящей последовательности
PNG: запуск/пауза, возврат в начало, выбор кадра, скорость, однократное
воспроизведение, повтор и движение туда-обратно. Первый кадр доступен без запуска
движения. Сравнивать можно на сетке, дневном и ночном фоне, в размере показа.

Для новой пробы подготовить запрос, получить движение в отдельном инструменте
анимации и загрузить ZIP. В корне архива должны быть только PNG одинакового
размера, например `idle_000.png`, `idle_001.png`, `idle_002.png`. Имена определяют
порядок, числовые части сортируются естественно: `frame2` раньше `frame10`.
Один PNG или лист с множеством поз не заменяет последовательность.

При импорте задаются FPS и режим воспроизведения; они сохраняются вместе с
вариантом. Переключатели проигрывателя меняют только просмотр. Чтобы выпустить
пакет с другими параметрами, импортировать новую пробу с нужными значениями.

Поддерживаются 2–240 кадров, 1–60 FPS, ZIP до 100 МиБ и до 100 МиБ суммарных
распакованных PNG, не более 128 миллионов пикселей во всех кадрах. Проверяются
каждый PNG, одинаковый холст, прозрачность, непустой силуэт и касание краёв.
Опору, дрожание, характер движения и шов петли оценивает владелец.

После принятия исходный пакет содержит оригинальный ZIP, неизменённые PNG в
порядке воспроизведения, `animation.json` с FPS/режимом/длительностью и паспорт
происхождения. Это комплект для следующей интеграции, не готовый SpriteKit atlas.

Статичные ключевые позы можно получать через ImageGen. Для нового движения
подключён Runway API; путь описан ниже. Архивный клип героя сохранён отдельно
и не выдаётся за результат новой генерации.

## Новая видеопроба через Runway

1. В [Runway Developer Portal](https://dev.runway.com/) создать проект, пополнить
   именно API-баланс и создать ключ в API Keys. Подписка веб-приложения и API
   используют разные кредиты. [Настройка API](https://docs.dev.runwayml.com/guides/setup/).
2. Открыть задание **«Новый огонь костра»**. У него подготовлен запрос с исходным
   рисунком и неподвижными поленьями. В блоке Runway ввести ключ в поле пароля и
   нажать сохранение. Ключ не отправляется в чат и не возвращается в ответах API.
3. Выбрать модель и референс сохранённого запроса. Кнопка показывает стоимость
   **одного** пятисекундного запуска: Gen-4.5 — около $0.60, Kling 3.0 Standard
   без звука — $0.45 по тарифам от 29 октября 2026. Налоги при пополнении могут
   оплачиваться отдельно. [Тарифы](https://docs.dev.runwayml.com/guides/pricing/).
4. Нажать генерацию. Затем обновлять статус задачи: это проверка существующего
   запуска, а не новая генерация. Готовый MP4 сохраняется локально, проигрывается
   в истории запроса и доступен для скачивания.

Сохранённый ключ означает наличие настройки, а не подтверждённый доступ к модели
или достаточный баланс. Ошибки авторизации/баланса показываются при обращении к
Runway. Если ответ на создание задачи потерян, запуск помечается `UNKNOWN` и
повторное платное создание для этого запроса блокируется. Сначала проверить
задачу в Developer Portal; автоматического перезапуска после таймаута нет.
Не обходить неопределённость созданием нового запроса до проверки списания.

Если видео уже сгенерировано, но скачивание не удалось, обновление статуса
повторяет получение результата без новой генерации. Доступ к интернету нужен
процессу Python, в котором работает мастерская.

**MP4 — видеочерновик.** Генерация ещё не создаёт прозрачный игровой спрайт,
бесшовный цикл или готовый atlas. После художественного отбора нужны маски,
стабилизация и PNG-кадры; их можно импортировать существующим путём. Видео
не проходит кнопку принятия прозрачного PNG автоматически.

Ключ хранится в `workspace/private/runway.json` с правами `0600`, каталог —
`0700`, весь workspace исключён из Git. Сервер слушает только `127.0.0.1`.
Вместо локального файла можно задать `RUNWAYML_API_SECRET` в окружении процесса;
локально сохранённый ключ имеет приоритет. При передаче истории другому человеку
исключить каталог `private/`.

### Передача ключа, когда доступен только чат

Для удалённого владельца можно подготовить одноразовую форму шифрования в чате.
Владелец вводит ключ в поле формы, шифрует его и отправляет в чат только строку
`CHEWYKEY1.…`. Форма использует WebCrypto; если он недоступен во встроенном просмотре,
переключается на вложенную библиотеку Forge 1.4.2 с теми же RSA-OAEP/AES-GCM.
Случайные данные в обоих случаях берутся только из `crypto.getRandomValues`;
при его недоступности ввод остаётся заблокированным. Исходный ключ не сохраняется
в состоянии чата или браузерном хранилище; поле очищается при запуске шифрования. Если
автоматическое копирование запрещено браузером, она выделяет шифр для ручного копирования.

Оператор создаёт сеанс командой `python3 content-pipeline/secret_transfer.py create`.
Она выводит только публичные параметры: `id`, `expiresAt`, `publicKeySpki`.
Их нужно встроить в `key-transfer/form.html` вместе с `key-transfer/crypto.js`
и проверенной библиотекой из `key-transfer/vendor/`. Происхождение, хеш и лицензия
библиотеки сохранены рядом. Закрытый ключ остаётся в игнорируемом каталоге
`workspace/private/transfer/`. Передача действует 48 часов и использует
RSA-OAEP SHA-256 + AES-256-GCM с привязкой к сеансу. Форма не загружает библиотеку
из сети и не вызывает API генератора. При доступности действия чата появляется
«Отправить шифр в чат»: только явное нажатие передаёт готовый шифротекст.

Полученный **шифр** подаётся через stdin в
`python3 content-pipeline/secret_transfer.py import`. Скрипт расшифровывает и
сохраняет ключ через существующий механизм Runway, не выводя его значение.
Успешный импорт одноразовый; закрытый ключ передачи удаляется. Уже настроенный
Runway-ключ не заменяется без явного `import --replace`. После ошибки локального
сохранения нужен новый сеанс. Рабочий API-ключ остаётся в `private/runway.json`;
одноразовым является шифр передачи, а не ключ Runway.

не утверждены. Точные промпты, копии референсов и файлы находятся в `workspace/`,

не сообщил; оно не выдумывается в паспорте.

Дополнительно импортирован существующий клип Чуви: `idle_000…idle_120` из
`chewy/chewy/Assets.xcassets/hero.spriteatlas`, 121 кадр 506 × 1060, 24 FPS,
5,0417 секунды. Темп взят из `SpriteKitHeroView.swift`; исходные PNG скопированы
побайтово. Это архивный материал, а не новая генерация. Начальный режим — один
проход, поскольку бесшовность петли не принята. Клип также ожидает решения.
Пути и хеши исходных кадров — в `workspace/imports/hero-idle-native-provenance.json`.

Первая новая видеопроба — костёр через **Runway Gen-4.5**, один запрос с оценкой $0.60.

5,0417 секунды, H.264 без alpha. Пламя меняет форму, общий рисунок узнаваем.
Чёрный фон и различие первого/последнего контура требуют отдельной подготовки.

GIF — уменьшенное превью для чата; исходное видео сохранено без изменений.

Внутри цветы, палатка, лампа, птица, бабочка и облака; 749 прозрачных PNG,

не выполняет его кнопкой. Видеопетли остаются черновиками для отбора.

- [catalog.json](catalog.json) — задания, критерии и ссылки на исходные референсы;
  редактируется как JSON. Новые задания добавляются здесь.
- [pipeline.py](pipeline.py) — локальный HTTP-сервер и CLI.
- [runway.py](runway.py) — вызов провайдера, состояния задач и сохранение видео.
- [web/](web/) — интерфейс без сборки и внешних зависимостей.
- `workspace/requests/` — неизменяемые запросы и снимки референсов.
- `workspace/attempts/` — оригинальные PNG, метаданные и решения.
- `workspace/exports/` — собранные исходные пакеты.
- `workspace/runway/generations/` — задачи Runway, происхождение и скачанные MP4.
- `workspace/private/` — локальные ключи; не включать в передачу истории.

`workspace/` исключён из Git. Перезапуск сервера сохраняет историю; для переноса
на свой другой компьютер переносить историю вместе с инструментом; каталог
`private/` содержит секреты и не входит в общий пакет исходников. Код и
`catalog.json` без неё открывают пустую историю с теми же заданиями. Несохранённые
правки промпта в браузере не являются версией запроса.

## CLI для работы из Codex

```sh
python3 content-pipeline/pipeline.py prepare hero-joy
python3 content-pipeline/pipeline.py prepare hero-sleep --prompt 'Точный новый промпт'
python3 content-pipeline/pipeline.py import-result hero-joy /absolute/path/result.png --packet r-ID --tool image_gen
python3 content-pipeline/pipeline.py import-animation hero-idle-motion /absolute/path/frames.zip --packet r-ID --tool external-animation --fps 24 --playback once
python3 content-pipeline/pipeline.py state
```

`r-ID` нужно взять из результата `prepare`; это не имя задания. `--model` у импорта
необязателен. Глобальные `--workspace` и `--catalog` указывать перед подкомандой,
например для отдельной пробной истории:

```sh
python3 content-pipeline/pipeline.py --workspace /tmp/chewy-content-trial serve --port 8767
```

Решение владельца и экспорт доступны в интерфейсе. Произвольные пути файлов
через HTTP не принимаются; загрузка идёт байтами выбранного PNG или ZIP.
`import-animation` также принимает путь к папке с PNG вместо ZIP.

## Проверка реализации

```sh
python3 -m unittest discover -s content-pipeline -p 'test_*.py' -v
node content-pipeline/web/motion.test.cjs
node content-pipeline/web/runway.test.cjs
node content-pipeline/key-transfer/test_crypto.cjs
node content-pipeline/key-transfer/test_form.cjs
node --check content-pipeline/web/app.js
node --check content-pipeline/web/motion.js
node --check content-pipeline/web/runway.js
```

Проверены 39 тестов сервера Python и 14 тестов передачи ключа, включая полный HTTP-проход, сохранность источников,
неизменяемые референсы, ошибочные PNG, историю решений и запрет экспорта до
приёмки/после отзыва решения. Анимационные проверки покрывают порядок кадров,
параметры времени, тип задания, ZIP-пути/дубликаты/лимиты, несовпадающие холсты,
ошибки alpha и побайтовую сохранность кадров в экспорте. Ещё 7 тестов плеера
проверяют темп, крайние кадры, паузу, ограниченный кэш, смену варианта и ошибку загрузки.
Runway проверен с подставным клиентом без внешних запросов: секреты, ограничения
референсов, списание только при создании задачи, блокировка повторов, неопределённый
результат отправки, получение и сохранение MP4. Ещё 7 тестов интерфейса проверяют
блокировки запуска, очистку поля ключа и безопасное воспроизведение локального видео.
В браузере проверены проигрывание до последнего кадра, перемотка, FPS/режим просмотра,
возврат к статичному заданию, история двух запросов, смена фона и размера показа. Реальные изображения не принимались
автоматически ради проверки экспорта: для этого тесты используют временные данные.
Видеопроход проверен в браузере на отдельном тестовом сервере: отправка → очередь →
готовый MP4 → воспроизведение. Реальный Runway проверен на одной пробе костра:
авторизация, создание задачи, статусы и получение MP4 сработали. Видео проверено
по декодированным кадрам. Захват встроенного браузера показывал белую область
видеоплеера при нормальном декодировании; для просмотра в чате подготовлено GIF-превью.
Форма передачи проверена в изолированном просмотре на вымышленном ключе:
WebCrypto и режим без WebCrypto → шифротекст → точная расшифровка в Python,
очистка поля и ручное копирование. Ещё 11 тестов JavaScript проверяют совместимость
криптографии, отказ при отсутствии надёжной случайности и отправку только шифра в чат.
