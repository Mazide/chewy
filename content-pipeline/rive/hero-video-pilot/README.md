# Чуви: сохранённое видео → кадры → Rive

Проба использует старую генерацию владельца: Чуви поднимает руку к виску,
затем смотрит на часы. Новое движение не генерируется. Исходные растровые
кадры упакованы в `.riv` как покадровая анимация; это не векторизация и не
восстановление костного рига.

## Материалы

Сохранились все исходники:

- [Видео `idle.mov`](../../../assets/idle.mov) и [MP4-копия](../../../assets/idle_from_mov.mp4).
- 121 прозрачный PNG в `chewy/chewy/Assets.xcassets/hero.spriteatlas/`,
  от `idle_000.imageset/idle_000@2x.png` до `idle_120.imageset/idle_120@2x.png`.
- Уменьшенный web-атлас `prototype/public/assets/sandbox/archive-reference/hero_idle_sheet.png`
  с метаданными; для этой пробы взяты более крупные нативные PNG.

Исходная последовательность: **506 × 1060, 24 FPS, 121 кадр, 5,0417 секунды**.
Последний кадр отличается от первого: показываем один проход и удерживаем
последнюю позу. Повтор явно возвращает к началу; бесшовность не заявляется.

При подготовке сделано только равномерное уменьшение до **253 × 530**.
Сохранены все кадры, порядок, прозрачность и темп. Перекадрирование,
стабилизация, повторное удаление фона и интерполяция кадров не применяются.
Хеши исходных и подготовленных кадров — [source-manifest.json](source-manifest.json).
Существующие исходники и герой в основном лагере не изменяются.

Все распакованные RGBA-кадры такого размера составили бы около **61,9 МиБ**;
это оценка пиксельных буферов, а не измерение памяти GPU/runtime. Покадровая
анимация сохраняет пластику видео, но дороже общего рига по памяти и размеру.
Одежда, волосы и ракурс записаны внутри кадров.
Экспорт `.riv` занимает **13 052 082 байта** (около 12,45 МиБ).

## Контракт

| Элемент | Значение |
|---|---|
| Artboard / State Machine / View Model | `ChewyVideo` |
| `action` | `0` — первый кадр, `1` — проиграть последовательность |
| `Rest` | Неподвижный исходный кадр |
| `RecordedGesture` | 121 кадр, 24 FPS, `oneShot`, удержание последнего |
| Повтор | `action=0`, один шаг state machine, затем `action=1` |
| Исходный мастер | `chewy/scene.rml` + `chewy/assets/*.png` |
| Экспорт | `exports/chewy-video.riv` |

Кадры встроены как ImageAsset. Solo выбирает один кадр; переключение дискретное,
без смешивания соседних рисунков. При reduced motion автоматическое движение
выключено; кадры можно изучить вручную.

Подготовка кадров выполняется отдельно, явно:

```sh
python3 content-pipeline/rive/hero-video-pilot/prepare_frames.py
```

Она отказывается заменять изменённые подготовленные PNG. Обычная сборка читает
сохранённый мастер и не запускает подготовку заново.

Сборка и проверка встроенных кадров:

```sh
python3 content-pipeline/rive/hero-video-pilot/pipeline.py --rive /tmp/chewy-rive-cli/bin/rive
```

Нужны Rive CLI 1.8.0, Python с Pillow и NumPy. Сборка использует временную копию,
проверяет структуру Solo, точные байты всех 121 встроенных PNG, выбранные кадры
реального CLI runtime и сохранность исходников. Генератор `author_flipbook.py`
нужен только для явного создания новой заготовки; повторная сборка его не вызывает.
Контракт и хеши — [exports/manifest.json](exports/manifest.json), результаты —
[exports/native-qa.json](exports/native-qa.json).

При запущенном `serve.py` браузерный прогон:

```sh
node content-pipeline/rive/hero-video-pilot/check_motion.mjs http://127.0.0.1:6014/hero-video-pilot/preview/review.html --out content-pipeline/rive/hero-video-pilot/exports/browser-qa
```

Для него нужны Playwright/Chromium из прототипа и FFmpeg. Он сравнивает кадры
настоящего WebGL2 runtime с PNG-источником и сохраняет отчёт и запись просмотра.

[Независимый аудит исходников](evidence/source-audit.json) проверил все 121
преобразование и встроенные изображения. Отдельный CLI-прогон на 6-й и 10-й
секунде удерживает последний кадр; повторная сборка даёт тот же SHA-256 `.riv`.
[Проверка собранного Storybook](evidence/storybook.json) подтверждает загрузку
обоих проигрывателей и управление позами.

## Что ещё не утверждено

Это проверка существующего материала внутри Rive. Художественная пригодность
жестов, качество исходной генерации и применение в основном лагере остаются
отдельными решениями. Восстановление редактируемого персонажа из видео не
выполнялось. Apple runtime и круг ручной правки в Editor пока не проверены.
