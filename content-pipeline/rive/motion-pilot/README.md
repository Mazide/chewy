Пилот на существующих ромашках Chewy: рисунок сохранён, стебли получили
кости и веса, цветки и листья — запаздывающее движение. Мастер редактируется
отдельно от сборки. Результат остаётся черновиком для художественного ревью.

## Повторить весь локальный прогон

Из корня репозитория:

```sh
python3 content-pipeline/rive/motion-pilot/pipeline.py run --rive /path/to/rive
```

Если CLI уже находится в `PATH` или задан через `RIVE_CLI`, флаг не нужен.
В текущей среде также распознаётся существующий `/tmp/chewy-rive-cli/bin/rive`;
для постоянной работы следует указать устойчивый путь к установленному CLI.
Версия закреплена в `pipeline.json`: неожиданный upgrade останавливает сборку.
Установка официального CLI описана в [Rive Getting Started](https://rive.app/docs/cli/getting-started).

Команда сама собирает проект, запускает временный сервер на свободном порту,
проверяет экспорт в Chromium, сохраняет кадры и MP4, затем завершает временный
сервер. Для просмотра после прогона использовать `serve.py` или Storybook.

Зависимости: Rive CLI **1.8.0**, Python с пакетами из `requirements.txt`, Node.js,
Playwright из `prototype/package-lock.json` и установленный Chromium, `ffmpeg`.
Проверенное окружение: Node.js 22.23.1, FFmpeg 8.0.1. Пакеты Python:
Pillow 12.1.1, NumPy 2.3.5, PyYAML 6.0.3. Веб-рендерер — сохранённый
`camp-scene-vector/preview/vendor/webgl2-2.40.1`, версия 2.40.1.

Подготовка зависимостей на новой машине:

```sh
python3 -m venv /tmp/chewy-motion-venv
source /tmp/chewy-motion-venv/bin/activate
python3 -m pip install -r content-pipeline/rive/motion-pilot/requirements.txt
npm ci --prefix prototype
cd prototype
npx playwright install chromium
```

FFmpeg устанавливается отдельно системным пакетным менеджером. После подготовки
вернуться в корень репозитория; запускать `pipeline.py` при активном окружении,
чтобы Python внутри браузерного QA находил те же зависимости.
Сборка не устанавливает пакеты и не обновляет CLI автоматически.

Для быстрой технической сборки без браузера существует команда `build` вместо
`run`; её отчёт явно отмечает, что браузерный QA не выполнялся.

## Что делает прогон

1. Проверяет версию CLI и контракт `PlantStates / stage`.
2. Копирует сохранённый мастер и baseline во временные проекты; генератор не запускается.
3. Выполняет `verify`, `inspect`, компиляцию `.riv` и рендер разных стадий/фаз.
4. В отдельной копии меняет положение травы, собирает дважды и проверяет,
   что правка видна в runtime, исходник сохранён, повторный экспорт совпадает.
5. При доступной авторизации экспортирует `.rev`, импортирует его через CLI,
   пересобирает и сравнивает кадры. Это проверка формата, не ручной работы в Editor.
6. Загружает `.riv` в браузере: проверяет опору, края, стык петли, стадии,
   прерывания, паузу, reduced motion и два размера экрана; записывает видео.
7. Публикует локальный выпуск и только после успешных проверок переключает `latest.json`.

Неудачный `run` не заменяет предыдущий успешный выпуск. `build` может стать
последним техническим выпуском без браузерного QA — его статус отличается от `run`.
Ни одна команда не загружает файлы в Rive account и не публикует их в интернете.

## Исходники и артефакты

| Файл | Назначение |
|---|---|
| `motion-brief.json` | Характер движения, опоры, имена стадий и контроллеров |
| `plants/scene.rml` | Главный редактируемый источник рисунка, рига, ключей и состояний |
| `pipeline.json` | Версия CLI, список ассетов, контракт и точки проверки |
| `author_plants.py` | Однократное создание начального мастера; обычная сборка его не вызывает |
| `evidence/authoring.json` | Проверка рига, весов, независимости слоёв и сохранения исходного рисунка |
| `exports/latest.json` | Указатель на актуальный локальный выпуск |
| `exports/runs/<id>/manifest.json` | Хеши, версии, результаты и ограничения конкретного прогона |
| `exports/runs/<id>/sources/` | Снимки исходников этого выпуска |
| `exports/runs/<id>/reproduce.json` | Конфигурация для повторной сборки именно сохранённых исходников |
| `exports/runs/<id>/plants.riv` | Новый runtime-ассет |
| `exports/runs/<id>/baseline-plants.riv` | Прежняя анимация для сравнения |
| `exports/runs/<id>/browser-qa/` | Отчёты, кадры, контактные листы и `review.mp4` |

Повторить старый выпуск после дальнейшей правки мастера:

```sh
python3 content-pipeline/rive/motion-pilot/pipeline.py build --config content-pipeline/rive/motion-pilot/exports/runs/20261106T153323Z-f471fb93/reproduce.json --output /tmp/chewy-motion-rebuild
```

Чтобы намеренно пересоздать черновой мастер, используется отдельный явный
`author_plants.py --bootstrap --replace-master`. Это перезапишет внесённые правки;
для доводки существующей анимации нужно редактировать `scene.rml`.

## Что поставлено в движении

У каждого стебля четыре кости. Векторные точки и ручки кривых привязаны к ним
весами. На канале вращения девять ключевых поз: спокойная пауза, наклон,
освобождение, более слабый обратный ход и затухание. Разные части немного
запаздывают. Начальная и конечная позы и скорости согласованы.

Слой `Daily state` меняет только масштаб/видимость. Слой `Authored breeze`
управляет костями, цветками и листьями. Статичные стадии — `Morning`, `Growing`,
`Full`; цикл движения — `Breeze`, шесть секунд. Для неподвижного вида применяются
выбранная стадия и нулевой кадр `Breeze`. Смена стадий остаётся смешиванием
внешнего вида; отдельная постановка роста в этот пилот не входит.

## Проверенные границы

Локальная сборка, сохранность правок, реальные web-кадры и поведение проверяются
автоматически. Художественное качество оценивается по сравнению и видео;
зелёный отчёт не заменяет эту приёмку.

При первом запуске CLI не был авторизован: `.rev` и его обратный импорт отмечены
как `blocked_by_auth`. Доступ к браузеру пользователя также выключен в Work
settings. Полный круг **Editor → ручная правка → возврат → выпуск** пока не
проверен. После входа `rive login` новый прогон выполнит проверку формата `.rev`;
ручной редакторский этап всё равно проверяется отдельно. Apple runtime не запускался.

Для регрессий сохранности и публикации:

```sh
python3 -m unittest discover -s content-pipeline/rive/motion-pilot -p 'test_pipeline.py'
```
